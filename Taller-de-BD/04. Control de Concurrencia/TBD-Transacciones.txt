Slide 5:
Instituto Tecnológico de Culiacán 
SQL Server proporciona una gran cantidad de variables globales, que son muy efectivas para usar Transact-SQL regular. 

Las variables globales representan un tipo especial de variable, debido a que el servidor siempre mantiene los valores de estas variables. Todas las variables globales representan información específica del servidor o una sesión de usuario actual.

Los nombres de las variables globales comienzan con un prefijo @@. No necesita declararlos, ya que el servidor los mantiene constantemente. Son funciones definidas por el sistema y no puede declararlas.

@@TRANCOUNT regresa el nivel de anidamiento de las transacciones. Cada inicio de transacción incrementa en 1 la variable @@trancount.
@@ROWCOUNT regresa el número de renglones afectados por el último comado.

Slide 7:
Consistencia (consistency)
Una TM mantendrá la consistencia de la base de datos. Esto es, si la base de datos se encuentra en un estado consistente antes de ejecutar la TM, una vez que ésta termine la consistencia de la base de datos deberá conservarse.
En términos de base de datos esto significa que se satisfacen todas las restricciones en cuanto a su integridad que incluyen:
Todos los valores de la llave primaria son únicos.
La base de datos mantiene integridad referencial lo que significa que los registros solo referencian información que existe.
Ciertos predicados se mantienen. Por ejemplo,
 La suma de los gastos es menor o igual al presupuesto.
Instituto Tecnológico de Culiacán 

Slide 8:
 Durabilidad (durability)
 Aislamiento (isolation) 
Durante la ejecución de una transacción, esta no debe revelar sus resultados a otras transacciones concurrentes antes de su compromiso. Si varias transacciones se ejecutan concurrentemente, los resultados deben ser los mismos que si ellas se hubieran ejecutado en forma secuencial (Seriabilidad). La seriabilidad consiste en asegurarse que los cambios siguen un orden adecuado.
Es la propiedad de las transacciones que asegura que una vez que una transacción realiza su compromiso, sus resultados son permanentes y no pueden ser borrados de la base de datos, se asegura que los resultados de una transacción sobrevivirán a fallas del sistema.

Set @V=@@ERROR
if @v=1222
   print 'No logro recuperar la tupla'

   print 'Recupero la tupla'

Slide 17:
Transacciones de Mantenimiento Anidadas
SQL Server permite manejar transacciones anidadas. Esto significa que podemos tenet TM dentro de TM (se puede iniciar una nueva TM sin que la TM anterior haya terminado su ejecución).
Asociada a esta ídea de anidamiento existe una variable global  @@TRANCOUNT que tiene el valor de 0 si  no hay ninguna TM activa, 1 si existe una TM activa, 2 si existe una TM anidada, 3 si existen dos TM anidadas y así sucesivamente.

Slide 18:
Niveles de aislamiento
Los niveles de aislamiento te permiten el control del nivel de consistencia que podrás obtener cuando manipulas datos, teniendo en mente que varios procesos puede ejecutarse concurrentemente.
SQL Server permite cuatro niveles de aislamiento:
Read uncommited
Read Commited
Repeatable read
 Serializable
Snapshot

Slide 19:
El nivel de aislamientos que se seleccione puede presentar (o no presentar) problemas de consistencia tales como:
1. Lecturas sucias:
2. Actualizaciones perdidas: 
3. Análisis inconsistente (lecturas no repetidas):
4. Fantasmas:
Una TM actualiza datos pero aún no realiza el commit tran cuando otra TM lee los mismos datos.
Una TM “B” puede sobre escribir sobre lo realizado por la TM “A” 
En dos lecturas separadas dentro de la misma TM obtenemos diferentes valores (hablando del mismo recurso).
Éstos se presentan cuando una TM está realizando una acción contra un rango de tuplas, mientras otra TM realiza una acción incompatible sobre tuplas en el mismo rango.
Ejemplo de fantasmas: una TM borra todos las tuplas basada en una condición y durante el borrado otra TM inserta una nueva tupla que satisface la condición. La nueva tupla es considerada una tupla fantasma.   
Instituto Tecnológico de Culiacán 

Slide 20:
SQL permite establecer el nivel de aislamiento usando la siguiente instrucción:
SET TRANSACTION ISOLATION LEVEL <isolation level>
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED
Estableciendo este nivel de aislamiento los lectores no solicitan bloqueos compartidos, así los lectores nunca están en conflicto con sesiones que modifican datos. Los lectores pueden leer datos que se encuentran con bloqueo  exclusivo. 
Lecturas sucias pueden presentarse. READ UNCOMMITTED es el peor nivel de aislamiento en terminos de consistencia pero el mejor en términos de concurrencia. 
Conexión 1
begin tran
   Update Ctl_Folios Set Usuario=4918
   Select * From Ctl_Folios
Conexión 2
SET TRANSACTION ISOLATION LEVEL  READ UNCOMMITTED
select * from Ctl_Folios
La TM en la conexión 1 no termina su ejecución y en la conexión 2 podemos acceder a los datos que modificó. 
Instituto Tecnológico de Culiacán 

Slide 21:
SET TRANSACTION ISOLATION LEVEL READ COMMITTED
Con este nivel de aislamiento (default de SQL Server) los procesos requieren bloqueos compartidos para leer datos y liberarlos tan pronto como el dato ha sido leido (no cuando la transacción termine).
Lecturas sucias no se presentan ya que los cambios que puedes leer son aquellos que han terminado con la ejecución de un commit.
Conexión 1
begin tran
   Update Ctl_folios Set Usuario=4918
   Select * From ctl_folios
Conexión 2
SET TRANSACTION ISOLATION LEVEL  READ COMMITTED
select * from ctl_folios
La TM en la conexión 1 no termina su ejecución y la conexión 2 queda bloqueada hasta que conexión termine con commit o rollback. 
Instituto Tecnológico de Culiacán 

Slide 22:
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ
Este nivel de aislamiento permite realizar lecturas repetibles, requiere de candados compartidos cuando lee datos, lo que significa que lecturas sucias no se pueden presentar. Se garantiza obtener lecturas repetibles debido a que ningún otro proceso será capaz de obtener un candado exclusivo entre tus lecturas. Actualizaciones perdidas no suceden con este nivel de aislamiento.
Si dos procesos que leen datos preservan candados compartidos hasta el final de la transacción, un intento por modificar el dato por ambos causará un deadlock, debido a que cada uno requiere un candado exclusivo que será bloqueado por el otro.
Conexión 1
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ
BEGIN TRAN
   Select Folio from pag_folio where estado='E'
-- mas instrucciones
   Select Folio from pag_folio where estado='E'
Conexión 2
UPDATE Pag_Folio Set fOLIO=0 where estado='E’
Desde conexión 1 ejecute hasta antes del segundo select, en conexión 2 ejecute el código y se bloqueará, regrese a conexión 1 y ejecute el último select y obtendrá la misma lectura que en el primer select.
Instituto Tecnológico de Culiacán 

Slide 23:
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE
El nivel de aislamiento SERIALIZABLE es similar al nivel de aislamiento REPEATABLE READ con una característica adicional, las TM activas ponen candados(puestos sobre índices) a un rango de claves basados sobre la condición de un filtro. El rango de candados aplica tanto para lectores como para escritores.   
El rango de claves bloqueadas incluye claves que se encuentran físicamente (claves que aún no existen físicamente) cuando se hace el acceso. 
Conexión 1
create nonclustered index IdxFolios on Folios (Folio)
set transaction isolation level serializable
begin tran
   update dbo.folios set Usuario=10 where folio between 1 and 50
commit tran

Conexión 2
insert into folios(folio,usuario,estatus) values(20,0,‘D')

El insert se bloquea debido a que en conexión1 se especificó el nivel de asilamiento serializable  y se encuantra actualizando las tuplas que FOLIO esten en el rango de 1 a 50, el 20 que se desea insertar esta en ese rango y no lo permite.
No permite tuplas fantasma

SET TRANSACTION ISOLATION LEVEL SNAPSHOT	 
SQL SERVER  requiere que enciendas la opción de la BD que permita trabajar este nivel asilamiento. 
ALTER DATABASE NOM_DB SET ALLOW_SNAPSHOT_ISOLATION ON
Conexión 1

Cuando una sentencia lee datos durante la ejecución de una TM con el nivel de aislamiento SNAPSHOT, la sentencia accesará la última versión consistente  de los datos que estaba disponible cuando inicio la TM. 
Cada vez que  una TM modifica una tupla y hay otra(s) TM ejecutándose en con nvel de aislamiento SNAPSHOT, SQL Server necesita una versión consistente de la tupla antes de la modificación(sin tener en cuenta si la TM que modifica esta ejecutandose en este nivel de aislamiento).  
La tupla que se almacenó previo a la modificación la podemos ver con:
Select * From Sys.dm_tran_version_store
El valor de usuario es cambiado de 0 a 4918., como se encendio en la BD la opción que permite aislamiento SNAPSHOT, esta TM tiene que guardar la tupla antes de la modificación.
