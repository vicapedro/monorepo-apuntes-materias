# DDL

## Base de datos
Una base de datos se define como una colección de tablas relacionadas entre si.

## Consideraciones para crear una BD
- Propósito del almacenamiento de los datos (OLTP, OLAP)
- Posible crecimiento de los dispositivos de almacenamiento físicos 
- Localización de los archivos (remotos, locales)
- Manejo de transacciones
- Arquitectura de la BD

## Archivos de Bases de Datos
Una base de datos se distribuye al menos en dos y probablemente varios archivos de bases de datos. Estos archivos, se especifican al crear o modificar una BD.

### Tipos de Archivos de BD
1. **Primario**.- Tiene extensión MDF. Se encarga de realizar el seguimiento de los demás archivos y es usado para almacenar datos. Contiene todas las tablas del sistema. Una base de datos sólo puede tener un archivo primario. Si no se especifica, el primer archivo enumerado en la instrucción CREATE DATABASE se convierte en el archivo principal.

2. **Secundario**.- Una base de datos puede tener uno o mas archivos secundarios. Tiene extensión NDF.

3. **Registro**.- Toda base de datos tendrá al menos un archivo de registro que contiene información necesaria para recuperar todas las transacciones de la misma. Tienen extensión LDF.

### Arquitectura de la Base de Datos

## Creación de la BD
La forma mas sencilla de crear la BD consiste en utilizar el administrador corporativo del SQL server.
Otra forma es utilizar la instrucción `CREATE DATABASE`

### CREATE DATABASE: - sintaxis parcial -

```sql
CREATE DATABASE database_name
```

Con esta instruccion se crea una base de datos con el nombre especificado en la ubicacion predeterminada del servidor, normalmente en la carpeta de datos del servidor `C:\Program Files\Microsoft SQL Server\MSSQL.x\MSSQL\Data`.

### CREATE DATABASE: - sintaxis completa -

```sql
CREATE DATABASE database_name
ON 
( NAME = 'logical_file_name',
    FILENAME = 'os_file_name',
    SIZE = initial_size,
    MAXSIZE = { max_size | UNLIMITED },
    FILEGROWTH = growth_increment )
[ LOG ON 
( NAME = 'logical_file_name',
    FILENAME = 'os_file_name',
    SIZE = initial_size,
    MAXSIZE = { max_size | UNLIMITED },
    FILEGROWTH = growth_increment ) ]
```

#### Parámetros de filespec:

- **NAME**.- Especifica el nombre lógico del archivo definido por `<filespec>`.
- **logical_file_name**.- Es el nombre utilizado para hacer referencia al archivo en las instrucciones Transact-SQL que se ejecuten después de que se haya creado la base de datos.
- **FILENAME**.- Especifica el nombre de archivo del sistema operativo del archivo definido por `<filespec>`.
- **'os_file_name'**.- Es la ruta de acceso y nombre de archivo que el sistema operativo utiliza cuando crea el archivo físico definido por `<filespec>`.
- **SIZE**.- Especifica el tamaño del archivo definido en `<filespec>`. Cuando en `<filespec>` no se especifica un parámetro SIZE para un archivo secundario o de registro, SQL Server hace el archivo de 1 MB.
- **MAXSIZE**.- Especifica el tamaño máximo al que puede aumentar el archivo definido en `<filespec>`.
- **UNLIMITED**.- Especifica que el archivo definido en `<filespec>` aumentará hasta que el disco esté lleno.
- **FILEGROWTH**.- Especifica el incremento de crecimiento del archivo definido en `<filespec>`. El valor FILEGROWTH de un archivo no puede exceder del valor MAXSIZE.
- **growth_increment**.- Es la cantidad de espacio que se agrega al archivo cada vez que se necesita más espacio. El valor se puede especificar en MB, KB, GB, TB o bien como un porcentaje (%) del tamaño del archivo en el momento en que tiene lugar el incremento. Si no se especifica FILEGROWTH, el valor predeterminado es 10 por ciento, y el valor mínimo es 64 KB.

### Ejemplo: Create Database
Creación de una base de datos que específica un archivo de datos y uno para el registro de transacciones

```sql
CREATE DATABASE MiBaseDatos
ON (NAME = 'MiBaseDatos_Data',
    FILENAME = 'C:\Data\MiBaseDatos.mdf',
    SIZE = 10MB,
    MAXSIZE = 100MB,
    FILEGROWTH = 5MB)
LOG ON (NAME = 'MiBaseDatos_Log',
        FILENAME = 'C:\Data\MiBaseDatos.ldf',
        SIZE = 1MB,
        MAXSIZE = 10MB,
        FILEGROWTH = 1MB);
```

Crear una base de datos mediante la especificación de múltiples archivos de datos y de registro de transacciones

```sql
CREATE DATABASE VentasEmpresa
ON 
  (NAME = 'VentasEmpresa_Data1',
   FILENAME = 'C:\Data\VentasEmpresa_Data1.mdf',
   SIZE = 50MB,
   MAXSIZE = 500MB,
   FILEGROWTH = 10MB),
  (NAME = 'VentasEmpresa_Data2',
   FILENAME = 'C:\Data\VentasEmpresa_Data2.ndf',
   SIZE = 30MB,
   MAXSIZE = 300MB,
   FILEGROWTH = 5MB)
LOG ON 
  (NAME = 'VentasEmpresa_Log1',
   FILENAME = 'C:\Logs\VentasEmpresa_Log1.ldf',
   SIZE = 10MB,
   MAXSIZE = 100MB,
   FILEGROWTH = 5MB),
  (NAME = 'VentasEmpresa_Log2',
   FILENAME = 'C:\Logs\VentasEmpresa_Log2.ldf',
   SIZE = 10MB,
   MAXSIZE = 100MB,
   FILEGROWTH = 5MB);
```

## Grupos de archivos
Es posible agrupar los archivos de una BD en grupos de archivos a efectos de asignación y administración.

### GRUPOS DE ARCHIVOS
- El grupo de archivos donde se encuentra el archivo de datos primario, se denomina **grupo de archivo primario**.
- Además del grupo de archivos primario, una BD puede tener varios grupos de archivos definidos por el usuario.

### CREATE DATABASE – Sintaxis parcial para grupos de archivos

```sql
CREATE DATABASE database_name
ON [PRIMARY] 
  ( FILEGROUP filegroup_name
    [ CONTAINS FILESTREAM ]
    <filespec> [ ,...n ]
  )
[ LOG ON <filespec> [ ,...n ] ]
```

### GRUPOS DE ARCHIVOS (propiedades)
- Un grupo de archivos siempre tiene la propiedad **DEFAULT**.
- Sólo un grupo de archivo puede tener la propiedad **DEFAULT**.
- El grupo de archivos primario, es el grupo de archivo por **DEFAULT**.
- Es posible cambiar el grupo de archivo por DEFAULT con la instrucción `ALTER DATABASE`.
- Los archivos de transacciones **no forman parte** de ningún grupo de archivos.

### GRUPOS DE ARCHIVOS –Ventajas-
- Permiten realizar de copias de seguridad de algunas partes de la BD.
- Se pueden tener tablas distintas asignadas a unidades distintas.
- Es posible colocar tablas y los índices de esas tablas en diferentes grupos. Lo cual, aumenta el desempeño debido al paralelismo.

## MODIFICAR LA BASE DE DATOS
### Operaciones posibles:
- Cambiar el nombre de la BD
- Agregar o borrar uno o varios archivos a la base de datos
- Agregar uno o varios archivos tipo LOG
- Modificar un archivo ya existente
  - Aumentar el size
  - Cambiar la propiedad MAXSIZE o FILEGROWTH
  - Cambiar el nombre del archivo

### ALTER DATABASE

```sql
ALTER DATABASE database_name
{
  ADD FILE <filespec> [ ,...n ] [ TO FILEGROUP filegroup_name ]
  | ADD LOG FILE <filespec> [ ,...n ]
  | REMOVE FILE logical_file_name
  | MODIFY FILE <filespec>
  | SET <optionspec> [ ,...n ]
}
```

## OPCIONES DE LA BASE DE DATOS SET < optionspec >

### Categorías de opciones:
- **Estado**
- **Cursor**
- **Automáticas**
- **De SQL**
- **De recuperación**

### Estado
Controlan la posibilidad de uso de la base de datos, en términos de quién puede utilizar la base de datos y para qué operaciones.

#### Estado: OFFLINE | ONLINE
- **OFFLINE**: La base de datos se cierra sin problemas y se marca como sin conexión. La base de datos no puede ser modificada mientras está desconectada.
- **ONLINE**: La base de datos está abierta y disponible para su utilización. ONLINE es el valor predeterminado.

#### Estado: READ_ONLY | READ_WRITE
- **READ_ONLY**: La base de datos está en modo de sólo lectura. Los usuarios pueden recuperar datos de la base de datos, pero no pueden modificarlos. Una base de datos de sólo lectura no permite realizar modificaciones en los datos. No se producen bloqueos en las bases de datos de sólo lectura, lo que puede producir un aumento del rendimiento de las consultas.
- **READ_WRITE**: Los usuarios pueden recuperar y modificar datos. READ_WRITE es el valor predeterminado.

### OPCIONES AUTOMATICAS
Afectan las acciones que SQL server puede realizar automáticamente. Se pueden activar (ON) o desactivar (OFF).

#### AUTO_CLOSE
Cuando esta opción se establece como ON, la BD se cierra ordenadamente cuando sale el último usuario de la misma. Cuando un usuario intenta utilizar la BD de nuevo, está se vuelve a abrir de forma automática. Afecta negativamente el rendimiento.

#### AUTO_CREATE_STATISTICS
Cuando el valor es ON, se crean automáticamente estadísticas de las columnas utilizadas en un predicado. Agregar estadísticas mejora el rendimiento de las consultas, ya que el optimizador de consultas de SQL Server puede determinar mejor la forma de evaluar una consulta.

#### AUTO_SHRINK
Cuando el valor es ON, los archivos de las bases de datos se pueden reducir periódicamente. Tanto los archivos de datos como los de registro pueden ser reducidos por SQL Server automáticamente. AUTO_SHRINK sólo reduce el tamaño del registro de transacciones si se establece en SIMPLE el modelo de recuperación de la base de datos o si se realiza una copia de seguridad del registro.

### Base de Datos del sistema y de usuario

#### Bases de datos del sistema:
- **master**: Contiene información de configuración del servidor y metadatos de todas las bases de datos
- **model**: Plantilla para nuevas bases de datos. Cualquier configuración en model se aplica a las nuevas BD
- **msdb**: Utilizada por el Agente de SQL Server para programar alertas y trabajos
- **tempdb**: Área de trabajo temporal para consultas y procedimientos

#### Bases de datos de usuario:
Son las bases de datos creadas por los usuarios para almacenar datos específicos de aplicaciones.

### Objetos de la base de datos
- **Tablas**: Estructuras básicas de almacenamiento de datos organizados en filas y columnas
- **Tipos de datos**: Definen el tipo de información que puede almacenarse en cada columna
- **Vistas**: Consultas almacenadas que presentan datos de una o más tablas
- **Procedimientos almacenados**: Conjuntos de instrucciones SQL compiladas y almacenadas
- **Triggers**: Procedimientos especiales que se ejecutan automáticamente ante eventos específicos
- **Funciones**: Rutinas que retornan un valor específico
- **Índices**: Estructuras que mejoran la velocidad de acceso a los datos
- **Constraints**: Reglas que garantizan la integridad de los datos
- **Defaults**: Valores predeterminados para columnas
- **Reglas**: Restricciones de dominio para validar datos

## Tipos de datos

### Tipos de datos numéricos
Son usados en datos con los que se quieren realizar comparaciones numéricas u operaciones aritméticas.

| Tipo | Rango | Bytes |
|------|-------|-------|
| **tinyint** | 0 a 255 | 1 |
| **smallint** | -32,768 a 32,767 | 2 |
| **int** | -2,147,483,648 a 2,147,483,647 | 4 |
| **bigint** | -9,223,372,036,854,775,808 a 9,223,372,036,854,775,807 | 8 |
| **decimal(p,s)** | Precisión fija, escala fija | 5-17 |
| **numeric(p,s)** | Sinónimo de decimal | 5-17 |
| **float** | Precisión flotante | 4 u 8 |
| **real** | Precisión flotante | 4 |

### Tipos de datos de fecha y hora
Son usados en datos para almacenar la fecha y la hora.

| Tipo | Formato | Rango |
|------|---------|-------|
| **datetime** | YYYY-MM-DD hh:mm:ss.nnn | 1753-01-01 a 9999-12-31 |
| **smalldatetime** | YYYY-MM-DD hh:mm | 1900-01-01 a 2079-06-06 |
| **date** | YYYY-MM-DD | 0001-01-01 a 9999-12-31 |
| **time** | hh:mm:ss.nnnnnnn | 00:00:00.0000000 a 23:59:59.9999999 |
| **datetime2** | YYYY-MM-DD hh:mm:ss.nnnnnnn | 0001-01-01 a 9999-12-31 |

### Tipos de dato caracter
Presentan cuatro variedades: cadenas de caracteres de longitud fija o de longitud variable (char o varchar).
- `CHAR(n)`: Longitud fija, rellena con espacios, máximo 8,000 caracteres
- `VARCHAR(n)`: Longitud variable, no rellena espacios, máximo 8,000 caracteres  
- `NCHAR(n)`: Unicode, longitud fija, máximo 4,000 caracteres
- `NVARCHAR(n)`: Unicode, longitud variable, máximo 4,000 caracteres
- `TEXT`: Longitud variable, hasta 2GB (obsoleto, usar VARCHAR(MAX))
- `NTEXT`: Unicode, longitud variable, hasta 1GB (obsoleto, usar NVARCHAR(MAX))

> **Nota importante**: Los tipos de datos `TEXT`, `NTEXT` e `IMAGE` están **obsoletos** y serán eliminados en futuras versiones de SQL Server. Se recomienda usar `VARCHAR(MAX)`, `NVARCHAR(MAX)` y `VARBINARY(MAX)` respectivamente para nuevos desarrollos. Los tipos `CHAR` y `VARCHAR` **NO están obsoletos** y siguen siendo completamente válidos y ampliamente utilizados.

### Otros tipos de datos importantes
- **bit**: Almacena 0, 1 o NULL
- **binary(n)**: Datos binarios de longitud fija
- **varbinary(n)**: Datos binarios de longitud variable
- **image**: Datos binarios variables hasta 2GB (obsoleto)
- **xml**: Almacena datos XML
- **uniqueidentifier**: Almacena GUID (16 bytes)

### Creación de tipos de datos
Los tipos de datos definidos por el usuario son abstracciones de los tipos de datos proporcionados por el SMBD y se utilizan para compartir tipos de datos en las tablas de una base de datos.

```sql
-- Crear tipo de dato personalizado
EXEC sp_addtype 'Codigo', 'CHAR(10)', 'NOT NULL';

-- Usar tipo de dato personalizado
CREATE TABLE Productos (
    CodigoProducto Codigo,
    NombreProducto VARCHAR(100)
);
```

**Creación y borrado de tipos de datos definidos por el usuario**

```sql
-- Eliminar tipo de dato personalizado
EXEC sp_droptype 'Codigo';
```

## Consideraciones para crear una tabla
- Columnas con nulls
- Tipos de datos especiales de una columna
- Columnas Identity
- Columnas timestamp
- Columnas uniqueindentifier

### Columnas con nulls
**Creación de tablas –valores nulos-**

Una columna puede aceptar valores NULL o no:
- **NULL**: Ausencia de valor, no es cero ni cadena vacía
- **NOT NULL**: La columna debe tener siempre un valor
- Si no se especifica, por defecto las columnas permiten NULL

```sql
CREATE TABLE Empleados (
    ID INT NOT NULL,           -- No permite NULL
    Nombre VARCHAR(50) NOT NULL,
    Telefono VARCHAR(15),      -- Permite NULL por defecto
    Email VARCHAR(100) NULL    -- Explícitamente permite NULL
);
```

### Columnas con identity
**Creación de tablas –Identity-**

#### Identity
- Es una **propiedad de la columna**, no es en si un tipo de dato.
- Crea una columna de identidad en una tabla. Esta propiedad se utiliza con las instrucciones `CREATE TABLE` y `ALTER TABLE` de Transact-SQL.
- Genera automáticamente valores numéricos únicos y secuenciales.
- Sintaxis: `IDENTITY(seed, increment)` donde `seed` es el valor inicial e `increment` es el incremento.

**Identity: ejemplo**

```sql
CREATE TABLE Clientes (
    ClienteID INT IDENTITY(1,1) PRIMARY KEY,  -- Inicia en 1, incrementa de 1 en 1
    Nombre VARCHAR(100) NOT NULL,
    Email VARCHAR(100)
);

-- Ejemplo con valores personalizados
CREATE TABLE Facturas (
    FacturaID INT IDENTITY(1000,5) PRIMARY KEY,  -- Inicia en 1000, incrementa de 5 en 5
    ClienteID INT,
    Fecha DATE
);
```

#### Características de Identity
- Permite ver el valor de la semilla (seed) y el incremento.
- Permite desactivar temporalmente los identity
- **No logra la exclusividad**, puede repetirse un valor si se desactiva temporalmente el identity.

```sql
-- Ver el valor actual del identity
SELECT IDENT_CURRENT('Clientes') AS ValorActual;

-- Insertar con identity desactivado temporalmente
SET IDENTITY_INSERT Clientes ON;
INSERT INTO Clientes (ClienteID, Nombre) VALUES (999, 'Cliente Especial');
SET IDENTITY_INSERT Clientes OFF;
```

### Columnas con timestamp

Una columna **timestamp** es un tipo de dato que se actualiza automáticamente cada vez que se modifica una fila.

```sql
CREATE TABLE Productos (
    ProductoID INT IDENTITY(1,1) PRIMARY KEY,
    Nombre VARCHAR(100),
    Precio DECIMAL(10,2),
    Version TIMESTAMP  -- Se actualiza automáticamente en cada cambio
);
```

**Características del timestamp:**
- Generado automáticamente por SQL Server
- No es una fecha/hora real, es un número binario único
- Útil para detectar cambios en las filas (concurrencia optimista)

### Columnas con uniqueidentifier

#### uniqueidentifier
- Almacena valores binarios de 16 bytes que operan como identificadores exclusivos globales (GUID).
- Un GUID es un número binario exclusivo; ningún otro equipo generará un duplicado de ese GUID.
- **No genera automáticamente** nuevos identificadores para las filas insertadas como lo hace la propiedad IDENTITY.
- Para obtener nuevos valores uniqueidentifier, una tabla debe tener una cláusula DEFAULT que especifique la función `NEWID`, o debe haber instrucciones INSERT que usen la función `NEWID`.

**Uniqueidentifier: ejemplo**

```sql
CREATE TABLE Documentos (
    DocumentoGUID UNIQUEIDENTIFIER DEFAULT NEWID() PRIMARY KEY,
    Titulo VARCHAR(200),
    Contenido TEXT,
    FechaCreacion DATETIME DEFAULT GETDATE()
);

-- Insertar con GUID automático
INSERT INTO Documentos (Titulo, Contenido) 
VALUES ('Mi Documento', 'Contenido del documento');

-- Insertar con GUID específico
INSERT INTO Documentos (DocumentoGUID, Titulo, Contenido) 
VALUES (NEWID(), 'Otro Documento', 'Más contenido');
```

## Create Table: sintaxis básica

### Propiedades de las columnas

Las columnas en SQL Server pueden tener las siguientes propiedades:
- **Tipo de dato**: Define qué tipo de información almacena
- **NULL/NOT NULL**: Si permite valores nulos
- **IDENTITY**: Para columnas autonuméricas
- **DEFAULT**: Valor por defecto
- **PRIMARY KEY**: Clave primaria
- **FOREIGN KEY**: Clave foránea
- **UNIQUE**: Valores únicos
- **CHECK**: Restricciones de validación

### CREATE TABLE: sintaxis

```sql
CREATE TABLE table_name (
    column_name data_type [NULL | NOT NULL] [DEFAULT value] [IDENTITY(seed,increment)],
    column_name data_type [column_properties],
    [CONSTRAINT constraint_name] [PRIMARY KEY | UNIQUE | CHECK (condition)],
    [CONSTRAINT fk_name] FOREIGN KEY (column) REFERENCES other_table(column)
);
```

**Ejemplo completo:**

```sql
CREATE TABLE Empleados (
    EmpleadoID INT IDENTITY(1,1) NOT NULL PRIMARY KEY,
    Nombre VARCHAR(50) NOT NULL,
    Email VARCHAR(100) UNIQUE,
    Salario DECIMAL(10,2) CHECK (Salario > 0),
    DepartamentoID INT,
    FechaContrato DATE DEFAULT GETDATE(),
    Activo BIT DEFAULT 1,
    CONSTRAINT FK_Emp_Dept FOREIGN KEY (DepartamentoID) 
        REFERENCES Departamentos(DepartamentoID)
);
```

## Integridad de los datos

La integridad de datos se refiere a la precisión y consistencia de los datos almacenados en una base de datos. SQL Server proporciona varios mecanismos para mantener la integridad:

### Tipos de integridad:
- **Integridad de entidad**: Cada fila debe ser única (PRIMARY KEY)
- **Integridad referencial**: Las relaciones entre tablas deben ser válidas (FOREIGN KEY)
- **Integridad de dominio**: Los valores deben cumplir reglas específicas (CHECK, DEFAULT)
- **Integridad definida por el usuario**: Reglas de negocio personalizadas (TRIGGERS, CONSTRAINTS)

### Constraints (Restricciones):
- **PRIMARY KEY**: Identifica únicamente cada fila
- **FOREIGN KEY**: Mantiene relaciones entre tablas
- **UNIQUE**: Garantiza valores únicos en una columna
- **CHECK**: Valida que los datos cumplan una condición
- **NOT NULL**: Asegura que una columna tenga valor
- **DEFAULT**: Proporciona valores predeterminados

### Agregando y eliminando columnas

```sql
-- Agregar una columna
ALTER TABLE table_name
ADD column_name data_type [constraints];

-- Agregar múltiples columnas
ALTER TABLE Empleados
ADD Telefono VARCHAR(15),
    Direccion VARCHAR(200),
    CodigoPostal CHAR(5);

-- Eliminar una columna
ALTER TABLE table_name
DROP COLUMN column_name;

-- Modificar una columna existente
ALTER TABLE table_name
ALTER COLUMN column_name new_data_type [NULL | NOT NULL];

-- Ejemplo completo
ALTER TABLE Empleados
ADD FechaNacimiento DATE,
    Estado BIT DEFAULT 1;

ALTER TABLE Empleados
DROP COLUMN Telefono;

ALTER TABLE Empleados
ALTER COLUMN Email VARCHAR(150) NOT NULL;
```
