 Triggers

Slide 2:
Qué es un trigger?
Un trigger es un procedimiento almacenado especial:
Se invoca cuando se ejecuta un INSERT, UPDATE o  DELETE sobre la tabla con la cual se asocia.
No puede ser llamado directamente.
El código del trigger y la instrucción que lo invocó, forman parte de la misma transacción.

Slide 3:
Para qué sirven los Triggers?
Realizar cambios en cascada.- Los triggers pueden realizar cambios en cascada, sin embargo esos cambios pueden ser realizados de forma mas eficiente utilizando integridad referencial. 
Garantizar la consistencia de los datos.- Se usan para garantizar la integridad Referencial, donde un CHECK no lo puede realizar.
Compara antes o después de las instrucciones de modificación de datos.

Slide 4:
Consideraciones para usar Triggers

Los Constraints se verifican antes que los triggers.
Una tabla, puede tener varios triggers. 
El propietario de la tabla debe tener permisos para crear triggers.  
No se pueden crear Triggers sobre Tablas Temporales.
Los Triggers no pueden regresar valores.

Slide 5:
Sintaxis 

CREATE TRIGGER trigger_name 
ON { table | view } 
[ WITH ENCRYPTION ] 
{ 
    { { FOR | AFTER | INSTEAD OF } { [ INSERT ] [ , ] [ UPDATE ] } 
       AS 
        [ { IF UPDATE ( column ) 
            [ { AND | OR } UPDATE ( column ) ] 
                [ ...n ] 
        | IF ( COLUMNS_UPDATED ( ) { bitwise_operator } updated_bitmask ) 
                { comparison_operator } column_bitmask [ ...n ] 
        } ] 
        sql_statement [ ...n ] 
    } 
} 

Slide 6:
Tipos de triggers
AFTER triggers. Son ejecutados despues de que la accion INSERT, UPDATE O DELETE se ha realizado. Soolamente se pueden definir AFTER trigger para tablas.
INSTEAD OF triggers. Son ejecutados antes de que la instrucción se realice. INSTEAD OF triggers, peden ser definidos sobre vistas con una o mas tablas base.

Slide 20:
Triggers INSTEAD OFF
Puede tener solo un tigger para cada accion INSERT, DELETE Y UPDATE.
No se pueden combinar con claves foraneas definidas con CASCADE.
No pueden ser recursivos.
Fueron diseñados para trabajar con vistas.

Slide 21:
Triggers INSTEAD OFF
CREATE TRIGGER DEL_union
ON vista_union
INSTEAD OF DELETE
AS 
DELETE tabla_1 
WHERE tabla_1.a IN (SELECT a1 FROM DELETED)
DELETE tabla_2 
WHERE tabla_2.a IN (SELECT a2 FROM DELETED)

CREATE VIEW vista_union AS
SELECT tabla_1.a as a1, b, c,
       tabla_2.a as a2, message
FROM tabla_1 JOIN tabla_2
ON tabla_1.a=tabla_2.a



Slide 22:
Consideraciones de Performance 
Los Triggers trabajan rápidamente por que las tablas  inserted and deleted  están en Cache
El tiempo de ejecución es determinado por:
El Número de tablas que son referenciadas
El Número de renglones que son afectados
Las acciones contenidas en un trigger son partes implícitas de una  Transacción

Slide 23:
Alterando y Eliminando Triggers
Alterar un Trigger
Cambia la definición sin eliminar el  trigger
Pueden activar o desactivar un trigger





Eliminar un Trigger: DROP TRIGGER <<nombre>>

 FOR INSERT
 AS
 	UPDATE copy

 	FROM copy INNER JOIN inserted
