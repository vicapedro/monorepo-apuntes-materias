Slide 3:
Qué es una vista?
Es una tabla virtual. 
Es una instrucción SELECT con nombre que produce dinámicamente un conjunto de resultados sobre los que se puede seguir operando.
Realmente, No guarda datos.
Sirve como filtro de las tablas que guardan los datos.

Slide 6:
Para qué se utilizan las vistas?
Permite a los usuarios enfocarse a datos específicos que son utilizados para tareas especificas. Los datos innecesarios, no se incluyen en la vista.
Simplifica el trabajo del usuario. Pueden definirse las consultas complejas y frecuentes como UNION, joins como vistas de tal forma que el usuario no tiene que especificar todas las condiciones.
Mejora la seguridad permitiendo al usuario acceder los datos a través de la vista, sin tener que otorgar a los usuarios los permisos sobre las tablas base.

Slide 12:
Requisitos para crear una vista
La instrucción ORDER BY, no puede ser usada en la consulta de la vista.
No puede tener un compute.
No puede tener un select…into
Todos las columnas de resultados deben tener nombre.
Es posible definir vistas sobre otras vistas (32 niveles máximo).
No se puede asociar un TRIGGER AFTER triggers con vistas, sólo triggers INSTEAD OF

Slide 17:
Modificar datos en una vista
Las vistas no mantienen una copia separada de los datos ( a excepción de las vistas indexadas).
Los cambios realizados sobre las vistas, modifican la tabla base.
Restricciones:
No puede afectar más de una tabla base.
No puede modificarse columnas derivadas de cálculos.
No puede modificar columnas  afectadas por GROUP BY, HAVING o DISTINCT


Slide 18:
Modificación de datos a través de las vistas
Los datos insertados o modificados en una vista, son verificadas si la opción  WITH CHECK OPTION ha sido especificada
Se considera actualizable si no contiene GROUP BY, TOP, UNION o  DISTINCT.
Si no se especifica WITH CKECK OPTION puede darse la alta en la tabla, pero no aparecer en la vista.

Slide 19:
Modificación de datos a través de las vistas
No se permiten DELETE en vistas formadas por varias tablas. Sólo INSERT y UPDATE.
No se aceptan INSERT, a menos que en la vista mediante la que se están insertando nuevas filas se incluyan todas las columnas NOT NULL.
Todas las columnas que se estén modificando deben de cumplir con las restricciones para la instrucción de modificación de datos, como si se estuviera ejecutando directamente sobre la tabla.

Slide 21:
Encryption
Si se especifica esta opción, el código SQL será cifrado.
Se aplica a triggers, procedimientos almacenados, vistas y tipos definidos por el usuario.
Se protege la lógica de la vista. 
USE library
GO
CREATE VIEW dbo.UnpaidFinesView (Member, TotalUnpaidFines)
WITH ENCRYPTION
AS
SELECT member_no, (sum(fine_assessed-fine_paid))
FROM loanhist
GROUP BY member_no, fine_assessed, fine_paid
HAVING SUM(fine_assessed-fine_paid) > 0
GO

Slide 22:
SchemaBinding
Liga el esquema de la vista o el tipo de dato al esquema de los objetos. 
Si se especifica esta opción, no se podrán borrar objetos  o realizar cambios al esquema.
Si se especifica esta opción no se podrá utilizar el * en a cláusula select y se debe de poner user.nombre, como nombre de la vista.

Slide 23:
Check option
Previene que se realicen inserciones o actualizaciones que tengan conflicto con la cláusula where de la vista.

Slide 26:
Vistas  indexadas –Materializadas-
Es una vista con un índice único, tipo clusterd.
Una vista materializada mejora el performance.
Permite al optimizador de consultas usar la vista.
Usa la vista cuando:
Los datos son modificados con poca frecuencia
Las consultas involucran un gran numero de JOINs y agregaciones


Slide 27:
Restricciones sobre las vistas materializadas
La vista no debe hacer referencia a ninguna otra vista, sólo a tablas base.
La vista se debe crear con la opción SCHEMABINDING. Mediante la opción SCHEMABINDING se asocia la vista al esquema de las tablas base.




Slide 28:
Vistas materializadas

USE northwind

CREATE VIEW product_totals
 WITH SCHEMABINDING
AS
SELECT productid, total_volume= sum (unitprice*quantity),
Total_qty=SUM (Quantity), number=count_big(*)

Slide 30:
Vistas divididas (particionadas)
Las vistas divididas permiten ver conjuntos de datos disjuntos en tablas independientes.
Una vista será considerada particionada si:
Las columnas de las posiciones correspondientes de cada SELECT son del mismo tipo exacto.
Una columna de cada tabla, en la misma posición debe tener una cláusula check definiendo sobre ellas restricciones mutuamente excluyente. Por ejemplo: una tabla puede tener un check región=‘norte, otra región=‘sur’, etc.
