## Introducción a QoS

### ¿Qué es Quality of Service?

**Quality of Service (QoS)** es el conjunto de **técnicas y mecanismos** para gestionar los recursos de red y proporcionar **diferentes niveles de servicio** a distintos tipos de tráfico.

```
┌────────────────────────────────────────────────────────┐
│  RED SIN QoS (Best Effort)                             │
├────────────────────────────────────────────────────────┤
│                                                        │
│  Todos los paquetes tratados igual:                   │
│                                                        │
│  [VoIP] [Email] [Video] [Download] → FIFO → Salida   │
│                                                        │
│  Problema:                                            │
│  - Download satura enlace                             │
│  - VoIP sufre delay/jitter                           │
│  - Video se entrecorta                                │
│                                                        │
└────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────┐
│  RED CON QoS                                           │
├────────────────────────────────────────────────────────┤
│                                                        │
│  Clasificación por prioridad:                         │
│                                                        │
│  [VoIP]     → Cola Alta Prioridad   → Salida primero │
│  [Video]    → Cola Media Prioridad  → Salida segundo │
│  [Email]    → Cola Baja Prioridad   → Salida después │
│  [Download] → Cola Baja Prioridad   → Salida después │
│                                                        │
│  Resultado:                                           │
│  ✅ VoIP con baja latencia/jitter                     │
│  ✅ Video fluido                                      │
│  ✅ Download usa ancho de banda sobrante              │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### Objetivos de QoS

1. **Garantizar recursos** para aplicaciones críticas
2. **Reducir latencia y jitter** para aplicaciones sensibles al tiempo
3. **Prevenir congestión** mediante gestión inteligente de colas
4. **Maximizar utilización** del ancho de banda disponible
5. **Cumplir SLAs** (Service Level Agreements)

## ¿Por Qué es Necesario QoS?

### Problema: Todas las Aplicaciones No Son Iguales

```
┌──────────────────────────────────────────────────────────┐
│  CARACTERÍSTICAS POR TIPO DE TRÁFICO                     │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  VoIP (Voz sobre IP)                                    │
│  ├─ Latencia requerida: <150ms                         │
│  ├─ Jitter tolerado: <30ms                             │
│  ├─ Packet loss tolerado: <1%                          │
│  ├─ Ancho de banda: 64-128 Kbps por llamada           │
│  └─ Prioridad: ALTA ⚠️                                 │
│                                                          │
│  Video Conferencia                                      │
│  ├─ Latencia requerida: <150ms                         │
│  ├─ Jitter tolerado: <30ms                             │
│  ├─ Packet loss tolerado: <0.5%                        │
│  ├─ Ancho de banda: 1-5 Mbps                           │
│  └─ Prioridad: ALTA ⚠️                                 │
│                                                          │
│  Video Streaming (Netflix, YouTube)                     │
│  ├─ Latencia requerida: <1s (buffer inicial)           │
│  ├─ Jitter tolerado: Variable (buffered)               │
│  ├─ Packet loss tolerado: <1%                          │
│  ├─ Ancho de banda: 3-25 Mbps                          │
│  └─ Prioridad: MEDIA                                   │
│                                                          │
│  Navegación Web (HTTP/HTTPS)                           │
│  ├─ Latencia requerida: <500ms                         │
│  ├─ Jitter tolerado: No crítico                        │
│  ├─ Packet loss tolerado: <3% (TCP retransmite)       │
│  ├─ Ancho de banda: Variable                           │
│  └─ Prioridad: MEDIA                                   │
│                                                          │
│  Email (SMTP/IMAP)                                      │
│  ├─ Latencia requerida: <5s                            │
│  ├─ Jitter tolerado: No crítico                        │
│  ├─ Packet loss tolerado: <5%                          │
│  ├─ Ancho de banda: Bajo                               │
│  └─ Prioridad: BAJA                                    │
│                                                          │
│  Transferencias FTP/Torrents                           │
│  ├─ Latencia requerida: No crítica                     │
│  ├─ Jitter tolerado: No crítico                        │
│  ├─ Packet loss tolerado: <10%                         │
│  ├─ Ancho de banda: Todo lo disponible                │
│  └─ Prioridad: BAJA (Scavenger)                       │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### Escenario Sin QoS

```
Situación: Enlace de 100 Mbps saturado

Usuario A: Descargando archivo grande (usando 95 Mbps)
Usuario B: En video conferencia (necesita 2 Mbps)

Sin QoS:
├─ Congestión en router
├─ Todos los paquetes sufren delay
├─ Video conferencia se entrecorta
└─ Usuario B frustrado

Con QoS:
├─ Video conferencia marcado como alta prioridad
├─ Download limitado a 80 Mbps
├─ Video conferencia obtiene sus 2 Mbps garantizados
└─ Ambos usuarios satisfechos
```

## Modelos de QoS

### 1. Best Effort (Sin QoS)

```
Modelo por defecto de Internet:
├─ Todos los paquetes tratados igual
├─ FIFO (First In, First Out)
├─ No garantías de servicio
└─ Funciona cuando hay abundancia de recursos

Pros:
✅ Simple, sin configuración
✅ Sin overhead

Contras:
❌ No protege tráfico crítico
❌ Congestión afecta a todos por igual
```

### 2. Integrated Services (IntServ)

```
Reserva de recursos por flujo:
├─ RSVP (Resource Reservation Protocol)
├─ Cada aplicación reserva ancho de banda
├─ Garantías end-to-end
└─ Usado en redes pequeñas/controladas

Pros:
✅ Garantías estrictas
✅ QoS por flujo individual

Contras:
❌ No escala (estado por flujo)
❌ Complejidad de gestión
❌ Poco usado en Internet
```

### 3. Differentiated Services (DiffServ)

```
Modelo más usado actualmente:
├─ Clasificación por clases de tráfico
├─ Marcado con DSCP (campo IP)
├─ Tratamiento por hop (router por router)
└─ Escalable para grandes redes

Pros:
✅ Escalable
✅ Simple de implementar
✅ Estándar de la industria

Contras:
⚠️ No garantías absolutas end-to-end
⚠️ Requiere configuración consistente
```

**DiffServ es el modelo que implementaremos en este curso.**

## Clasificación y Marcado de Tráfico

### DSCP (Differentiated Services Code Point)

**DSCP** es un campo de 6 bits en el header IP (dentro del campo ToS/Traffic Class).

```
┌─────────────────────────────────────────────────────┐
│  HEADER IP (IPv4)                                   │
├─────────────────────────────────────────────────────┤
│  Version │ IHL │ DSCP │ ECN │ Total Length         │
│   (4b)   (4b)  (6b)  (2b)   (16b)                  │
└─────────────────────────────────────────────────────┘

DSCP: 6 bits = 64 valores posibles (0-63)
ECN: 2 bits para Explicit Congestion Notification
```

### Valores DSCP Estándar

#### Per-Hop Behaviors (PHBs)

```
┌───────────────────────────────────────────────────────────┐
│  CLASES DSCP PRINCIPALES                                  │
├───────────────────────────────────────────────────────────┤
│                                                           │
│  EF (Expedited Forwarding) - DSCP 46                     │
│  ├─ Prioridad más alta                                   │
│  ├─ Baja latencia, bajo jitter, baja pérdida            │
│  ├─ Uso: VoIP, control de señalización                  │
│  └─ Binario: 101110                                     │
│                                                           │
│  AF (Assured Forwarding) - DSCP 10-46                    │
│  ├─ 4 clases (AF1x, AF2x, AF3x, AF4x)                   │
│  ├─ 3 niveles de drop precedence (baja, media, alta)    │
│  ├─ Uso: Aplicaciones críticas del negocio              │
│  └─ Ejemplos:                                            │
│      AF41 (DSCP 34): Video conferencia                  │
│      AF31 (DSCP 26): Streaming                          │
│      AF21 (DSCP 18): Transaccional                      │
│      AF11 (DSCP 10): Bulk data                          │
│                                                           │
│  CS (Class Selector) - DSCP 0-56 (múltiplos de 8)       │
│  ├─ Compatibilidad con IP Precedence antiguo            │
│  ├─ CS0 (0): Best Effort                                │
│  ├─ CS1 (8): Scavenger (menos que best effort)          │
│  ├─ CS5 (40): Señalización (SIP, H.323)                 │
│  └─ CS6 (48): Network control                           │
│                                                           │
│  DF (Default Forwarding) - DSCP 0                        │
│  ├─ Best effort tradicional                             │
│  └─ Sin garantías                                        │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

#### Tabla de Valores DSCP Comunes

| DSCP | Decimal | Binario | Nombre | Uso Típico |
|------|---------|---------|--------|------------|
| EF | 46 | 101110 | Expedited Forwarding | VoIP RTP |
| CS5 | 40 | 101000 | Class Selector 5 | VoIP Signaling |
| AF41 | 34 | 100010 | Assured Forwarding 41 | Video conferencia |
| AF31 | 26 | 011010 | Assured Forwarding 31 | Streaming video |
| AF21 | 18 | 010010 | Assured Forwarding 21 | Tráfico transaccional |
| AF11 | 10 | 001010 | Assured Forwarding 11 | Bulk data importante |
| CS1 | 8 | 001000 | Class Selector 1 | Scavenger (P2P, backup) |
| DF | 0 | 000000 | Default | Best effort |

### 802.1p (Capa 2 - Ethernet)

Para QoS en **LAN** (switches), se usa **802.1p CoS** (Class of Service).

```
┌─────────────────────────────────────────────────────┐
│  802.1Q VLAN TAG (Ethernet Frame)                   │
├─────────────────────────────────────────────────────┤
│  TPID │ PCP │ DEI │ VID                             │
│  (16b) (3b) (1b) (12b)                              │
└─────────────────────────────────────────────────────┘

PCP (Priority Code Point): 3 bits = 8 valores (0-7)
También llamado CoS (Class of Service)
```

#### Valores 802.1p

| CoS | Prioridad | Tráfico |
|-----|-----------|---------|
| 7 | Highest | Network control |
| 6 | High | Voice (señalización) |
| 5 | High | Voice (media RTP) |
| 4 | Medium-High | Video conferencia |
| 3 | Medium | Aplicaciones críticas |
| 2 | Medium-Low | Excelent effort |
| 1 | Low | Background (bulk) |
| 0 | Lowest | Best effort |

### Mapeo DSCP ↔ 802.1p

```
┌────────────────────────────────────────────┐
│  DSCP (Capa 3)  →  CoS (Capa 2)           │
├────────────────────────────────────────────┤
│  EF (46)        →  5 (Voice)              │
│  CS5 (40)       →  5 (Voice signaling)    │
│  AF41 (34)      →  4 (Video)              │
│  AF31 (26)      →  3 (Critical apps)      │
│  AF21 (18)      →  2 (Excellent effort)   │
│  CS1 (8)        →  1 (Background)         │
│  DF (0)         →  0 (Best effort)        │
└────────────────────────────────────────────┘

Nota: El mapeo exacto puede variar según vendor
```

## Mecanismos de QoS

### Clasificación (Classification)

**Identificar el tipo de tráfico** basándose en criterios.

```
Criterios de clasificación:
├─ Capa 2: MAC origen/destino, VLAN, 802.1p
├─ Capa 3: IP origen/destino, DSCP, protocolo
├─ Capa 4: Puerto TCP/UDP origen/destino
├─ Capa 7: Aplicación (DPI - Deep Packet Inspection)
└─ Combinaciones de los anteriores

Ejemplos:
- "Todo el tráfico de 192.168.1.0/24 → Clase A"
- "TCP puerto 5060-5061 (SIP) → VoIP Signaling"
- "UDP puerto 10000-20000 (RTP) → VoIP Media"
- "HTTP User-Agent contiene 'Zoom' → Video conferencia"
```

### Marcado (Marking)

**Etiquetar paquetes** para tratamiento posterior.

```
Marcado en diferentes capas:
├─ Capa 2: Establecer 802.1p CoS
├─ Capa 3: Establecer DSCP en header IP
└─ Interno: Marcar en switch/router (no modifica paquete)

Punto de marcado:
├─ Lo más cerca de la fuente posible
├─ Típicamente en switch de acceso o router de borde
└─ Se respeta en toda la red (trust boundary)
```

### Policing (Control de Tasa)

**Limitar la tasa** de tráfico, descartando exceso.

```
┌────────────────────────────────────────────┐
│  POLICING                                  │
├────────────────────────────────────────────┤
│                                            │
│  Límite configurado: 10 Mbps              │
│                                            │
│  Tráfico entrante: 15 Mbps                │
│    ├─ Primeros 10 Mbps → Permitidos      │
│    └─ Exceso 5 Mbps → DESCARTADOS        │
│                                            │
│  Resultado: Puede causar packet loss      │
│                                            │
└────────────────────────────────────────────┘

Uso típico:
- Entrada de WAN (enforce SLA del ISP)
- Prevenir que un usuario sature enlace
- Cumplimiento de políticas corporativas
```

### Shaping (Modelado de Tráfico)

**Limitar la tasa** mediante buffering (delay, no drop).

```
┌────────────────────────────────────────────┐
│  SHAPING                                   │
├────────────────────────────────────────────┤
│                                            │
│  Límite configurado: 10 Mbps              │
│                                            │
│  Tráfico entrante: 15 Mbps                │
│    ├─ Primeros 10 Mbps → Enviados        │
│    └─ Exceso 5 Mbps → BUFFERED (espera)  │
│                                            │
│  Resultado: Incrementa latencia pero      │
│             evita packet loss              │
│                                            │
└────────────────────────────────────────────┘

Uso típico:
- Salida de WAN (adaptar a ancho de banda disponible)
- Prevenir congestión downstream
- Suavizar tráfico bursty
```

**Policing vs Shaping:**

| Característica | Policing | Shaping |
|----------------|----------|---------|
| **Acción exceso** | DROP | BUFFER (delay) |
| **Latencia** | No aumenta | Aumenta |
| **Packet loss** | Puede aumentar | Reduce |
| **Dirección** | Típicamente inbound | Típicamente outbound |
| **Buffer requerido** | Mínimo | Significativo |

### Queuing (Encolamiento)

**Gestionar múltiples colas** con diferentes prioridades.

```
┌──────────────────────────────────────────────────────┐
│  QUEUING HIERARCHY                                   │
├──────────────────────────────────────────────────────┤
│                                                      │
│  Tráfico entrante:                                  │
│  [VoIP] [Video] [Web] [Bulk] [Scavenger]          │
│                                                      │
│          ↓ CLASIFICACIÓN ↓                          │
│                                                      │
│  Cola 1 (Priority): [VoIP] → Servida primero       │
│  Cola 2 (High):     [Video]                         │
│  Cola 3 (Medium):   [Web]                           │
│  Cola 4 (Low):      [Bulk]                          │
│  Cola 5 (Scavenger):[P2P] → Servida última         │
│                                                      │
│          ↓ SCHEDULER ↓                              │
│                                                      │
│  Salida: Según algoritmo (PQ, WFQ, etc.)           │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### Congestión Avoidance

**Prevenir congestión** antes de que ocurra.

```
Técnicas:
├─ RED (Random Early Detection)
│   └─ Descartar paquetes aleatoriamente cuando cola llena
│
├─ WRED (Weighted RED)
│   └─ RED pero respetando DSCP (drop primero bajo DSCP)
│
└─ ECN (Explicit Congestion Notification)
    └─ Marcar paquetes en lugar de descartar
```

## Algoritmos de Cola (Queuing)

### 1. FIFO (First In, First Out)

**Algoritmo más simple**: El primero en llegar, primero en salir.

```
┌────────────────────────────────────┐
│  FIFO QUEUE                        │
├────────────────────────────────────┤
│  Entrada → [P1][P2][P3][P4] → Salida │
│                                    │
│  P1 entra primero → P1 sale primero│
└────────────────────────────────────┘

Pros:
✅ Simple
✅ Bajo overhead

Contras:
❌ No diferencia tráfico
❌ No hay QoS
❌ Congestión afecta a todos
```

### 2. Priority Queuing (PQ)

**Strict Priority**: Cola de alta prioridad siempre primero.

```
┌────────────────────────────────────────────┐
│  PRIORITY QUEUING                          │
├────────────────────────────────────────────┤
│                                            │
│  Cola High:   [VoIP][VoIP] ────┐         │
│  Cola Medium: [Video][Web]      │→ Scheduler│
│  Cola Low:    [Bulk][Bulk][Bulk]┘         │
│                                            │
│  Regla: Vaciar High, luego Medium,        │
│         finalmente Low                     │
│                                            │
└────────────────────────────────────────────┘

Pros:
✅ Baja latencia para tráfico prioritario
✅ Simple de entender

Contras:
❌ Starvation de colas bajas
❌ Tráfico alto en cola prioritaria bloquea todo
```

**⚠️ Riesgo de Starvation**: Si cola High siempre tiene tráfico, colas Medium/Low nunca se atienden.

### 3. WFQ (Weighted Fair Queuing)

**Fairness con pesos**: Distribución proporcional de ancho de banda.

```
┌────────────────────────────────────────────┐
│  WEIGHTED FAIR QUEUING                     │
├────────────────────────────────────────────┤
│                                            │
│  Cola A (peso 50): [P1][P2] → 50% BW      │
│  Cola B (peso 30): [P3]     → 30% BW      │
│  Cola C (peso 20): [P4]     → 20% BW      │
│                                            │
│  Scheduler sirve proporcionalmente         │
│                                            │
└────────────────────────────────────────────┘

Ejemplo con 100 Mbps:
- Cola A: 50 Mbps garantizados
- Cola B: 30 Mbps garantizados
- Cola C: 20 Mbps garantizados

Pros:
✅ Previene starvation
✅ Garantías de ancho de banda
✅ Fairness

Contras:
⚠️ No garantiza baja latencia
⚠️ Más complejo que PQ
```

### 4. CBWFQ (Class-Based WFQ)

**WFQ con clasificación**: Combinación de clasificación + WFQ.

```
┌────────────────────────────────────────────┐
│  CLASS-BASED WFQ                           │
├────────────────────────────────────────────┤
│                                            │
│  Clase VoIP (30%):    [P1][P2]            │
│  Clase Video (40%):   [P3][P4][P5]        │
│  Clase Data (20%):    [P6]                │
│  Clase Default (10%): [P7][P8]            │
│                                            │
│  Cada clase garantiza % de ancho de banda │
│                                            │
└────────────────────────────────────────────┘

Características:
- Clases configurables (no solo por flujo)
- Garantías de ancho de banda mínimo
- Excess bandwidth compartido proporcionalmente
```

### 5. LLQ (Low Latency Queuing)

**CBWFQ + Priority Queue**: Lo mejor de ambos mundos.

```
┌────────────────────────────────────────────┐
│  LOW LATENCY QUEUING (LLQ)                 │
├────────────────────────────────────────────┤
│                                            │
│  Priority Queue (strict): [VoIP] ────┐    │
│                                       │    │
│  CBWFQ Queues:                       │→ Out│
│    Clase Video (50%): [Video]        │    │
│    Clase Data (30%):  [Web]          │    │
│    Clase Default (20%):[Bulk] ──────┘    │
│                                            │
│  VoIP siempre primero (con policing)      │
│  Resto con CBWFQ                          │
│                                            │
└────────────────────────────────────────────┘

Pros:
✅ Baja latencia para VoIP
✅ Garantías para el resto
✅ No starvation (priority queue limitada)

Uso:
- Gold standard para VoIP + datos
- Cisco IOS default para QoS moderno
```

### Comparación de Algoritmos

| Algoritmo | Latencia | Garantías BW | Fairness | Complejidad |
|-----------|----------|--------------|----------|-------------|
| **FIFO** | Variable | ❌ No | ❌ No | Muy baja |
| **PQ** | ✅ Baja (high) | ❌ No | ❌ No | Baja |
| **WFQ** | Media | ✅ Sí | ✅ Sí | Media |
| **CBWFQ** | Media | ✅ Sí | ✅ Sí | Alta |
| **LLQ** | ✅ Baja (priority) | ✅ Sí | ✅ Sí | Alta |

## Traffic Shaping vs Traffic Policing

### Conceptos Detallados

#### Token Bucket Algorithm

Ambos shaping y policing típicamente usan **Token Bucket**.

```
┌─────────────────────────────────────────────────┐
│  TOKEN BUCKET                                   │
├─────────────────────────────────────────────────┤
│                                                 │
│  Bucket capacity: 1000 tokens (burst size)     │
│  Token rate: 100 tokens/s (rate)               │
│                                                 │
│  ┌────────────────┐                            │
│  │   🪙🪙🪙🪙🪙   │  ← Bucket con tokens       │
│  │   🪙🪙🪙🪙     │                            │
│  └────────────────┘                            │
│         ↑                                       │
│    Tokens agregados                             │
│    a 100/segundo                                │
│                                                 │
│  Paquete llega (100 bytes = 100 tokens):       │
│  ├─ Hay tokens? → PERMITIR, consumir tokens    │
│  └─ No hay tokens? → POLICING: DROP            │
│                      SHAPING: BUFFER           │
│                                                 │
└─────────────────────────────────────────────────┘
```

#### Traffic Policing

```bash
# Ejemplo conceptual de policing

Configuración:
- Rate: 10 Mbps (Committed Information Rate - CIR)
- Burst: 1 MB (Committed Burst Size - CBS)

Comportamiento:
if (paquete_size <= tokens_disponibles):
    transmitir(paquete)
    tokens -= paquete_size
else:
    DROP(paquete)  # O marcar como exceso
```

**Acciones posibles:**
- **Conform**: Dentro del rate → Transmitir
- **Exceed**: Excede CIR pero dentro de burst → Marcar como low priority
- **Violate**: Excede todo → DROP

#### Traffic Shaping

```bash
# Ejemplo conceptual de shaping

Configuración:
- Rate: 10 Mbps
- Burst: 1 MB
- Queue size: 10 MB

Comportamiento:
if (paquete_size <= tokens_disponibles):
    transmitir(paquete)
    tokens -= paquete_size
else:
    if (queue_space_available):
        buffer(paquete)  # Espera en cola
    else:
        DROP(paquete)    # Solo si cola llena
```

## QoS en Linux con tc (Traffic Control)

### Introducción a tc

**tc** (traffic control) es la herramienta de Linux para QoS.

```
Conceptos clave:
├─ qdisc (queuing discipline): Algoritmo de cola
├─ class: Categoría de tráfico
├─ filter: Regla de clasificación
└─ action: Acción a tomar (mark, drop, etc.)

Jerarquía:
qdisc (root)
  ├─ class 1
  │   └─ qdisc (leaf)
  ├─ class 2
  │   └─ qdisc (leaf)
  └─ class 3
      └─ qdisc (leaf)
```

### Qdiscs Disponibles

```bash
# Ver qdiscs disponibles
tc qdisc show

# Qdiscs comunes:
# - pfifo_fast: FIFO con 3 bandas de prioridad (default)
# - sfq: Stochastic Fair Queuing
# - tbf: Token Bucket Filter (shaping)
# - htb: Hierarchical Token Bucket (flexible)
# - prio: Priority queuing
# - fq_codel: Fair Queue with Controlled Delay (anti-bufferbloat)
```

### Ejemplo 1: Traffic Shaping Simple con TBF

**Limitar interfaz a 10 Mbps:**

```bash
# Eliminar qdisc actual
sudo tc qdisc del dev eth0 root

# Agregar TBF (Token Bucket Filter)
sudo tc qdisc add dev eth0 root tbf \
  rate 10mbit \
  burst 32kbit \
  latency 400ms

# Parámetros:
# - rate: Tasa máxima (10 Mbps)
# - burst: Tamaño de ráfaga permitida (32 KB)
# - latency: Máximo delay antes de drop (400ms)

# Verificar
tc qdisc show dev eth0

# Output:
qdisc tbf 1: root refcnt 2 rate 10Mbit burst 4Kb lat 400.0ms

# Test con iperf3
iperf3 -c servidor
# Debería limitar a ~10 Mbps
```

### Ejemplo 2: HTB (Hierarchical Token Bucket)

**HTB permite crear jerarquía de clases con límites.**

```bash
#!/bin/bash
# qos_htb.sh - QoS básico con HTB

INTERFACE="eth0"
TOTAL_BW="100mbit"  # Ancho de banda total

# 1. Limpiar qdiscs existentes
tc qdisc del dev $INTERFACE root 2>/dev/null

# 2. Crear qdisc raíz HTB
tc qdisc add dev $INTERFACE root handle 1: htb default 30

# 3. Crear clase raíz (100 Mbps total)
tc class add dev $INTERFACE parent 1: classid 1:1 htb rate $TOTAL_BW

# 4. Crear clases hijas (distribución de ancho de banda)

# Clase 1:10 - VoIP (30% = 30 Mbps, prioridad alta)
tc class add dev $INTERFACE parent 1:1 classid 1:10 htb \
  rate 30mbit ceil 50mbit prio 1

# Clase 1:20 - Video (40% = 40 Mbps, prioridad media)
tc class add dev $INTERFACE parent 1:1 classid 1:20 htb \
  rate 40mbit ceil 60mbit prio 2

# Clase 1:30 - Data (20% = 20 Mbps, prioridad baja)
tc class add dev $INTERFACE parent 1:1 classid 1:30 htb \
  rate 20mbit ceil 80mbit prio 3

# Clase 1:40 - Bulk (10% = 10 Mbps, prioridad muy baja)
tc class add dev $INTERFACE parent 1:1 classid 1:40 htb \
  rate 10mbit ceil 100mbit prio 4

# Parámetros:
# - rate: Ancho de banda garantizado
# - ceil: Ancho de banda máximo (puede usar si hay disponible)
# - prio: Prioridad (1 = más alta)

# 5. Asignar qdiscs hoja (SFQ para fairness dentro de cada clase)
tc qdisc add dev $INTERFACE parent 1:10 handle 10: sfq perturb 10
tc qdisc add dev $INTERFACE parent 1:20 handle 20: sfq perturb 10
tc qdisc add dev $INTERFACE parent 1:30 handle 30: sfq perturb 10
tc qdisc add dev $INTERFACE parent 1:40 handle 40: sfq perturb 10

# 6. Crear filtros para clasificar tráfico

# VoIP - Puerto UDP 5060-5061 (SIP) y 10000-20000 (RTP)
tc filter add dev $INTERFACE protocol ip parent 1:0 prio 1 u32 \
  match ip protocol 17 0xff \
  match ip dport 5060 0xffff \
  flowid 1:10

tc filter add dev $INTERFACE protocol ip parent 1:0 prio 1 u32 \
  match ip protocol 17 0xff \
  match ip sport 10000 0x0000 \
  match ip sport 0x0000 20000 \
  flowid 1:10

# Video - Puerto TCP 443 con DSCP EF (46)
tc filter add dev $INTERFACE protocol ip parent 1:0 prio 2 u32 \
  match ip tos 0xb8 0xff \
  flowid 1:20

# HTTP/HTTPS normal
tc filter add dev $INTERFACE protocol ip parent 1:0 prio 3 u32 \
  match ip dport 80 0xffff \
  flowid 1:30

tc filter add dev $INTERFACE protocol ip parent 1:0 prio 3 u32 \
  match ip dport 443 0xffff \
  flowid 1:30

# Bulk - Marcado con DSCP CS1 (8)
tc filter add dev $INTERFACE protocol ip parent 1:0 prio 4 u32 \
  match ip tos 0x20 0xff \
  flowid 1:40

echo "QoS HTB configurado en $INTERFACE"
tc qdisc show dev $INTERFACE
tc class show dev $INTERFACE
```

**Verificar configuración:**

```bash

# Ver clases

# Ver filtros

# Estadísticas
```

### Ejemplo 4: Marcado DSCP con iptables + tc

```bash
#!/bin/bash
# qos_dscp.sh - Marcado y clasificación por DSCP

INTERFACE="eth0"

# 1. Marcar tráfico con iptables (mangle table)
iptables -t mangle -F  # Limpiar

# VoIP RTP → EF (DSCP 46)
iptables -t mangle -A POSTROUTING -o $INTERFACE \
  -p udp --dport 10000:20000 \
  -j DSCP --set-dscp 46

# VoIP SIP → CS5 (DSCP 40)
iptables -t mangle -A POSTROUTING -o $INTERFACE \
  -p udp --dport 5060:5061 \
  -j DSCP --set-dscp 40

# Video conferencia → AF41 (DSCP 34)
iptables -t mangle -A POSTROUTING -o $INTERFACE \
  -p tcp --dport 3478:3497 \
  -j DSCP --set-dscp 34

# Bulk/backup → CS1 (DSCP 8)
iptables -t mangle -A POSTROUTING -o $INTERFACE \
  -p tcp --dport 873 \
  -j DSCP --set-dscp 8

# 2. QoS basado en DSCP
tc qdisc del dev $INTERFACE root 2>/dev/null
tc qdisc add dev $INTERFACE root handle 1: htb default 40

tc class add dev $INTERFACE parent 1: classid 1:1 htb rate 100mbit

# EF (46) - VoIP
tc class add dev $INTERFACE parent 1:1 classid 1:10 htb \
  rate 5mbit ceil 10mbit prio 1

# CS5 (40) - Signaling
tc class add dev $INTERFACE parent 1:1 classid 1:20 htb \
  rate 2mbit ceil 5mbit prio 2

# AF41 (34) - Video
tc class add dev $INTERFACE parent 1:1 classid 1:30 htb \
  rate 30mbit ceil 50mbit prio 3

# Default
tc class add dev $INTERFACE parent 1:1 classid 1:40 htb \
  rate 63mbit ceil 100mbit prio 4

# Leaf qdiscs
tc qdisc add dev $INTERFACE parent 1:10 handle 10: sfq
tc qdisc add dev $INTERFACE parent 1:20 handle 20: sfq
tc qdisc add dev $INTERFACE parent 1:30 handle 30: sfq
tc qdisc add dev $INTERFACE parent 1:40 handle 40: fq_codel

# Filtros por DSCP
tc filter add dev $INTERFACE protocol ip parent 1:0 prio 1 u32 \
  match ip tos 0xb8 0xfc \
  flowid 1:10  # EF (46 << 2 = 184 = 0xb8)

tc filter add dev $INTERFACE protocol ip parent 1:0 prio 2 u32 \
  match ip tos 0xa0 0xfc \
  flowid 1:20  # CS5 (40 << 2 = 160 = 0xa0)

tc filter add dev $INTERFACE protocol ip parent 1:0 prio 3 u32 \
  match ip tos 0x88 0xfc \
  flowid 1:30  # AF41 (34 << 2 = 136 = 0x88)

echo "QoS DSCP-based configurado"
```

**Nota sobre DSCP en filtros tc:**
- DSCP está en los 6 bits más significativos del campo ToS
- Para filtrar, necesitas shift left por 2: `DSCP << 2`
- Máscara: `0xfc` (11111100 en binario)

### Ejemplo 5: fq_codel para Anti-Bufferbloat

```bash
# fq_codel: Fair Queue + Controlled Delay
# Reduce bufferbloat automáticamente

# Simple: Reemplazar qdisc por fq_codel
sudo tc qdisc replace dev eth0 root fq_codel

# Con parámetros personalizados
sudo tc qdisc replace dev eth0 root fq_codel \
  limit 10240 \
  flows 1024 \
  target 5ms \
  interval 100ms \
  quantum 1514 \
  ecn

# Parámetros:
# - limit: Máximo de paquetes en cola
# - flows: Número de flujos (colas internas)
# - target: Delay objetivo (5ms)
# - interval: Intervalo de medición
# - quantum: Bytes por dequeue
# - ecn: Habilitar ECN

# Ver estadísticas
tc -s qdisc show dev eth0
```

## QoS para VoIP

### Requisitos de VoIP

```
┌─────────────────────────────────────────────┐
│  REQUISITOS VOIP                            │
├─────────────────────────────────────────────┤
│                                             │
│  Latencia:       <150ms (preferible <100ms)│
│  Jitter:         <30ms                      │
│  Packet Loss:    <1% (preferible <0.5%)    │
│  Ancho de Banda: 64-128 Kbps por llamada   │
│                  (depende del codec)        │
│                                             │
│  Codecs comunes:                            │
│  ├─ G.711 (PCMU/PCMA): 64 Kbps, alta calidad│
│  ├─ G.729: 8 Kbps, calidad aceptable       │
│  ├─ Opus: 6-510 Kbps, adaptativo           │
│  └─ G.722: 64 Kbps, wideband (mejor)       │
│                                             │
└─────────────────────────────────────────────┘
```

### Componentes VoIP a Priorizar

```
1. Signaling (SIP, H.323, SCCP)
   ├─ Puertos: TCP/UDP 5060-5061 (SIP)
   ├─ DSCP: CS5 (40)
   └─ Prioridad: Alta (pero no la más alta)

2. RTP Media (voz actual)
   ├─ Puertos: UDP 10000-20000 (rango típico)
   ├─ DSCP: EF (46)
   └─ Prioridad: Máxima (strict priority)

3. RTCP (control RTP)
   ├─ Puertos: RTP port + 1
   ├─ DSCP: CS5 (40)
   └─ Prioridad: Alta
```

### Configuración VoIP Completa

```bash
#!/bin/bash
# voip_qos.sh - QoS optimizado para VoIP

INTERFACE="eth0"
TOTAL_BW="100mbit"
VOIP_BW="10mbit"      # 10 Mbps para VoIP (suficiente ~150 llamadas concurrentes)
VOIP_BURST="15k"       # Burst pequeño

# Limpiar
tc qdisc del dev $INTERFACE root 2>/dev/null

# 1. Marcado con iptables
iptables -t mangle -F OUTPUT
iptables -t mangle -F POSTROUTING

# RTP media → EF
iptables -t mangle -A OUTPUT -p udp -m multiport --dports 10000:20000 \
  -j DSCP --set-dscp-class ef

iptables -t mangle -A POSTROUTING -o $INTERFACE -p udp -m multiport --dports 10000:20000 \
  -j DSCP --set-dscp-class ef

# SIP signaling → CS5
iptables -t mangle -A OUTPUT -p udp -m multiport --dports 5060,5061 \
  -j DSCP --set-dscp-class cs5

iptables -t mangle -A POSTROUTING -o $INTERFACE -p udp -m multiport --dports 5060,5061 \
  -j DSCP --set-dscp-class cs5

# 2. HTB con Priority Queue para VoIP
tc qdisc add dev $INTERFACE root handle 1: htb default 30

# Clase raíz
tc class add dev $INTERFACE parent 1: classid 1:1 htb rate $TOTAL_BW

# VoIP RTP (EF) - Strict Priority con límite
tc class add dev $INTERFACE parent 1:1 classid 1:10 htb \
  rate $VOIP_BW ceil $VOIP_BW burst $VOIP_BURST prio 0

# Signaling (CS5)
tc class add dev $INTERFACE parent 1:1 classid 1:20 htb \
  rate 2mbit ceil 5mbit prio 1

# Otras aplicaciones
tc class add dev $INTERFACE parent 1:1 classid 1:30 htb \
  rate 88mbit ceil 100mbit prio 2

# Leaf qdiscs
# Para VoIP: PFIFO pequeño (baja latencia)
tc qdisc add dev $INTERFACE parent 1:10 handle 10: pfifo limit 5

# Para signaling: SFQ
tc qdisc add dev $INTERFACE parent 1:20 handle 20: sfq perturb 10

# Para el resto: fq_codel
tc qdisc add dev $INTERFACE parent 1:30 handle 30: fq_codel

# 3. Filtros por DSCP
# EF (46 << 2 = 184 = 0xb8)
tc filter add dev $INTERFACE protocol ip parent 1:0 prio 1 u32 \
  match ip tos 0xb8 0xfc \
  flowid 1:10

# CS5 (40 << 2 = 160 = 0xa0)
tc filter add dev $INTERFACE protocol ip parent 1:0 prio 2 u32 \
  match ip tos 0xa0 0xfc \
  flowid 1:20

echo "QoS VoIP configurado en $INTERFACE"
tc -s class show dev $INTERFACE
```

```bash
# Terminal 3: Monitorear estadísticas de clases

# Resultados esperados:
# - VoIP: jitter bajo (<30ms), 0% packet loss
# - Bulk: puede tener throughput reducido si hay congestión

```

### Troubleshooting Común

#### Problema 1: QoS No Funciona

```bash
# Verificar:
# 1. ¿Está configurado en interfaz correcta?
tc qdisc show dev eth0

# 2. ¿Filtros coinciden con tráfico?
tc -s filter show dev eth0

# 3. ¿Marcado DSCP aplicado?
sudo tcpdump -i eth0 -vv -c 10 udp port 5060

# 4. ¿iptables marca correctamente?
iptables -t mangle -L -v -n

# 5. ¿Hay congestión real? (QoS solo actúa en congestión)
tc -s class show dev eth0 | grep backlog
# Si backlog siempre 0, no hay congestión → QoS inactivo
```

#### Problema 2: Alta Latencia en VoIP Pesar de QoS

```bash
# Posibles causas:

# 1. VoIP no clasificado correctamente
# Verificar con tcpdump que tiene DSCP EF

# 2. Cola VoIP muy larga
# Reducir límite de cola:
tc qdisc replace dev eth0 parent 1:10 handle 10: pfifo limit 3

# 3. Shaping upstream (ISP)
# Configurar shaping ligeramente menor que capacidad real:
# Si ISP ofrece 100 Mbps, configurar 95 Mbps en tu router

# 4. Bufferbloat
# Usar fq_codel en clases no-VoIP
```

#### Problema 3: Starvation de Clases Bajas

```bash
# Si priority queue para VoIP consume todo el ancho de banda

# Solución: Limitar strict priority queue
tc class change dev eth0 parent 1:1 classid 1:10 htb \
  rate 5mbit ceil 5mbit  # Techo estricto, no puede exceder

# O usar LLQ (priority + policing)
```

### Script de Monitoring QoS

```bash
#!/bin/bash
# qos_monitor.sh - Exportar estadísticas QoS a Prometheus

INTERFACE="eth0"
TEXTFILE_DIR="/var/lib/node_exporter/textfile_collector"
OUTPUT_FILE="$TEXTFILE_DIR/qos_stats.prom"

# Función para obtener estadísticas
get_class_stats() {
    local interface=$1
    local classid=$2
    
    tc -s class show dev $interface | awk -v classid="$classid" '
    $0 ~ classid {
        getline; getline
        if (match($0, /Sent ([0-9]+) bytes ([0-9]+) pkt.*dropped ([0-9]+)/, arr)) {
            print "tc_class_bytes{interface=\"'$interface'\",classid=\"'$classid'\"} " arr[1]
            print "tc_class_packets{interface=\"'$interface'\",classid=\"'$classid'\"} " arr[2]
            print "tc_class_dropped{interface=\"'$interface'\",classid=\"'$classid'\"} " arr[3]
        }
    }'
}

# Limpiar archivo
> $OUTPUT_FILE

# Exportar estadísticas por clase
get_class_stats $INTERFACE "1:10" >> $OUTPUT_FILE  # VoIP
get_class_stats $INTERFACE "1:20" >> $OUTPUT_FILE  # Video
get_class_stats $INTERFACE "1:30" >> $OUTPUT_FILE  # Data
get_class_stats $INTERFACE "1:40" >> $OUTPUT_FILE  # Bulk

# Agregar timestamp
echo "# HELP qos_scrape_timestamp Unix timestamp of last scrape" >> $OUTPUT_FILE
echo "# TYPE qos_scrape_timestamp gauge" >> $OUTPUT_FILE
echo "qos_scrape_timestamp $(date +%s)" >> $OUTPUT_FILE

# Ejecutar cada 15 segundos con cron
# */15 * * * * /usr/local/bin/qos_monitor.sh
```

## Mejores Prácticas

### 1. Clasificación y Marcado

```
✅ DO:
- Marcar tráfico lo más cerca de la fuente posible
- Usar valores DSCP estándar (EF, AF4x, etc.)
- Re-marcar en trust boundary (borde de red)
- Validar marcado con tcpdump/Wireshark

❌ DON'T:
- Confiar en marcado de usuarios finales
- Inventar valores DSCP no estándar
- Sobre-priorizar demasiadas aplicaciones
- Olvidar documentar clases configuradas
```

### 2. Asignación de Ancho de Banda

```
Regla 80/20:
- 20% del ancho de banda para tráfico crítico/garantizado
- 80% flexible para uso oportunista

Ejemplo 100 Mbps:
├─ VoIP (EF):          10 Mbps garantizados (10%)
├─ Video (AF41):       20 Mbps garantizados (20%)
├─ Critical Data:      10 Mbps garantizados (10%)
└─ Default/Best Effort: 60 Mbps (resto)

Total garantizado: 40 Mbps (40%)
Headroom: 60 Mbps para bursts y excess traffic
```

### 3. Configuración de Colas

```
VoIP:
✅ Priority queue con policing estricto
✅ Cola pequeña (3-5 paquetes)
✅ DSCP EF

Video Conferencia:
✅ CBWFQ con garantía
✅ Cola moderada (SFQ o fq_codel)
✅ DSCP AF41

Video Streaming:
✅ CBWFQ con menos prioridad que conferencia
✅ Buffer grande OK (pre-buffering)
✅ DSCP AF31

Bulk/Backup:
✅ Scavenger class (menos que best effort)
✅ fq_codel para fairness
✅ DSCP CS1
```
