## Introducción a los Analizadores de Protocolos

### ¿Qué son los Analizadores de Protocolos?

Los **analizadores de protocolos** son herramientas esenciales para la administración de redes que permiten:

- **Capturar tráfico de red** a nivel de paquetes
- **Decodificar protocolos** de las capas OSI/TCP-IP
- **Diagnosticar problemas** de conectividad y rendimiento
- **Detectar anomalías** y posibles ataques
- **Validar configuraciones** de servicios y aplicaciones
- **Optimizar el desempeño** mediante análisis detallado

### Tipos de Analizadores

#### 1. **Packet Sniffers (Capturadores)**
Interceptan y registran el tráfico de red en tiempo real:
- **Wireshark**: Analizador gráfico multiplataforma
- **tcpdump**: Herramienta CLI clásica de Unix/Linux
- **tshark**: Versión CLI de Wireshark

#### 2. **Network Scanners (Escaneadores)**
Descubren hosts, servicios y vulnerabilidades:
- **Nmap**: Mapeador y escaneador de puertos
- **Masscan**: Escaneador de puertos de alta velocidad
- **Angry IP Scanner**: Escaneador GUI simple

#### 3. **Protocol Analyzers (Analizadores Especializados)**
Herramientas específicas para protocolos:
- **Netcat**: Manipulación de conexiones TCP/UDP
- **hping3**: Crafteo y análisis de paquetes
- **Scapy**: Librería Python para manipulación de paquetes

### Niveles de Captura

```
┌─────────────────────────────────────────────────────────┐
│              ANÁLISIS POR CAPAS OSI/TCP-IP              │
├─────────────────────────────────────────────────────────┤
│ Aplicación  │ HTTP, DNS, SMTP, SSH, FTP, etc.          │
│             │ → Decodificación de payload              │
├─────────────────────────────────────────────────────────┤
│ Transporte  │ TCP, UDP, SCTP                           │
│             │ → Puertos, flags, secuencias             │
├─────────────────────────────────────────────────────────┤
│ Red         │ IP, ICMP, ARP, OSPF, BGP                 │
│             │ → Direcciones, routing, fragmentación    │
├─────────────────────────────────────────────────────────┤
│ Enlace      │ Ethernet, WiFi (802.11), PPP             │
│             │ → MAC addresses, VLANs, frames           │
├─────────────────────────────────────────────────────────┤
│ Física      │ Señales eléctricas/ópticas               │
│             │ → Captura a nivel de bits                │
└─────────────────────────────────────────────────────────┘
```

### Casos de Uso Comunes

| Escenario | Herramienta Recomendada | Objetivo |
|-----------|-------------------------|----------|
| Troubleshooting conectividad | Wireshark + ping/traceroute | Identificar pérdida de paquetes |
| Análisis de rendimiento web | Wireshark filtro HTTP | Medir tiempos de respuesta |
| Detección de escaneo de puertos | tcpdump + fail2ban | Identificar intentos de intrusión |
| Auditoría de seguridad | Nmap + Wireshark | Descubrir servicios expuestos |
| Debugging de aplicación | tshark con filtros específicos | Capturar tráfico de API |
| Inventario de red | Nmap -sn scan | Descubrir hosts activos |
| Análisis de malware | Wireshark + sandbox | Estudiar comunicaciones C&C |
| Validación de QoS | Wireshark (campo DSCP) | Verificar marcado de tráfico |

## Packet Sniffers - Captura de Paquetes

### Fundamentos de Packet Sniffing

#### Modos de Captura

**1. Modo Promiscuo**
- Captura **todo el tráfico** que pasa por la interfaz de red
- Requiere permisos de administrador (root/sudo)
- Útil en switches con port mirroring (SPAN)

**2. Modo Normal**
- Captura solo tráfico destinado a la interfaz local
- Incluye broadcasts y multicasts
- Suficiente para análisis básico

#### Cómo Funciona la Captura

```
┌──────────────────────────────────────────────────────────┐
│                 FLUJO DE CAPTURA DE PAQUETES             │
└──────────────────────────────────────────────────────────┘

1. Paquetes → NIC (Network Interface Card)
              ↓
2. Driver de red → Buffer del kernel
              ↓
3. Libpcap/WinPcap → Capa de captura
              ↓
4. Filtro BPF (Berkeley Packet Filter)
              ↓
5. Aplicación (Wireshark/tcpdump/tshark)
              ↓
6. Decodificación → Análisis → Almacenamiento (PCAP)
```

### Formato PCAP (Packet Capture)

Los archivos `.pcap` son el estándar para almacenar capturas:

**Estructura de un archivo PCAP:**
```
┌─────────────────────────────┐
│  PCAP Global Header (24B)   │  ← Metadatos del archivo
├─────────────────────────────┤
│  Packet Header (16B)        │  ← Timestamp, longitud
│  Packet Data (variable)     │  ← Frame completo
├─────────────────────────────┤
│  Packet Header              │
│  Packet Data                │
├─────────────────────────────┤
│         ...                 │
└─────────────────────────────┘
```

### Berkeley Packet Filter (BPF)

Lenguaje de filtrado eficiente a nivel de kernel:

**Sintaxis básica:**
```bash
# Filtrar por protocolo
icmp
tcp
udp
arp

# Filtrar por host
host 192.168.1.100
src host 10.0.0.5
dst host 8.8.8.8

# Filtrar por puerto
port 80
src port 443
dst port 22

# Filtrar por red
net 192.168.0.0/24
net 10.0.0.0 mask 255.255.255.0

# Combinaciones lógicas
tcp and port 80
host 192.168.1.1 or host 192.168.1.2
not port 53
```

**Ejemplos complejos:**
```bash
# Capturar solo SYN packets (inicio de conexión TCP)
tcp[tcpflags] & tcp-syn != 0

# Paquetes mayores a 1000 bytes
greater 1000

# Tráfico HTTP (puerto 80 o 8080)
tcp port 80 or tcp port 8080

# Todo excepto SSH y DNS
not (port 22 or port 53)

# Broadcast y multicast
ether broadcast or ether multicast
```

## Wireshark - Análisis Gráfico

### Introducción a Wireshark

**Wireshark** es el analizador de protocolos de red más popular del mundo:
- **Open Source** (GPLv2)
- **Multiplataforma** (Linux, Windows, macOS)
- **Soporta 2000+ protocolos**
- **Interfaz gráfica intuitiva**
- **Análisis en tiempo real y offline**

### Instalación

```bash
# Debian/Ubuntu
sudo apt update
sudo apt install wireshark

# Durante instalación, permitir que usuarios no-root capturen paquetes
sudo dpkg-reconfigure wireshark-common
# Seleccionar "Yes"

# Agregar usuario al grupo wireshark
sudo usermod -aG wireshark $USER

# Re-loguear o ejecutar
newgrp wireshark

# Fedora/RHEL/Rocky Linux
sudo dnf install wireshark

# Arch Linux
sudo pacman -S wireshark-qt
```

### Captura de Tráfico

#### Inicio de Captura

```
1. Capture → Options (o Ctrl+K)
2. Seleccionar interfaz (eth0, wlan0, etc.)
3. Configurar opciones:
   - Capture Filter (BPF): port 80 or port 443
   - Enable promiscuous mode
   - Buffer size (MB)
4. Start
```

#### Opciones de Captura Importantes

| Opción | Descripción | Uso |
|--------|-------------|-----|
| **Promiscuous Mode** | Captura todo el tráfico del segmento | Análisis completo de red |
| **Capture Filter** | Filtro BPF aplicado durante captura | Reducir tamaño de archivo |
| **Ring Buffer** | Archivos rotativos con límite de tamaño | Capturas de larga duración |
| **Stop Condition** | Detener tras N paquetes/MB/segundos | Automatización |
| **Name Resolution** | Resolver nombres DNS/puertos | Lectura más fácil (⚠️ ralentiza) |

### Display Filters (Filtros de Visualización)

Más potentes que BPF, se aplican **después de la captura**:

#### Filtros por Protocolo

```
# Protocolos comunes
http
https
dns
ssh
ftp
smtp
icmp
arp

# Específico de HTTP
http.request
http.response
http.request.method == "GET"
http.request.uri contains "login"
http.response.code == 404
```

#### Filtros por Direcciones IP

```
# Por IP
ip.addr == 192.168.1.100
ip.src == 10.0.0.5
ip.dst == 8.8.8.8

# Rangos de IP
ip.addr == 192.168.1.0/24
ip.src == 10.0.0.0/8

# Excluir IPs
!(ip.addr == 192.168.1.1)
```

#### Filtros por Puertos

```
# Puerto TCP/UDP
tcp.port == 80
udp.port == 53
tcp.dstport == 443
tcp.srcport == 22

# Rangos de puertos
tcp.port >= 1024 and tcp.port <= 65535
```

#### Filtros por Flags TCP

```
# Flags TCP específicos
tcp.flags.syn == 1
tcp.flags.ack == 1
tcp.flags.rst == 1
tcp.flags.fin == 1

# Combinaciones (SYN+ACK)
tcp.flags == 0x012

# Solo SYN (inicio de conexión)
tcp.flags.syn == 1 and tcp.flags.ack == 0
```

#### Filtros Avanzados

```
# Contiene texto específico
tcp contains "password"
http.request.uri contains "admin"
dns.qry.name contains "malware"

# Coincide con regex
http.host matches ".*\\.ru$"

# Longitud de paquetes
frame.len > 1000
ip.len < 100

# Tiempo entre paquetes
frame.time_delta > 0.5

# Seguir stream TCP
tcp.stream eq 42

# Errores y retransmisiones
tcp.analysis.retransmission
tcp.analysis.duplicate_ack
icmp.type == 3 (Destination Unreachable)
```

#### Operadores Lógicos

```
# AND
tcp.port == 80 and ip.addr == 192.168.1.1

# OR
tcp.port == 80 or tcp.port == 443

# NOT
not arp
!(tcp.port == 22)

# Combinaciones
(http or https) and ip.addr == 10.0.0.0/8
```

### Análisis de Performance

#### Identificar Problemas de Rendimiento

**1. Retransmisiones TCP**
```
Display Filter: tcp.analysis.retransmission

Indica:
- Pérdida de paquetes
- Problemas de congestión
- Enlaces saturados
```

**2. Duplicate ACKs**
```
Display Filter: tcp.analysis.duplicate_ack

Precursor de retransmisiones
Sugiere pérdida selectiva de paquetes
```

**3. Window Full**
```
Display Filter: tcp.analysis.window_full

Receptor no puede procesar datos lo suficientemente rápido
Revisar capacidad de procesamiento del servidor
```

**4. Out of Order**
```
Display Filter: tcp.analysis.out_of_order

Paquetes llegando desordenados
Problemas de routing o load balancing asimétrico
```

#### Round Trip Time (RTT)

```
Statistics → TCP Stream Graphs → Round Trip Time

Mide latencia entre cliente y servidor
RTT elevado indica:
- Distancia geográfica
- Congestión de red
- Equipos intermedios lentos
```

### Casos de Uso con Wireshark

#### Caso 1: Troubleshooting Lentitud Web

**Síntoma**: Sitio web carga lento

**Pasos de diagnóstico:**
```
1. Iniciar captura en interfaz del servidor web
2. Filtro: http.host == "www.example.com"
3. Analizar:
   - Statistics → HTTP → Load Distribution
   - Identificar recursos lentos
   - Buscar http.response.code == 500 (errores servidor)
   - Verificar tcp.analysis.retransmission

4. Follow HTTP Stream para ver headers completos
5. I/O Graph para visualizar picos de tráfico
```

#### Caso 2: Detección de Escaneo de Puertos

**Síntoma**: Alertas de firewall

**Filtro para detectar:**
```
# SYN scan (conexiones no completadas)
tcp.flags.syn == 1 and tcp.flags.ack == 0

# Múltiples puertos desde mismo origen
Statistics → Conversations → TCP
Ordenar por "Address A", buscar muchos puertos distintos
```

#### Caso 3: Debugging de DNS

**Síntoma**: Resolución DNS lenta

**Análisis:**
```
Display Filter: dns

Buscar:
- dns.flags.rcode != 0 (errores DNS)
- dns.qry.name (queries realizadas)
- frame.time_delta > 1 (respuestas lentas)

Statistics → DNS
Ver queries más frecuentes
```

## tcpdump - Captura en CLI

### Introducción a tcpdump

**tcpdump** es la herramienta de línea de comandos clásica para captura de paquetes:
- **Disponible en prácticamente todos los sistemas Unix/Linux**
- **Ligera y eficiente** (ideal para servidores sin GUI)
- **Usa libpcap** (misma librería que Wireshark)
- **Filtros BPF** para captura selectiva
- **Formato PCAP** estándar

### Instalación

```bash
# Debian/Ubuntu
sudo apt install tcpdump

# Fedora/RHEL/Rocky Linux
sudo dnf install tcpdump

# Arch Linux
sudo pacman -S tcpdump

# Verificar instalación
tcpdump --version
```

### Sintaxis Básica

```bash
tcpdump [opciones] [filtro BPF]

# Estructura general
sudo tcpdump -i <interfaz> -n -c <count> <filtro>
```

### Opciones Principales

| Opción | Descripción | Ejemplo |
|--------|-------------|---------|
| `-i <interfaz>` | Interfaz a capturar | `-i eth0`, `-i any` |
| `-n` | No resolver nombres | Más rápido |
| `-nn` | No resolver nombres ni puertos | Ver números exactos |
| `-c <count>` | Capturar N paquetes y salir | `-c 100` |
| `-w <archivo>` | Escribir a archivo PCAP | `-w captura.pcap` |
| `-r <archivo>` | Leer desde archivo PCAP | `-r captura.pcap` |
| `-v, -vv, -vvv` | Verbosidad (más detalles) | `-vvv` |
| `-A` | Imprimir payload ASCII | Ver contenido |
| `-X` | Imprimir payload hex+ASCII | Análisis detallado |
| `-s <snaplen>` | Bytes a capturar por paquete | `-s 0` (completo) |
| `-q` | Salida breve | Menos información |
| `-t` | No imprimir timestamp | Salida limpia |
| `-tttt` | Timestamp legible | Fecha y hora completa |
| `-C <MB>` | Rotar archivo cada N MB | `-C 100` |
| `-G <segundos>` | Rotar archivo cada N segundos | `-G 3600` |

### Ejemplos Básicos

#### Captura Simple

```bash
# Ver todo el tráfico en interfaz eth0
sudo tcpdump -i eth0

# Capturar primeros 50 paquetes
sudo tcpdump -i eth0 -c 50

# Capturar en cualquier interfaz
sudo tcpdump -i any

# Sin resolución DNS (más rápido)
sudo tcpdump -i eth0 -n
```

#### Guardar a Archivo

```bash
# Capturar y guardar
sudo tcpdump -i eth0 -w captura.pcap

# Capturar con límite
sudo tcpdump -i eth0 -c 1000 -w captura.pcap

# Capturar paquetes completos (no truncar)
sudo tcpdump -i eth0 -s 0 -w captura.pcap

# Leer archivo capturado
tcpdump -r captura.pcap

# Leer con filtro
tcpdump -r captura.pcap 'port 80'
```

#### Archivos Rotativos

```bash
# Rotar cada 100 MB, mantener máximo 5 archivos
sudo tcpdump -i eth0 -w /var/log/captures/cap.pcap \
  -C 100 -W 5

# Rotar cada hora (3600 segundos)
sudo tcpdump -i eth0 -w /var/log/captures/cap_%Y%m%d_%H%M%S.pcap \
  -G 3600
```

### Filtros BPF Comunes

#### Por Protocolo

```bash
# ICMP (ping)
sudo tcpdump -i eth0 icmp

# TCP
sudo tcpdump -i eth0 tcp

# UDP
sudo tcpdump -i eth0 udp

# ARP
sudo tcpdump -i eth0 arp
```

#### Por Host

```bash
# Tráfico de/hacia host específico
sudo tcpdump -i eth0 host 192.168.1.100

# Solo tráfico originado desde host
sudo tcpdump -i eth0 src host 10.0.0.5

# Solo tráfico destinado a host
sudo tcpdump -i eth0 dst host 8.8.8.8

# Múltiples hosts
sudo tcpdump -i eth0 'host 192.168.1.1 or host 192.168.1.2'
```

#### Por Puerto

```bash
# Tráfico HTTP
sudo tcpdump -i eth0 port 80

# Tráfico HTTPS
sudo tcpdump -i eth0 port 443

# Tráfico SSH
sudo tcpdump -i eth0 port 22

# Puerto origen
sudo tcpdump -i eth0 src port 53

# Puerto destino
sudo tcpdump -i eth0 dst port 3306

# Rango de puertos
sudo tcpdump -i eth0 portrange 1024-65535
```

#### Por Red

```bash
# Todo el tráfico de subred
sudo tcpdump -i eth0 net 192.168.1.0/24

# Formato alternativo
sudo tcpdump -i eth0 net 192.168.1.0 mask 255.255.255.0

# Origen en red específica
sudo tcpdump -i eth0 src net 10.0.0.0/8
```

#### Filtros Combinados

```bash
# HTTP desde IP específica
sudo tcpdump -i eth0 'host 192.168.1.100 and port 80'

# Todo excepto SSH
sudo tcpdump -i eth0 'not port 22'

# HTTP o HTTPS
```

## tshark - Wireshark en Terminal

### Introducción a tshark

**tshark** es la versión CLI de Wireshark:
- **Mismos dissectors** que Wireshark (2000+ protocolos)
- **Display filters** de Wireshark (más potentes que BPF)
- **Análisis estadístico** desde terminal
- **Ideal para automatización** con scripts
- **Procesamiento de archivos PCAP** sin GUI

### Instalación

```bash
# Se instala junto con Wireshark
sudo apt install tshark

# O específicamente
sudo apt install tshark

# Permitir captura a usuarios no-root
sudo dpkg-reconfigure wireshark-common
sudo usermod -aG wireshark $USER
```

### Sintaxis Básica

```bash
tshark [opciones] [filtros]

# Estructura
tshark -i <interfaz> -Y '<display filter>' -w archivo.pcap
```

### Opciones Principales

| Opción | Descripción | Equivalente Wireshark |
|--------|-------------|-----------------------|
| `-i <interfaz>` | Interfaz de captura | Capture → Interfaces |
| `-w <archivo>` | Escribir a archivo | File → Save As |
| `-r <archivo>` | Leer archivo | File → Open |
| `-Y <filtro>` | Display filter | Barra de filtro |
| `-f <filtro>` | Capture filter (BPF) | Capture Filter |
| `-c <count>` | Número de paquetes | Stop Conditions |
| `-a duration:X` | Capturar X segundos | Stop Conditions |
| `-V` | Detalles completos | Packet Details panel |
| `-T fields -e <campo>` | Extraer campos específicos | Custom columns |
| `-z <estadística>` | Generar estadísticas | Statistics menu |
| `-q` | Modo silencioso (solo estadísticas) | - |
| `-x` | Mostrar hex dump | Packet Bytes panel |

### Ejemplos Básicos

```bash

# Capturar y guardar
sudo tshark -i eth0 -w captura.pcap

# Leer archivo

# Aplicar display filter
tshark -r captura.pcap -Y 'http.request.method == "GET"'
```

### Display Filters (como Wireshark)

```bash

# Filtro por IP

# Filtro por puerto TCP
tshark -r captura.pcap -Y 'tcp.port == 443'

# Filtros complejos
tshark -r captura.pcap -Y 'http.request and ip.src == 10.0.0.5'

# Buscar texto en payload
tshark -r captura.pcap -Y 'tcp contains "password"'
```

### Extracción de Campos Específicos

Uno de los poderes de tshark: extraer campos concretos.

```bash
# Sintaxis
tshark -r captura.pcap -T fields -e <campo1> -e <campo2>

# Ejemplo: Extraer IP origen y destino
tshark -r captura.pcap -T fields -e ip.src -e ip.dst

# Ejemplo: Extraer URLs HTTP

# Ejemplo: Extraer User-Agents

# Ejemplo: DNS queries

```

#### Campos Útiles por Protocolo

**General:**
- `frame.number` - Número de paquete
- `frame.time` - Timestamp
- `frame.len` - Longitud del frame

**IP:**
- `ip.src` - IP origen
- `ip.dst` - IP destino
- `ip.proto` - Protocolo (6=TCP, 17=UDP)
- `ip.ttl` - Time to Live

**TCP:**
- `tcp.srcport` - Puerto origen
- `tcp.dstport` - Puerto destino
- `tcp.flags` - Flags TCP
- `tcp.stream` - ID de stream
- `tcp.len` - Longitud de datos TCP

**HTTP:**
- `http.host` - Host header
- `http.request.method` - GET, POST, etc.
- `http.request.uri` - URL solicitada
- `http.response.code` - 200, 404, 500, etc.
- `http.user_agent` - User-Agent header
- `http.cookie` - Cookies

**DNS:**
- `dns.qry.name` - Nombre consultado
- `dns.a` - Respuesta A (IPv4)
- `dns.aaaa` - Respuesta AAAA (IPv6)
- `dns.flags.response` - 0=query, 1=response

## Network Scanners - Escaneo de Red

### Introducción a los Scanners

Los **network scanners** son herramientas que descubren y mapean redes:

**Usos legítimos:**
- Inventario de activos de red
- Auditorías de seguridad autorizadas
- Validación de configuraciones de firewall
- Descubrimiento de servicios para administración

**⚠️ ADVERTENCIA LEGAL**: El escaneo no autorizado de redes ajenas es **ilegal** en la mayoría de jurisdicciones. Solo escanear redes propias o con autorización explícita.

### Tipos de Escaneo

#### 1. **Host Discovery (Descubrimiento de Hosts)**
Determinar qué dispositivos están activos en la red.

#### 2. **Port Scanning (Escaneo de Puertos)**
Identificar puertos abiertos, cerrados o filtrados.

#### 3. **Service Detection (Detección de Servicios)**
Determinar qué aplicación escucha en cada puerto.

#### 4. **OS Detection (Detección de Sistema Operativo)**
Fingerprinting del sistema operativo basado en respuestas.

#### 5. **Vulnerability Scanning (Escaneo de Vulnerabilidades)**
Identificar versiones vulnerables de servicios.

### Estados de Puertos

```
┌──────────┬──────────────────────────────────────────────────┐
│  Estado  │  Descripción                                     │
├──────────┼──────────────────────────────────────────────────┤
│  Open    │ Aplicación escuchando activamente               │
│          │ → SYN recibe SYN-ACK                            │
├──────────┼──────────────────────────────────────────────────┤
│  Closed  │ Puerto accesible, pero ninguna aplicación       │
│          │ → SYN recibe RST                                │
├──────────┼──────────────────────────────────────────────────┤
│ Filtered │ Firewall bloqueando, no hay respuesta           │
│          │ → SYN no recibe nada (timeout)                  │
├──────────┼──────────────────────────────────────────────────┤
│ Unfiltered│ Puerto accesible, estado indeterminado         │
│          │ → ACK scan recibe RST                           │
├──────────┼──────────────────────────────────────────────────┤
│ Open|Filtered│ No se puede determinar (UDP, FIN scan)     │
└──────────┴──────────────────────────────────────────────────┘
```

## Nmap - Network Mapper

### Introducción a Nmap

**Nmap** ("Network Mapper") es el escaner de red más popular:
- **Open Source** (GPLv2)
- **Multiplataforma** (Linux, Windows, macOS)
- **Extremadamente flexible** (docenas de técnicas de escaneo)
- **Scripting Engine** (NSE) con 600+ scripts
- **Detección de SO y servicios**
- **Evasión de firewalls/IDS**

**Creador**: Gordon Lyon (Fyodor)  
**Primera versión**: 1997  
**Uso famoso**: Aparece en múltiples películas (Matrix Reloaded, The Bourne Ultimatum, etc.)

### Instalación

```bash
# Debian/Ubuntu
sudo apt update
sudo apt install nmap

# Fedora/RHEL/Rocky Linux
sudo dnf install nmap

# Arch Linux
sudo pacman -S nmap

# Verificar instalación
nmap --version
```

### Sintaxis Básica

```bash
nmap [Tipo de Escaneo] [Opciones] {objetivo}

# Ejemplos
nmap 192.168.1.1
nmap 192.168.1.0/24
nmap scanme.nmap.org
```

### Host Discovery (Descubrimiento)

#### Ping Scan (Descubrir hosts activos)

```bash
# Ping scan (sin escanear puertos)
nmap -sn 192.168.1.0/24

# -sn: "No port scan"
# También llamado "ping sweep"

# Salida ejemplo:
# Nmap scan report for 192.168.1.1
# Host is up (0.0012s latency).
# Nmap scan report for 192.168.1.100
# Host is up (0.0034s latency).
# Nmap done: 256 IP addresses (2 hosts up) scanned in 2.45 seconds
```

#### Técnicas de Host Discovery

```bash
# ICMP echo request (ping tradicional)
nmap -PE 192.168.1.0/24

# ICMP timestamp request
nmap -PP 192.168.1.0/24

# TCP SYN a puerto 80
nmap -PS80 192.168.1.0/24

# TCP ACK a puerto 80
nmap -PA80 192.168.1.0/24

# UDP a puerto 53
nmap -PU53 192.168.1.0/24

# ARP ping (red local, muy efectivo)
nmap -PR 192.168.1.0/24

# No hacer ping (asumir host up)
nmap -Pn 192.168.1.100
```

### Port Scanning (Escaneo de Puertos)

#### TCP Connect Scan

```bash
# TCP connect() completo (no requiere root)
nmap -sT 192.168.1.100

# Proceso:
# 1. SYN →
# 2. ← SYN-ACK (puerto abierto) / RST (puerto cerrado)
# 3. ACK →
# 4. Cerrar conexión
```

#### TCP SYN Scan (Stealth Scan)

```bash
# Half-open scan (requiere root)
sudo nmap -sS 192.168.1.100

# Proceso:
# 1. SYN →
# 2. ← SYN-ACK (abierto) / RST (cerrado)
# 3. RST → (no completa handshake)

# Ventajas:
# - Más rápido que -sT
# - Menos detectable (no completa conexión)
# - Menos logs en servidores antiguos
```

#### UDP Scan

```bash
# Escaneo UDP (muy lento)
sudo nmap -sU 192.168.1.100

# Proceso:
# 1. UDP packet →
# 2. ← UDP response (abierto) / ICMP unreachable (cerrado) / nada (filtrado)

# Común para:
# - DNS (53)
# - SNMP (161)
# - DHCP (67, 68)
```

#### Otros Tipos de Escaneo

```bash
# TCP ACK scan (detectar firewalls)
sudo nmap -sA 192.168.1.100

# TCP Window scan
sudo nmap -sW 192.168.1.100

# TCP FIN scan (evadir algunos firewalls)
sudo nmap -sF 192.168.1.100

# TCP Xmas scan (FIN, PSH, URG flags)
sudo nmap -sX 192.168.1.100

# TCP Null scan (sin flags)
sudo nmap -sN 192.168.1.100
```

### Especificación de Puertos

```bash
# Puerto específico
nmap -p 80 192.168.1.100

# Múltiples puertos
nmap -p 22,80,443 192.168.1.100

# Rango de puertos
nmap -p 1-1000 192.168.1.100

# Todos los puertos (1-65535)
nmap -p- 192.168.1.100

# Top 100 puertos más comunes (por defecto)
nmap 192.168.1.100

# Top 1000 puertos
nmap --top-ports 1000 192.168.1.100

# Puertos UDP
sudo nmap -sU -p 53,161,514 192.168.1.100

# Combinación TCP + UDP
sudo nmap -sS -sU -p T:80,443,U:53,161 192.168.1.100
```

### Service and Version Detection

```bash
# Detectar versiones de servicios
nmap -sV 192.168.1.100

# Salida ejemplo:
# PORT    STATE SERVICE  VERSION
# 22/tcp  open  ssh      OpenSSH 8.2p1 Ubuntu 4ubuntu0.5
# 80/tcp  open  http     Apache httpd 2.4.41
# 443/tcp open  ssl/http Apache httpd 2.4.41

# Intensidad de detección (0-9)
nmap -sV --version-intensity 5 192.168.1.100

# Nivel 0: Más rápido, menos preciso
# Nivel 9: Más lento, más preciso (defecto: 7)
```

### OS Detection

```bash
# Detectar sistema operativo
sudo nmap -O 192.168.1.100

# Salida ejemplo:
# Running: Linux 5.X
# OS CPE: cpe:/o:linux:linux_kernel:5
# OS details: Linux 5.4 - 5.10

# OS detection + Version detection
sudo nmap -A 192.168.1.100

# -A incluye:
# - OS detection (-O)
# - Version detection (-sV)
# - Script scanning (-sC)
# - Traceroute (--traceroute)
```

### Nmap Scripting Engine (NSE)

Nmap incluye **600+ scripts** para tareas especializadas.

#### Categorías de Scripts

```bash
# Listar scripts disponibles
ls /usr/share/nmap/scripts/

# Categorías:
# - auth: Autenticación (brute force, bypass)
# - broadcast: Descubrimiento por broadcast
# - brute: Ataques de fuerza bruta
# - default: Scripts del escaneo -sC
# - discovery: Descubrimiento avanzado
# - dos: Pruebas de denegación de servicio
# - exploit: Exploits (¡usar con cuidado!)
# - external: Consultas a servicios externos
# - fuzzer: Fuzzing de protocolos
# - intrusive: Pueden afectar al objetivo
# - malware: Detección de malware
```


### Timing and Performance

Nmap permite ajustar velocidad vs sigilo.

```bash

# - T4: Redes locales, auditorías autorizadas
```


#### Script Python

```python
#!/usr/bin/env python3
from scapy.all import *

# Port scanner simple
def scan_port(ip, port):
    pkt = IP(dst=ip)/TCP(dport=port, flags="S")
    resp = sr1(pkt, timeout=1, verbose=0)
    
    if resp is None:
        return "Filtered"
    elif resp.haslayer(TCP):
        if resp.getlayer(TCP).flags == 0x12:  # SYN-ACK
            return "Open"
        elif resp.getlayer(TCP).flags == 0x14:  # RST-ACK
            return "Closed"
    return "Unknown"

# Escanear puertos comunes
target = "192.168.1.100"
ports = [22, 80, 443, 3306, 8080]

for port in ports:
    result = scan_port(target, port)
    print(f"Port {port}: {result}")
```

## Casos de Uso y Troubleshooting

### Caso 1: Conexión de Aplicación Falla

**Síntoma**: Aplicación no puede conectar al servidor.

**Diagnóstico con analizadores:**

```bash
# Paso 1: Verificar conectividad básica
ping 192.168.1.100

# Paso 2: Verificar puerto abierto
nmap -p 3306 192.168.1.100

# Paso 3: Capturar tráfico durante intento de conexión
sudo tcpdump -i eth0 -nn host 192.168.1.100 and port 3306 -w debug.pcap

# Paso 4: Analizar en Wireshark
wireshark debug.pcap

# Buscar:
# - SYN sin SYN-ACK → Puerto cerrado o firewall bloqueando
# - SYN-ACK sin ACK → Problema en cliente
# - Conexión establecida pero luego RST → Error de aplicación
# - ICMP unreachable → Problema de routing
```

### Caso 2: Red Lenta - Análisis de Performance

**Síntoma**: Usuarios reportan lentitud.

**Diagnóstico:**

```bash
# 1. Capturar tráfico representativo
sudo tcpdump -i eth0 -s 0 -w traffic.pcap -G 300 -C 100 -W 5
# Captura 5 archivos de 100MB, rotan cada 5 minutos

# 2. Analizar con tshark
# Retransmisiones TCP (indican pérdida de paquetes)
tshark -r traffic.pcap0 -Y 'tcp.analysis.retransmission' | wc -l

# Duplicate ACKs
tshark -r traffic.pcap0 -Y 'tcp.analysis.duplicate_ack' | wc -l

# 3. Top talkers (hosts que más tráfico generan)
tshark -r traffic.pcap0 -q -z endpoints,ip | sort -k3 -rn | head -10

# 4. Protocolos más usados
tshark -r traffic.pcap0 -q -z io,phs

# 5. Análisis en Wireshark
wireshark traffic.pcap0

# Statistics → I/O Graphs
# Buscar picos de tráfico
# Correlacionar con reportes de lentitud
```

### Caso 3: Detección de Escaneo de Puertos

**Síntoma**: IDS alerta de escaneo.

**Análisis:**

```bash
# Capturar durante escaneo sospechoso
sudo tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0' -w scan_detection.pcap

# Analizar con tshark
# IPs que inician más conexiones SYN
tshark -r scan_detection.pcap -Y 'tcp.flags.syn==1 and tcp.flags.ack==0' \
  -T fields -e ip.src | sort | uniq -c | sort -rn | head -10

# Si una IP tiene cientos de SYN a múltiples puertos → escaneo

# Ver puertos escaneados
tshark -r scan_detection.pcap -Y 'tcp.flags.syn==1 and tcp.flags.ack==0' \
  -T fields -e tcp.dstport | sort -u

# Patrón secuencial (1,2,3,...) o aleatorio?
```

### Caso 4: Debugging de DNS

**Síntoma**: Resolución DNS intermitente.

**Diagnóstico:**

```bash
# Capturar queries DNS
sudo tcpdump -i eth0 port 53 -w dns_debug.pcap

# Analizar tiempos de respuesta
tshark -r dns_debug.pcap -Y dns -T fields \
  -e frame.number -e frame.time_delta_displayed -e dns.qry.name -e dns.flags.response

# Buscar:
# - Queries sin response (timeout)
# - Tiempos altos (>500ms)
# - NXDOMAIN (dominio no existe)
# - SERVFAIL (error de servidor DNS)

# Estadísticas DNS con tshark
tshark -r dns_debug.pcap -q -z dns,tree
```

### Caso 5: Análisis de Ataque DDoS

**Síntoma**: Servidor inaccesible, alto tráfico.

**Análisis:**

```bash
# Captura durante ataque (con límite de tamaño)
sudo tcpdump -i eth0 -s 96 -w ddos.pcap -C 200 -W 5
# -s 96: Solo capturar headers (no payload completo)

# Análisis de IPs origen
tshark -r ddos.pcap0 -T fields -e ip.src | sort | uniq -c | sort -rn | head -50

# Si muchas IPs diferentes → DDoS distribuido
# Si pocas IPs → DoS simple (más fácil de bloquear)

# Tipo de tráfico
tshark -r ddos.pcap0 -q -z io,phs

# Común en DDoS:
# - SYN flood: Muchos SYN sin ACK
# - UDP flood: Alto tráfico UDP
# - ICMP flood: Ping flood
# - HTTP flood: Requests HTTP legítimos pero en volumen

# Tasa de paquetes por segundo
capinfos ddos.pcap0 | grep "Average packet rate"

# Respuesta:
# - Bloquear IPs atacantes en firewall
# - Rate limiting
# - Contactar ISP/proveedor anti-DDoS
```

### Caso 6: Verificación de QoS

**Síntoma**: Validar que marcado DSCP funciona.

**Análisis:**

```bash
# Capturar tráfico
sudo tcpdump -i eth0 -w qos_check.pcap

# Ver valores DSCP en Wireshark
wireshark qos_check.pcap

# Display Filter: ip.dsfield.dscp
# O: ip.dsfield.dscp == 46 (para EF - Expedited Forwarding)

# Valores comunes:
# 0  (CS0) → Best Effort (normal)
# 8  (CS1) → Low Priority
# 46 (EF)  → Expedited Forwarding (VoIP)
# 34 (AF41) → Assured Forwarding (video)
```

### Caso 7: Detección de Tráfico No Autorizado

**Síntoma**: Sospecha de datos exfiltrados.

**Análisis:**

```bash
# Capturar tráfico saliente
sudo tcpdump -i eth0 src net 192.168.1.0/24 -w outbound.pcap

# Buscar conexiones inusuales
tshark -r outbound.pcap -q -z conv,tcp | sort -k6 -rn

# Buscar:
# - Transferencias grandes a IPs externas desconocidas
# - Tráfico en horarios no laborales
# - Protocolos inusuales (túneles DNS, ICMP tunneling)

# Verificar túnel DNS (exfiltración común)
tshark -r outbound.pcap -Y 'dns.qry.name.len > 50'
# Queries DNS anormalmente largas pueden ser datos codificados

# Buscar conexiones HTTPS a IPs (no dominios legítimos)
tshark -r outbound.pcap -Y 'ssl and not dns' -T fields -e ip.dst | sort -u
```

### Exportación de Métricas desde PCAP

Generar métricas de Prometheus desde archivos PCAP.

```python
#!/usr/bin/env python3
# pcap_to_metrics.py

from scapy.all import *
from prometheus_client import Counter, Histogram, Gauge, start_http_server
import time

# Definir métricas
packets_total = Counter('packets_total', 'Total packets', ['protocol'])
packet_size = Histogram('packet_size_bytes', 'Packet size distribution')
tcp_flags = Counter('tcp_flags_total', 'TCP flags', ['flag'])

def process_packet(pkt):
    if IP in pkt:
        # Contar por protocolo
        proto = pkt[IP].proto
        proto_name = {1: 'ICMP', 6: 'TCP', 17: 'UDP'}.get(proto, 'Other')
        packets_total.labels(protocol=proto_name).inc()
        
        # Tamaño de paquete
        packet_size.observe(len(pkt))
        
        # TCP flags
        if TCP in pkt:
            flags = pkt[TCP].flags
            if flags & 0x02:  # SYN
                tcp_flags.labels(flag='SYN').inc()
            if flags & 0x10:  # ACK
                tcp_flags.labels(flag='ACK').inc()
            if flags & 0x04:  # RST
                tcp_flags.labels(flag='RST').inc()

# Iniciar servidor Prometheus en :8000
start_http_server(8000)

# Procesar PCAP
print("Procesando captura...")
sniff(offline='capture.pcap', prn=process_packet, store=0)

print("Métricas disponibles en http://localhost:8000/metrics")
```

## Consideraciones Legales y Éticas

### Marco Legal

**⚠️ ADVERTENCIA CRÍTICA**: El escaneo y análisis de redes **sin autorización es ilegal** en la mayoría de jurisdicciones.

#### Leyes Aplicables (Ejemplos)

**Estados Unidos:**
- **Computer Fraud and Abuse Act (CFAA)**
- Penas: Multas y hasta 10 años de prisión

**Unión Europea:**
- **Directiva NIS2**
- **GDPR** (datos personales en tráfico)

**México:**
- **Código Penal Federal, Art. 211 bis**
- Delitos informáticos: 6 meses a 4 años de prisión

**Reino Unido:**
- **Computer Misuse Act 1990**

### Reglas de Oro

```
✅ PERMITIDO:
- Escanear tus propias redes
- Escanear con autorización escrita
- Usar scanme.nmap.org (host de prueba oficial de Nmap)
- Laboratorios virtuales aislados
- Entornos de formación autorizados

❌ PROHIBIDO:
- Escanear redes ajenas sin permiso
- Escanear infraestructura crítica
- Usar técnicas de evasión contra sistemas de producción
- Explotar vulnerabilidades sin autorización
- Capturar tráfico de terceros
```

**Ejemplo de carta de autorización:**

```
Restricciones:

Firma y sello:

```

### Ética del Pentester

**Principios:**
1. **Autorización siempre** - Nunca sin permiso escrito
2. **No hacer daño** - Minimizar impacto en sistemas
3. **Confidencialidad** - Proteger información descubierta
4. **Divulgación responsable** - Reportar vulnerabilidades apropiadamente
5. **Cumplimiento legal** - Respetar leyes locales e internacionales

### OSINT vs Invasivo

**Open Source Intelligence (OSINT)** - Generalmente legal:
- Búsquedas en Google
- DNS lookups públicos
- WHOIS queries
- Información en redes sociales

**Técnicas Invasivas** - Requieren autorización:
- Port scanning
- Vulnerability scanning
- Packet sniffing
- Exploitation

## Mejores Prácticas

### Para Captura de Tráfico

```bash
# 1. Usar filtros de captura para reducir tamaño
sudo tcpdump -i eth0 'port 80 or port 443' -w web.pcap

# 2. Rotar archivos para evitar archivos gigantes
sudo tcpdump -i eth0 -w /var/captures/cap.pcap -C 100 -W 10

# 3. Limitar snaplen si solo necesitas headers
sudo tcpdump -i eth0 -s 96 -w headers.pcap

# 4. Usar timestamps absolutos para correlación
sudo tcpdump -i eth0 -tttt -w capture.pcap

# 5. Capturar en múltiples interfaces si es necesario
sudo tcpdump -i any -w all_interfaces.pcap
```

### Para Análisis

```bash
# 1. Trabajar con copias de PCAP, no originales
cp original.pcap analisis.pcap

# 2. Usar filtros display en lugar de recapturar
tshark -r captura.pcap -Y 'http' -w http_only.pcap

# 3. Extraer estadísticas antes de análisis manual
tshark -r captura.pcap -q -z io,phs > estadisticas.txt

# 4. Documentar hallazgos con screenshots y filtros usados
# En Wireshark: File → Export → Specified Packets

# 5. Sanitizar PCAP antes de compartir (eliminar datos sensibles)
# Use editcap de Wireshark suite
editcap --seed 12345 original.pcap anonimizado.pcap
```

### Para Escaneo

```bash
# 1. Comenzar con escaneos no invasivos
nmap -sn 192.168.1.0/24  # Ping scan primero

# 2. Respetar timing en entornos de producción
nmap -T2 target.com  # Polite timing

# 3. Documentar escaneos realizados
nmap -oA scan_$(date +%Y%m%d_%H%M%S) target.com

# 4. Usar whitelists/blacklists
nmap -iL targets.txt --excludefile production_servers.txt

# 5. Validar antes de escaneos masivos
nmap --top-ports 10 test_target.com
# Si funciona OK, entonces full scan
```

### Seguridad de Herramientas


### Troubleshooting Eficiente

**Metodología de 5 pasos:**

```
1. DEFINIR EL PROBLEMA
   - ¿Qué no funciona exactamente?
   - ¿Desde cuándo?
   - ¿Afecta a todos o solo algunos usuarios?

2. RECOPILAR INFORMACIÓN
   - Ping, traceroute
   - Nmap del servicio afectado
   - Logs del sistema/aplicación

3. HIPÓTESIS
   - Basándote en la información, ¿qué puede ser?
   - Listar 2-3 causas probables

4. CAPTURA DIRIGIDA
   - tcpdump con filtro específico del problema
   - Reproducir el problema mientras capturas

5. ANÁLISIS EN WIRESHARK
   - Follow stream de la conexión
   - Buscar retransmisiones, RSTs, timeouts
   - Correlacionar con logs

6. SOLUCIÓN Y VALIDACIÓN
   - Aplicar fix
   - Repetir captura para confirmar solución
   - Documentar para futura referencia
```

## Conclusión

Los **analizadores de protocolos** son herramientas fundamentales para cualquier administrador de redes:

### Herramientas Clave Cubiertas

1. **Wireshark** - Análisis gráfico profundo, ideal para troubleshooting interactivo
2. **tcpdump** - Captura ligera en CLI, perfect para servidores
3. **tshark** - Power de Wireshark en terminal, excellent para automatización
4. **Nmap** - Scanner versátil, desde descubrimiento hasta auditoría de seguridad
5. **Netcat, hping3, Masscan, Scapy** - Herramientas especializadas complementarias

### Casos de Uso Principales

- **Troubleshooting**: Diagnosticar problemas de conectividad y rendimiento
- **Seguridad**: Detectar escaneos, intrusiones, exfiltración de datos
- **Auditoría**: Inventariar activos, validar configuraciones, compliance
- **Optimización**: Identificar cuellos de botella, validar QoS
- **Forense**: Investigación de incidentes, análisis post-mortem

### Integración con Monitoreo

Los analizadores complementan (no reemplazan) las herramientas de monitoreo:

```
Métricas (SNMP, Prometheus) → ¿QUÉ está mal?
Logs (rsyslog, ELK) → ¿CUÁNDO y DÓNDE?
Flujos (NetFlow) → ¿QUIÉN habla con QUIÉN?
Analizadores (Wireshark) → ¿POR QUÉ y CÓMO exactamente?
```

### Responsabilidad y Ética

- ✅ **Siempre obtener autorización** antes de escanear o capturar
- ✅ **Proteger datos capturados** (pueden contener información sensible)
- ✅ **Usar con fines legítimos** (administración, seguridad autorizada, educación)
- ❌ **Nunca analizar redes ajenas** sin permiso explícito
