# 1.3 Gestión de Contabilidad (Accounting Management)

## 📋 Introducción

La **Gestión de Contabilidad** (Accounting Management) es el área funcional de FCAPS responsable de **medir, registrar, reportar y controlar el uso de recursos de red** por usuarios, aplicaciones, departamentos y servicios. Su objetivo es proporcionar visibilidad sobre **quién usa qué, cuánto, cuándo y para qué**, permitiendo optimización de recursos, facturación interna/externa y cumplimiento de políticas.

### **⚠️ Aclaración Importante: Accounting vs Accounts**


```
┌─────────────────────────────────────────────────────────┐
│ INTERPRETACIONES DE LA "A" EN FCAPS                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│ 1️⃣ ACCOUNTING MANAGEMENT (Definición ITU-T Original)   │
│    "Gestión de Contabilidad de Recursos"               │
│                                                         │
│    Enfoque: Uso de recursos de red                     │
│    ├─ Medición de consumo de ancho de banda            │
│    ├─ Registro de uso por usuario/departamento         │
│    ├─ Facturación interna (chargeback/showback)        │
│    ├─ Capacity planning y optimización                 │
│    └─ Auditoría de uso de recursos                     │
│                                                         │
│    Contexto: Telecomunicaciones, ISPs, empresas        │
│    Estándar: ITU-T M.3400, TMN                         │
│                                                         │
├─────────────────────────────────────────────────────────┤
│                                                         │
│ 2️⃣ ACCOUNTS MANAGEMENT (Interpretación Alternativa)    │
│    "Gestión de Cuentas de Usuario"                     │
│                                                         │

│    ├─ Creación/eliminación de cuentas de usuario       │

│    ├─ Autenticación y autorización (AAA)               │
│    ├─ Auditoría de accesos y actividades               │

│                                                         │
│    Contexto: Seguridad de TI, Identity Management      │
│    Estándar: AAA (RADIUS, TACACS+), LDAP, AD           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**¿Cuál es la correcta?**

```
Respuesta: AMBAS son válidas según el contexto

📡 Telecomunicaciones/Redes tradicionales:
   → "A" = Accounting (contabilidad de recursos)
   → Enfoque en costos y facturación
   
🔒 Seguridad de TI/Redes empresariales:
   → "A" = Accounts (gestión de usuarios)
   → Enfoque en control de acceso y auditoría
   
🎯 Enfoque moderno integrado:
   → AMBOS aspectos son complementarios
   → Accounting: ¿Cuánto se consume?
   → Accounts: ¿Quién lo consume?
   → Juntos proporcionan visibilidad completa
```

## 📊 PARTE 1: Accounting Management (Contabilidad de Recursos)

### **¿Qué es Accounting Management?**

**Definición ITU-T M.3400:**
> "Conjunto de funciones que permiten registrar el uso de recursos de red y servicios para propósitos de análisis de tendencias, planificación de capacidad, facturación, distribución de costos y administración del nivel de servicio."

**En términos prácticos:**
Accounting Management responde preguntas como:

```
Preguntas de Negocio           Accounting Management Proporciona
─────────────────────────────────────────────────────────────────
¿Quién consume más ancho       → Reportes de top talkers por
 de banda?                       usuario/departamento/aplicación

¿Cuánto cuesta la red          → Desglose de costos por servicio,
 al negocio?                     ubicación, departamento

¿Necesitamos más capacidad?    → Análisis de tendencias de uso,
                                 proyección de saturación

¿Los departamentos están       → Métricas de uso vs cuotas
 usando recursos              asignadas
 eficientemente?                

¿Cumplimos políticas de uso?   → Auditoría de uso vs políticas
                                 (ej. no streaming video)

¿Cómo justificamos el          → ROI de inversiones en red
 presupuesto de TI?              basado en uso real
```

### **Objetivos de Accounting Management**

#### **1. Medición de Uso de Recursos**

**Objetivo:** Capturar y registrar métricas cuantificables sobre el consumo de recursos de red.

**Recursos medidos:**

| **Recurso** | **Métricas** | **Granularidad** | **Fuente de Datos** |
|-------------|--------------|------------------|---------------------|
| **Ancho de banda** | Bytes/paquetes transmitidos/recibidos | Por usuario, VLAN, aplicación, interfaz | NetFlow, sFlow, SNMP |
| **Tiempo de conexión** | Duración de sesiones | Por usuario, servicio (VPN, WiFi) | AAA logs, RADIUS accounting |
| **Llamadas/sesiones** | Cantidad, duración | VoIP, videoconferencias, VPN | CDR (Call Detail Records), syslog |
| **Almacenamiento** | GB utilizados en NAS/SAN | Por usuario, departamento | Storage APIs, SNMP |
| **Recursos de CPU/RAM** | Utilización de equipos de red | Por dispositivo, proceso | SNMP, telemetría |
| **Licencias** | Uso de licencias concurrentes | Por aplicación, usuario | License servers, SNMP |

**Ejemplo práctico - Medición de ancho de banda con NetFlow:**


#### **2. Chargeback y Showback**

**Chargeback:**
Modelo de **facturación interna** donde los departamentos **pagan** por el uso de recursos de red según consumo real.

**Showback:**
Modelo de **visibilidad** donde se **muestra** (pero no se cobra) el costo de recursos consumidos por departamento.

**Comparación:**

| **Aspecto** | **Chargeback** | **Showback** |
|-------------|----------------|--------------|
| **Facturación real** | ✅ Sí, afecta presupuesto departamental | ❌ No, solo informativo |
| **Objetivo** | Recuperar costos, incentivar eficiencia | Crear conciencia de costos |
| **Complejidad** | Alta (requiere aprobación financiera) | Media (solo reportes) |
| **Resistencia organizacional** | Alta (departamentos se resisten a pagar) | Baja (solo informativo) |
| **Incentivo para optimizar** | Fuerte (impacto en presupuesto) | Moderado (presión social) |
| **Implementación típica** | Empresas grandes, ISPs | Cualquier organización |

**Ejemplo de Chargeback:**

#### **3. Capacity Planning (Planificación de Capacidad)**

**Objetivo:** Predecir cuándo se alcanzarán límites de capacidad y planificar expansiones antes de que ocurran problemas.

**Metodología:**

```
1. RECOLECTAR DATOS HISTÓRICOS
   └─ Mínimo 6-12 meses de métricas de uso

2. IDENTIFICAR TENDENCIAS
   └─ Crecimiento lineal, estacional, eventos especiales

3. PROYECTAR USO FUTURO
   └─ Extrapolar tendencias con modelos estadísticos

4. DETERMINAR PUNTO DE SATURACIÓN
   └─ Umbral de alerta (ej. 80% de capacidad)

5. PLANIFICAR ACCIONES
   └─ Upgrade, balanceo de carga, optimización
```

**Ejemplo real - Capacity Planning para enlace WAN:**

```python
#!/usr/bin/env python3
# capacity_planning.py - Proyección de saturación de enlace WAN

import pandas as pd
import numpy as np
from datetime import datetime, timedelta
import matplotlib.pyplot as plt
from scipy import stats

# Datos históricos de uso de ancho de banda (últimos 12 meses)
# Fuente: NetFlow/SNMP collector
data = {
    'Mes': ['2025-04', '2025-05', '2025-06', '2025-07', '2025-08', 
            '2025-09', '2025-10', '2025-11', '2025-12', '2026-01', 
            '2026-02', '2026-03'],
    'Uso_Promedio_Mbps': [450, 470, 490, 510, 530, 550, 580, 610, 
                          640, 670, 700, 730]
}

df = pd.DataFrame(data)
df['Mes_Num'] = range(1, 13)

# Regresión lineal para tendencia
slope, intercept, r_value, p_value, std_err = stats.linregress(
    df['Mes_Num'], df['Uso_Promedio_Mbps']
)

print(f"📊 ANÁLISIS DE CAPACIDAD - Enlace WAN Principal")
print(f"{'='*60}")
print(f"\n📈 Tendencia histórica (últimos 12 meses):")
print(f"Crecimiento mensual promedio: {slope:.2f} Mbps/mes")
print(f"Coeficiente de correlación (R²): {r_value**2:.4f}")

# Capacidad actual del enlace
CAPACIDAD_ACTUAL = 1000  # Mbps (1 Gbps)
UMBRAL_ALERTA = 0.80     # 80%
UMBRAL_CRITICO = 0.90    # 90%

# Proyección a 12 meses
meses_futuros = 12
proyeccion = []

for mes in range(1, meses_futuros + 1):
    mes_total = 12 + mes
    uso_proyectado = slope * mes_total + intercept
    proyeccion.append({
        'Mes': (datetime.now() + timedelta(days=30*mes)).strftime('%Y-%m'),
        'Uso_Proyectado_Mbps': uso_proyectado,
        'Porcentaje_Capacidad': (uso_proyectado / CAPACIDAD_ACTUAL) * 100
    })

df_proyeccion = pd.DataFrame(proyeccion)

# Determinar cuándo se alcanzará 80% y 90%
alerta_mbps = CAPACIDAD_ACTUAL * UMBRAL_ALERTA
critico_mbps = CAPACIDAD_ACTUAL * UMBRAL_CRITICO

meses_a_alerta = (alerta_mbps - intercept) / slope - 12
meses_a_critico = (critico_mbps - intercept) / slope - 12

print(f"\n⚠️ ALERTAS DE CAPACIDAD:")
print(f"Capacidad total: {CAPACIDAD_ACTUAL} Mbps")
print(f"Uso actual (marzo 2026): 730 Mbps (73%)")
print(f"")
print(f"Umbral de alerta (80%): {alerta_mbps:.0f} Mbps")
print(f"  → Se alcanzará en: {meses_a_alerta:.1f} meses ({(datetime.now() + timedelta(days=30*meses_a_alerta)).strftime('%B %Y')})")
print(f"")
print(f"Umbral crítico (90%): {critico_mbps:.0f} Mbps")
print(f"  → Se alcanzará en: {meses_a_critico:.1f} meses ({(datetime.now() + timedelta(days=30*meses_a_critico)).strftime('%B %Y')})")

# Recomendaciones
print(f"\n💡 RECOMENDACIONES:")

if meses_a_alerta < 3:
    print(f"🔴 URGENTE: Planificar upgrade INMEDIATO")
    print(f"   Tiempo de provisión típico: 2-3 meses")
    print(f"   Riesgo: ALTO (saturación inminente)")
elif meses_a_alerta < 6:
    print(f"🟡 IMPORTANTE: Iniciar proceso de upgrade")
    print(f"   Ventana de acción: {meses_a_alerta:.1f} meses")
    print(f"   Riesgo: MEDIO")
else:
    print(f"🟢 Capacidad suficiente a corto plazo")
    print(f"   Monitorear trimestralmente")
    print(f"   Planificar upgrade en próximo presupuesto")

# Proyección detallada
print(f"\n📅 PROYECCIÓN PRÓXIMOS 6 MESES:")
print(f"{'Mes':<12} {'Uso (Mbps)':<15} {'% Capacidad':<15} {'Estado'}")
print(f"{'-'*60}")

for _, row in df_proyeccion.head(6).iterrows():
    uso = row['Uso_Proyectado_Mbps']
    pct = row['Porcentaje_Capacidad']
    
    if pct >= 90:
        estado = "🔴 CRÍTICO"
    elif pct >= 80:
        estado = "🟡 ALERTA"
    else:
        estado = "🟢 OK"
    
    print(f"{row['Mes']:<12} {uso:>8.0f} Mbps   {pct:>6.1f}%         {estado}")

print(f"\n💰 ESTIMACIÓN DE COSTOS:")
print(f"Upgrade a 2 Gbps: $5,000/mes adicionales")
print(f"Costo de NO hacer upgrade (downtime): $15,000/incidente")
print(f"ROI de upgrade proactivo: Positivo si se evita ≥1 incidente")

# Resultado esperado:
# 📊 ANÁLISIS DE CAPACIDAD - Enlace WAN Principal
# ============================================================
# 
# 📈 Tendencia histórica (últimos 12 meses):
# Crecimiento mensual promedio: 25.45 Mbps/mes
# Coeficiente de correlación (R²): 0.9987
# 
# ⚠️ ALERTAS DE CAPACIDAD:
# Capacidad total: 1000 Mbps
# Uso actual (marzo 2026): 730 Mbps (73%)
# 
# Umbral de alerta (80%): 800 Mbps
#   → Se alcanzará en: 2.7 meses (Junio 2026)
# 
# Umbral crítico (90%): 900 Mbps
#   → Se alcanzará en: 6.7 meses (Octubre 2026)
# 
# 💡 RECOMENDACIONES:
# 🟡 IMPORTANTE: Iniciar proceso de upgrade
#    Ventana de acción: 2.7 meses
#    Riesgo: MEDIO
```

#### **4. Optimización de Costos**

**Objetivo:** Reducir gastos en infraestructura de red sin comprometer el nivel de servicio.

**Estrategias de optimización:**

**A) Identificación de desperdicio de recursos**

```
Análisis de uso revela:

❌ Problema: Enlace WAN de 500 Mbps en sucursal
   Uso promedio: 50 Mbps (10% de capacidad)
   Uso pico: 120 Mbps (24% de capacidad)
   Costo actual: $3,000/mes
   
✅ Solución: Downgrade a 200 Mbps
   Capacidad suficiente con margen (60% pico)
   Costo optimizado: $1,500/mes
   Ahorro anual: $18,000
```

**B) Balanceo de carga**

```
❌ Problema: Enlace primario saturado (90%), secundario subutilizado (20%)
   
✅ Solución: Implementar SD-WAN para balanceo inteligente
   Resultado: Uso equilibrado (55% primario, 55% secundario)
   Beneficio: Evita upgrade innecesario ($60k/año)
```

**C) Políticas de QoS y rate limiting**

```
❌ Problema: Streaming de video no laboral consume 30% del ancho de banda
   
✅ Solución: Implementar políticas de QoS
   - Prioridad alta: VoIP, ERP, CRM (40% garantizado)
   - Prioridad media: Email, navegación (30% garantizado)
   - Prioridad baja: Streaming personal (30% best effort)
   
   Resultado: Capacidad liberada para tráfico crítico
```

**D) Rightsizing de licencias**

```
Auditoría de licencias de software:

Cisco Webex licenses:
  ├─ Licencias compradas: 500
  ├─ Usuarios activos: 320
  ├─ Uso concurrente máximo: 85 usuarios
  └─ Desperdicio: 180 licencias ($45/lic/año = $8,100/año)

✅ Acción: Reducir a 350 licencias con margen
   Ahorro: $6,750/año
```

## 👥 PARTE 2: Accounts Management (Gestión de Cuentas de Usuario)

### **¿Qué es Accounts Management?**

**Definición operativa:**
> Conjunto de procesos y controles para gestionar el ciclo de vida de cuentas de usuario, permisos de acceso y auditoría de actividades en la infraestructura de red.

**Enfoque:** Seguridad, control de acceso y cumplimiento normativo.

---

### **Componentes de Accounts Management**

#### **1. Gestión del Ciclo de Vida de Usuarios**

**Fases del ciclo de vida:**

```
┌────────────────────────────────────────────────────────┐
│ CICLO DE VIDA DE CUENTA DE USUARIO                    │
├────────────────────────────────────────────────────────┤
│                                                        │
│ 1️⃣ PROVISIONING (Creación)                            │
│   ├─ Trigger: Nuevo empleado, contratista, estudiante │
│   ├─ Acción: Crear cuenta en AD/LDAP                  │
│   ├─ Asignar: VLAN, permisos, grupos, cuotas          │
│   └─ Notificar: Usuario recibe credenciales           │
│                                                        │
│ 2️⃣ MAINTENANCE (Mantenimiento)                        │
│   ├─ Cambio de rol: Reasignar permisos                │
│   ├─ Cambio de departamento: Mover a nueva VLAN       │
│   ├─ Reset de password: Proceso self-service/helpdesk │
│   └─ Actualización de políticas: Aplicar nuevas reglas│
│                                                        │
│ 3️⃣ SUSPENSION (Suspensión temporal)                   │
│   ├─ Trigger: Licencia médica, ausencia, investigación│
│   ├─ Acción: Deshabilitar cuenta (no eliminar)        │
│   ├─ Impacto: Sin acceso a red, datos preservados     │
│   └─ Reversible: Reactivación rápida si es necesario  │
│                                                        │
│ 4️⃣ DEPROVISIONING (Eliminación)                       │
│   ├─ Trigger: Renuncia, despido, graduación           │
│   ├─ Acción: Deshabilitar cuenta inmediatamente       │
│   ├─ Archivado: Mover datos a backup (retención 30-90d)│
│   ├─ Auditoría: Revisar accesos finales               │
│   └─ Eliminación: Purga completa después de retención │
└────────────────────────────────────────────────────────┘
```

```powershell

# Trigger: Nuevo empleado en sistema de RH

    [string]$NombreCompleto = "Juan Pérez García",
    [string]$Departamento = "Ventas",

           -GivenName "Juan" `
           -Surname "Pérez García" `
           -SamAccountName $Username `
           -UserPrincipalName "$Username@empresa.local" `
           -EmailAddress $Email `
           -Department $Departamento `
           -Title $Puesto `
           -AccountPassword $Password `
           -Enabled $true `
           -ChangePasswordAtLogon $true

# 2. Asignar a grupos según departamento
Switch ($Departamento) {
    "Ventas" {
        Add-ADGroupMember -Identity "GRP-Ventas" -Members $Username
        Add-ADGroupMember -Identity "GRP-VLAN10-Users" -Members $Username
        Add-ADGroupMember -Identity "GRP-VPN-Access" -Members $Username
    }
    "Finanzas" {
        Add-ADGroupMember -Identity "GRP-Finanzas" -Members $Username
        Add-ADGroupMember -Identity "GRP-VLAN20-Servers" -Members $Username
        # No VPN por política de seguridad
    }
}

# 3. Configurar cuotas de red
# Via RADIUS attribute (Mikrotik example)
$RADIUSProfile = @{
    Username = $Username
    MaxBandwidthUp = "20M"    # 20 Mbps upload
    MaxBandwidthDown = "50M"  # 50 Mbps download
    MaxSessions = 3            # 3 dispositivos concurrentes
}

# 4. Provisionar en sistemas de red
# 4a. Agregar a TACACS+ para acceso a equipos de red (si es admin)
if ($Puesto -like "*Ingeniero*" -or $Puesto -like "*Administrador*") {
    # Agregar a servidor TACACS+
    Write-Host "Agregando usuario $Username a TACACS+ con privilegios nivel 1"
}

# 4b. Crear entrada DHCP reservada si aplica
if ($Departamento -eq "TI") {
    # Reservar IP estática en DHCP
    Write-Host "Creando reservación DHCP para $Username"
}

# 5. Notificar al usuario
$EmailBody = @"
Bienvenido a TecnoSoft, $NombreCompleto

Sus credenciales de red son:
Usuario: $Username
Password temporal: Temp@123! (debe cambiar en primer acceso)

Accesos asignados:
- WiFi: SSID 'Empresa-Segura' (WPA2-Enterprise con usuario/password)
- VPN: $(if ($Departamento -eq "Ventas") {"Habilitado"} else {"No disponible"})
- Email: $Email

Políticas de uso:
- Ancho de banda: 50 Mbps descarga / 20 Mbps subida
- Dispositivos concurrentes: 3 máximo
- Almacenamiento OneDrive: 1 TB

Soporte: helpdesk@empresa.com | Ext. 9999
"@

Send-MailMessage -To $Email -From "noreply@empresa.com" `
                 -Subject "Credenciales de Red - TecnoSoft" `
                 -Body $EmailBody -SmtpServer "smtp.empresa.com"

Write-Host "✅ Usuario $Username creado exitosamente"
Write-Host "📧 Credenciales enviadas a $Email"
```

```cisco
aaa accounting commands 1 default start-stop group tacacs+

line vty 0 15

 authorization commands 1 default
 authorization commands 15 default
 accounting exec default

!

! 7. Excepción para consola (usar autenticación local)
```

```sql
-- Query para detectar actividad sospechosa
-- Base de datos: SIEM (Security Information and Event Management)

-- Caso: Usuario accediendo a recursos fuera de horario normal

SELECT 
    username,
    resource_accessed,
    timestamp,
    source_ip,
    CASE 
        WHEN HOUR(timestamp) BETWEEN 22 AND 6 THEN 'Horario inusual'
        WHEN DAYOFWEEK(timestamp) IN (1,7) THEN 'Fin de semana'
        ELSE 'Horario normal'
    END AS time_category,
    COUNT(*) OVER (PARTITION BY username, DATE(timestamp)) AS daily_accesses
FROM 
    access_logs
WHERE 
    username = 'jperez'
    AND timestamp >= DATE_SUB(NOW(), INTERVAL 30 DAY)
    AND resource_accessed LIKE '%Servidor-Financiero%'
ORDER BY 
    timestamp DESC;
```
