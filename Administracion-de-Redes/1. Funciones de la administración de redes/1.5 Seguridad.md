# 1.5 Gestión de la Seguridad (Security Management)

## Introducción

La **Gestión de Seguridad** es el quinto pilar del framework FCAPS (ITU-T M.3400) y probablemente el más crítico en la era actual de ciberamenazas constantes. Mientras que las otras áreas de FCAPS se enfocan en operación y eficiencia, Security Management protege la **disponibilidad, integridad y confidencialidad** de toda la infraestructura.

### Objetivos de la Gestión de Seguridad

1. **Prevenir accesos no autorizados** - Control de quién puede acceder a qué recursos
2. **Proteger la integridad de datos** - Evitar modificaciones no autorizadas en configuraciones y tráfico
3. **Asegurar disponibilidad** - Proteger contra ataques DoS/DDoS y sabotaje
4. **Garantizar confidencialidad** - Cifrado de comunicaciones sensibles
5. **Auditar y trazar actividad** - Logging completo para análisis forense y cumplimiento
6. **Responder a incidentes** - Procedimientos para contener y remediar brechas de seguridad

---

### Triángulo CIA (Fundamento de Seguridad)

```
              CONFIDENCIALIDAD
                 /        \
                /          \
               /            \
              /   SEGURIDAD  \
             /                \
            /                  \
    INTEGRIDAD ───────────── DISPONIBILIDAD

CONFIDENCIALIDAD:
- Solo usuarios autorizados acceden a información
- Cifrado de datos en tránsito y reposo
- Control de acceso estricto

INTEGRIDAD:
- Datos no modificados sin autorización
- Verificación de cambios (hashing, firmas digitales)
- Configuration management riguroso

DISPONIBILIDAD:
- Sistemas accesibles cuando se necesitan
- Protección contra DoS/DDoS
- Redundancia y respaldos
```

### Amenazas Comunes en Redes

```
AMENAZAS EXTERNAS:
1. DoS/DDoS: Saturar recursos (bandwidth, CPU, conexiones)
2. Malware: Ransomware, botnets, cryptominers
3. Escaneo/Reconocimiento: Nmap, Shodan, vulnerability scans
4. Explotación de vulnerabilidades: 0-days, CVEs conocidos
5. Man-in-the-Middle: Interceptación de tráfico
6. Ataques a aplicaciones: SQL injection, XSS, CSRF

AMENAZAS INTERNAS:
1. Empleados descontentos: Sabotaje intencional
2. Negligencia: Configuraciones débiles, passwords compartidos
3. Ingeniería social: Phishing, pretexting
4. Shadow IT: Dispositivos no autorizados en red
5. Exfiltración de datos: Empleado roba información
6. Acceso no autorizado: Privilegios excesivos

VECTORES DE ATAQUE:
- Puertos/servicios expuestos innecesariamente
- Contraseñas débiles o por defecto
- Software desactualizado (CVEs)
- Falta de segmentación de red
- Ausencia de monitoreo/alertas
- Sin cifrado en comunicaciones
```

### Clasificación de Tecnologías de Seguridad

#### Firewall (Cortafuegos)

**Función:** Filtrar tráfico de red según reglas predefinidas (permitir/denegar).

**Tipos de Firewall:**

```
1. PACKET FILTERING FIREWALL (Capa 3-4)
   - Inspecciona: IP origen/destino, puerto, protocolo
   - Ventajas: Rápido, bajo overhead
   - Desventajas: No inspecciona contenido, sin contexto
   - Ejemplo: ACLs en routers Cisco, iptables básico
   
   Decisión: IP 192.168.1.10 → 8.8.8.8:53 UDP
   Regla: permit udp any any eq 53 → PERMITIR

2. STATEFUL INSPECTION FIREWALL (Capa 4)
   - Inspecciona: + Estado de conexión (NEW, ESTABLISHED)
   - Ventajas: Más seguro que packet filtering, bloquea conexiones no solicitadas
   - Desventajas: No inspecciona datos de aplicación
   - Ejemplo: Cisco ASA, Zone-Based Firewall, iptables con conntrack
   
   Flujo TCP:
   1. SYN (interno→externo) → Crea entrada en tabla de estado → PERMITIR
   2. SYN-ACK (externo→interno) → Valida vs estado → PERMITIR
   3. ACK (interno→externo) → Valida vs estado → PERMITIR
   4. Paquete externo→interno sin SYN previo → NO en tabla → BLOQUEAR

3. APPLICATION LAYER FIREWALL / PROXY (Capa 7)
   - Inspecciona: Contenido completo de aplicación (HTTP, FTP, DNS)
   - Ventajas: Puede bloquear malware, SQL injection, comandos peligrosos
   - Desventajas: Alto overhead (termina conexiones), más lento
   - Ejemplo: Squid proxy, Blue Coat ProxySG
   
   HTTP Request: GET /admin.php?id=1' OR '1'='1
   Firewall detecta: SQL injection → BLOQUEAR

4. NEXT-GENERATION FIREWALL (NGFW)
   - Inspecciona: Todo lo anterior + Deep Packet Inspection (DPI)
   - Características adicionales:
     * IPS integrado (detección/prevención intrusiones)
     * Application awareness (identifica apps, no solo puertos)
     * SSL/TLS inspection (descifra, inspecciona, re-cifra)
     * User identity (quién, no solo qué IP)
     * Threat intelligence integration
   - Ventajas: Seguridad completa en un dispositivo
   - Desventajas: Costoso, requiere hardware potente
   - Ejemplo: Palo Alto Networks, Cisco Firepower, Fortinet FortiGate
   
   Ejemplo decisión:
   - Puerto 443 (HTTPS) detectado
   - DPI identifica: Aplicación = Torrent (P2P)
   - Política: Bloquear P2P en horario laboral
   - Acción: BLOQUEAR (aunque es puerto 443 "legítimo")

5. WEB APPLICATION FIREWALL (WAF)
   - Especializado: Proteger aplicaciones web (HTTP/HTTPS)
   - Inspecciona: Peticiones/respuestas HTTP, cookies, headers
   - Protege contra: SQL injection, XSS, CSRF, DDoS capa 7
   - Modos:
     * Transparent: Solo alerta, no bloquea
     * Blocking: Bloquea ataques detectados
   - Ejemplo: ModSecurity, Cloudflare WAF, AWS WAF, F5 ASM
   
   Request: POST /login.php
   Body: username=admin&password=' OR 1=1--
   WAF detecta: Patrón SQL injection → HTTP 403 Forbidden

6. CLOUD FIREWALL / FWaaS (Firewall as a Service)
   - Ubicación: En la nube (no on-premises)
   - Ventajas: Escalable, sin hardware, gestión centralizada
   - Uso: Proteger tráfico de usuarios remotos, oficinas distribuidas
   - Ejemplo: Zscaler, Cloudflare Gateway, Cisco Umbrella
```

**Comparación de Capacidades:**

| Característica | Packet Filter | Stateful | App Proxy | NGFW | WAF |
|----------------|---------------|----------|-----------|------|-----|
| **Velocidad** | ★★★★★ | ★★★★☆ | ★★☆☆☆ | ★★★☆☆ | ★★★☆☆ |
| **Seguridad** | ★★☆☆☆ | ★★★☆☆ | ★★★★☆ | ★★★★★ | ★★★★☆ (web) |

#### IDS vs IPS (Intrusion Detection/Prevention System)

**IDS (Intrusion Detection System):**

```
FUNCIÓN: Detectar + Alertar (PASIVO)

CARACTERÍSTICAS:
- Monitorea tráfico en modo promiscuo (copia del tráfico)
- NO puede bloquear ataques (solo alerta)
- Ubicación: Conectado a puerto SPAN/mirror de switch
- No afecta performance de red (out of band)
- Riesgo: Ataque puede completarse antes de respuesta humana

VENTAJAS:
✓ Sin impacto en latencia
✓ Sin riesgo de bloquear tráfico legítimo
✓ Bueno para análisis forense

DESVENTAJAS:
✗ No previene ataques en tiempo real
✗ Requiere respuesta manual
✗ Tiempo entre detección y mitigación

USO: Auditorías, cumplimiento, investigación, redes donde no se puede arriesgar bloqueos
```

**IPS (Intrusion Prevention System):**

```
FUNCIÓN: Detectar + Bloquear (ACTIVO)

CARACTERÍSTICAS:
- Ubicado inline (tráfico pasa A TRAVÉS del IPS)
- Puede bloquear ataques automáticamente
- Inspecciona cada paquete antes de forwarding
- Agrega latencia (milisegundos)
- Riesgo: Falso positivo = bloqueo de tráfico legítimo

VENTAJAS:
✓ Prevención en tiempo real
✓ Sin intervención humana necesaria
✓ Detiene ataque antes de que llegue a destino

DESVENTAJAS:
✗ Single point of failure (si IPS cae, red cae)
✗ Impacto en performance
✗ Falsos positivos pueden causar downtime

USO: Protección perimetral, segmentos críticos, cumplimiento PCI-DSS
```

**Métodos de Detección:**

```
1. SIGNATURE-BASED (Basado en Firmas)
   - Compara tráfico con base de datos de patrones conocidos
   - Ventaja: Alta precisión para amenazas conocidas
   - Desventaja: No detecta ataques nuevos (0-days)
   - Ejemplo: Detectar exploit específico de MS17-010 (WannaCry)

   Firma: 
   alert tcp any any -> any 445 (
     content:"|ff 53 4d 42|"; 
     msg:"SMB MS17-010 Exploit Attempt";
   )

2. ANOMALY-BASED (Basado en Anomalías)
   - Aprende comportamiento "normal" de red
   - Alerta cuando detecta desviaciones
   - Ventaja: Detecta ataques desconocidos (0-days)
   - Desventaja: Muchos falsos positivos
   - Ejemplo: Tráfico normal = 1000 conexiones/hora
              Súbitamente = 50,000 conexiones/hora → ALERTA (posible DDoS)

3. HYBRID (Combinado)
   - Usa ambos métodos
   - Más común en IPS/IDS modernos
   - Ejemplo: Suricata, Snort 3

4. HEURISTIC / BEHAVIORAL
   - Analiza comportamiento de código/tráfico
   - Detecta malware por acciones, no firma
   - Ejemplo: Proceso intenta escribir en 10,000 archivos/segundo → Ransomware
```

**Topología de Deployment:**

```
OPCIÓN 1: IDS (Out of Band)
                     
Router ─── Switch ──┬── Firewall ── Internet
              │     └── Servidores
              │
           SPAN Port
              │
            [IDS]
              │
        Syslog → SIEM
        
* IDS recibe COPIA del tráfico
* No afecta flujo de red
* Solo puede alertar


OPCIÓN 2: IPS (Inline)

Internet ── [Firewall] ── [IPS] ── Switch ── Servidores
                           │
                         Alertas
                           │
                         SIEM

* TODO el tráfico pasa por IPS
* IPS puede DROP paquetes maliciosos
* Agrega latencia (~1-5ms típico)
```

#### SIEM (Security Information and Event Management)

**Función:** Centralizar, correlacionar y analizar logs de seguridad de múltiples fuentes.

```
SIEM = SIM + SEM

SIM (Security Information Management):
- Almacenamiento de logs a largo plazo
- Cumplimiento y auditoría

SEM (Security Event Management):
- Análisis en tiempo real
- Correlación de eventos
- Alertas automatizadas
```

**Arquitectura SIEM:**

```
FUENTES DE DATOS:
[Firewalls] ─┐
[IPS/IDS]   ─┤
[Switches]  ─┤
[Routers]   ─┤
[Servers]   ─┼──→ [SIEM] ──→ [Dashboards]
[AD/LDAP]   ─┤      │          [Reports]
[Apps]      ─┤      │          [Alertas]
[Endpoints] ─┤      │
[Cloud]     ─┘      └──→ [SOAR] (Automatización)

FLUJO:
1. COLLECTION: Recolectar logs (syslog, API, agents)
2. NORMALIZATION: Convertir a formato común
3. STORAGE: Almacenar en base de datos indexada
4. CORRELATION: Detectar patrones multi-fuente
5. ALERTING: Notificar eventos críticos
6. VISUALIZATION: Dashboards y reportes
```

**Ejemplo de Correlación:**

```
EVENTO AISLADO (Sin SIEM):
10:00 - Firewall: 50 intentos de SSH fallidos desde 185.220.101.23
  → Admin ve log, anota IP, continúa trabajando

10:15 - IPS: Escaneo de puertos desde 185.220.101.23
  → Admin ve alerta, anota

10:30 - Web Server: SQL injection intento desde 185.220.101.23
  → Admin ve log

10:45 - AD: Login exitoso de usuario "backup_service" desde 185.220.101.23
  → Admin piensa: "Servicio de backup normal"

CON SIEM (Correlación automática):
10:46 - SIEM Alerta CRÍTICA:
  "Patrón de ataque detectado: Reconocimiento → Explotación → Compromiso"
  
  Eventos correlacionados:
  1. Brute force SSH (10:00)
  2. Port scan (10:15)
  3. Web attack (10:30)
  4. Credencial comprometida (10:45) ← Cuenta de servicio desde IP atacante!
  
  Confianza: 95%
  Severidad: CRÍTICA
  Acción recomendada: Bloquear IP, deshabilitar cuenta, iniciar incident response
  
  Timeline: 45 minutos desde inicio de ataque
  → Respuesta inmediata vs descubrimiento días después
```

**Casos de Uso SIEM:**

```
1. DETECCIÓN DE AMENAZAS
   - Correlación multi-fuente
   - Machine learning para anomalías
   - Threat intelligence integration

2. COMPLIANCE Y AUDITORÍA
   - PCI-DSS: Logs de acceso a datos de tarjetas
   - HIPAA: Quién accedió a registros médicos
   - SOX: Cambios en sistemas financieros
   - GDPR: Accesos a datos personales

3. INVESTIGACIÓN FORENSE
   - Timeline completo de incidente
   - "¿Qué hizo el atacante?"
   - "¿Qué sistemas tocó?"
   - "¿Qué datos exfiltró?"

4. INCIDENT RESPONSE
   - Alertas en tiempo real
   - Playbooks automatizados
   - Integración con SOAR

5. MONITOREO DE USUARIOS PRIVILEGIADOS
   - Comandos de administradores
   - Accesos a sistemas críticos
   - Cambios de configuración
```

#### EDR (Endpoint Detection and Response)

**Función:** Proteger endpoints (laptops, desktops, servidores) con detección avanzada.

```
DIFERENCIA CON ANTIVIRUS TRADICIONAL:

ANTIVIRUS:
- Detección basada en firmas
- Escaneo de archivos
- Protección básica
- Limitado a malware conocido

EDR:
- Behavioral analysis (comportamiento de procesos)
- Visibility completa de endpoint
- Threat hunting (buscar amenazas proactivamente)
- Detección de malware sin firma (0-days)
- Investigación forense
- Rollback de cambios maliciosos
```

**Capacidades EDR:**

```
1. CONTINUOUS MONITORING
   - Procesos ejecutados
   - Conexiones de red
   - Modificaciones de archivos/registry
   - Comandos ejecutados

2. BEHAVIORAL DETECTION
   - Powershell ejecutando shellcode → Alerta
   - Proceso inesperado inyectando DLL → Alerta
   - Excel abriendo cmd.exe → Alerta (macro maliciosa)

3. THREAT HUNTING
   - Buscar IOCs (Indicators of Compromise)
   - "¿Algún endpoint contactó IP 185.220.101.23?"
   - Query: "Procesos que modificaron >1000 archivos en <5 min"

4. ISOLATION
   - Aislar endpoint comprometido de red
   - Evitar propagación lateral

5. FORENSICS
   - Timeline completo de actividad
   - "¿Qué hizo el malware?"
   - Evidencia para análisis

6. REMEDIATION
   - Eliminar archivos maliciosos
   - Revertir cambios de registry
   - Restaurar archivos cifrados (ransomware)
```

**Herramientas EDR:**

```
• CrowdStrike Falcon: Cloud-native, detección AI
• Microsoft Defender for Endpoint: Integrado con Windows
• SentinelOne: Autonomous response
• Carbon Black (VMware): Enterprise
• Cortex XDR (Palo Alto): XDR (Extended Detection and Response)
```

#### Sandbox

**Función:** Ejecutar archivos/URLs sospechosos en entorno aislado para análisis.

```
FLUJO TÍPICO:

Email con adjunto → Gateway de seguridad
                          ↓
              ¿Archivo sospechoso?
                    ↓ SÍ
            Enviar a Sandbox
                    ↓
      [VM aislada ejecuta archivo]
                    ↓
          Monitorear comportamiento:
          • ¿Descarga más malware?
          • ¿Modifica registry?
          • ¿Cifra archivos?
          • ¿Contacta C2 server?
                    ↓
         Generar reporte de amenaza
                    ↓
    ¿Malicioso? → Bloquear + Alerta
    ¿Seguro? → Entregar al usuario

TIPOS:

1. LOCAL SANDBOX
   - En dispositivo de seguridad
   - Rápido pero recursos limitados
   - Ejemplo: Palo Alto WildFire (integrado en NGFW)

2. CLOUD SANDBOX
   - En la nube, recursos ilimitados
   - Análisis profundo
   - Ejemplo: VirusTotal, Joe Sandbox, ANY.RUN

3. HYBRID
   - Pre-análisis local, casos complejos a cloud
```

**Evasión de Sandbox (Técnicas de Malware):**

```
Malware moderno detecta sandbox y cambia comportamiento:

1. Environment Checks:
   - ¿Cantidad de RAM < 4GB? → Sandbox
   - ¿Pocos archivos en disco? → Sandbox
   - ¿Procesos típicos de usuario ausentes? → Sandbox
   → Si detecta sandbox: No ejecutar payload

2. Time Delays:
   - Sleep(2 hours)
   - Sandbox típicamente ejecuta 5-10 min
   → Malware no muestra comportamiento malicioso

3. User Interaction:
   - Requerir clicks, movimientos de mouse
   - Sandbox automatizado no simula usuario real

CONTRAMEDIDA:
- Sandboxes avanzados simulan ambiente real
- Análisis por más tiempo (horas)
- Emulación de actividad de usuario
```

#### DLP (Data Loss Prevention)

**Función:** Prevenir exfiltración de datos sensibles.

```
UBICACIONES DLP:

1. NETWORK DLP
   - Gateway que inspecciona tráfico saliente
   - Ubicación: Perímetro de red
   - Detecta: Envío de datos por email, HTTP, FTP

2. ENDPOINT DLP
   - Agent en laptops/desktops
   - Controla: USB, clipboard, screenshots, impresión
   - Ejemplo: Bloquear copiar SSN a USB

3. CLOUD DLP
   - Protege datos en SaaS (Google Drive, Dropbox, Office 365)
   - API integration

MÉTODOS DE DETECCIÓN:

1. Pattern Matching (Regex):
   - SSN: \d{3}-\d{2}-\d{4}
   - Tarjetas de crédito: \d{4}[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{4}

2. Dictionary/Keyword:
   - Buscar palabras: "CONFIDENCIAL", "SECRETO"

3. Fingerprinting:
   - Hash de documento sensible
   - Detectar envío de archivo exacto o fragmento

4. Machine Learning:
   - Clasificar documentos por contexto
   - "Este documento contiene información médica"

ACCIONES:

• BLOCK: Prevenir envío
• QUARANTINE: Enviar a revisión admin
• ENCRYPT: Cifrar automáticamente
• ALERT: Permitir pero notificar
• WATERMARK: Agregar marca de agua con usuario/timestamp
```

#### XDR (Extended Detection and Response)

**Función:** Evolución de EDR, correlación entre endpoint, red, cloud, email.

```
EDR: Solo endpoints
```

### AAA (Authentication, Authorization, Accounting)

AAA es el estándar enterprise para gestión de acceso. Centraliza autenticación en servidor RADIUS o TACACS+.

#### Arquitectura AAA

```
[Usuario] → [Dispositivo de Red] → [Servidor AAA] → [Base de Datos]
              (Cisco Router)         (FreeRADIUS)     (LDAP/AD)
              
Flujo de autenticación:
1. Usuario ingresa credenciales en router
2. Router envía credenciales a servidor AAA (cifradas)
3. Servidor AAA valida contra AD/LDAP
4. Servidor responde: Accept/Reject + nivel de privilegio
5. Router otorga o niega acceso
6. Todas las acciones se registran (Accounting)
```

#### Configuración AAA con TACACS+ (Cisco)

```cisco
! Habilitar AAA
aaa new-model

! Configurar servidor TACACS+
tacacs-server host 10.10.10.100 key T@c@cs!K3y2026
tacacs-server timeout 5

! Configurar autenticación
aaa authentication login default group tacacs+ local
! Primero intenta TACACS+, si falla usa usuarios locales (fallback)

aaa authentication enable default group tacacs+ enable
! Enable mode también autenticado con TACACS+

! Configurar autorización (qué comandos puede ejecutar)
aaa authorization exec default group tacacs+ local
aaa authorization commands 15 default group tacacs+ local

! Configurar accounting (auditoría de comandos)
aaa accounting exec default start-stop group tacacs+
aaa accounting commands 15 default start-stop group tacacs+
! Registra todos los comandos de nivel 15 (enable mode)

! Usuario local de emergencia (si TACACS+ falla)
username emergency privilege 15 secret Emerg3ncy!2026
```

**Ventajas de AAA:**
- Autenticación centralizada (1 usuario para todos los dispositivos)
- Políticas de contraseña corporativas (complejidad, rotación)
- Auditoría completa (quién ejecutó qué comando y cuándo)
- Revocación inmediata (empleado despedido = deshabilitar 1 cuenta)
- Integración con AD (Single Sign-On)

### Script de Auditoría de Configuración AAA

```python
#!/usr/bin/env python3
"""
Auditar configuraciones de seguridad en dispositivos Cisco
Verifica: AAA habilitado, SSH v2, no telnet, enable secret, etc.
"""

from netmiko import ConnectHandler
import csv
from datetime import datetime

def audit_device(ip, username, password):
    """Auditar un dispositivo Cisco IOS"""
    
    device = {
        'device_type': 'cisco_ios',
        'ip': ip,
        'username': username,
        'password': password,
    }
    
    results = {
        'device': ip,
        'timestamp': datetime.now().strftime("%Y-%m-%d %H:%M"),
        'aaa_enabled': False,
        'ssh_version': 'Unknown',
        'telnet_allowed': True,
        'enable_secret_configured': False,
        'password_encryption': False,
        'exec_timeout': 'Not configured',
        'issues': []
    }
    
    try:
        conn = ConnectHandler(**device)
        
        # Obtener running-config
        config = conn.send_command("show running-config")
        
        # Verificar AAA
        if 'aaa new-model' in config:
            results['aaa_enabled'] = True
        else:
            results['issues'].append("AAA no habilitado")
        
        # Verificar SSH version
        ssh_output = conn.send_command("show ip ssh")
        if 'version 2.0' in ssh_output:
            results['ssh_version'] = '2.0'
        elif 'SSH Disabled' in ssh_output:
            results['ssh_version'] = 'Disabled'
            results['issues'].append("SSH deshabilitado")
        else:
            results['ssh_version'] = '1.x'
            results['issues'].append("SSH v1 inseguro, actualizar a v2")
        
        # Verificar Telnet
        if 'transport input ssh' in config:
            results['telnet_allowed'] = False
        elif 'transport input telnet' in config or 'transport input all' in config:
            results['issues'].append("Telnet permitido (inseguro)")
        
        # Verificar enable secret
        if 'enable secret 5' in config or 'enable secret 9' in config:
            results['enable_secret_configured'] = True
        else:
            results['issues'].append("Enable secret no configurado")
        
        # Verificar password encryption
        if 'service password-encryption' in config:
            results['password_encryption'] = True
        else:
            results['issues'].append("Cifrado de contraseñas no habilitado")
        
        # Verificar exec-timeout en VTY
        import re
        vty_section = re.search(r'line vty.*?(?=line|!)', config, re.DOTALL)
        if vty_section:
            timeout_match = re.search(r'exec-timeout (\d+) (\d+)', vty_section.group())
            if timeout_match:
                minutes = timeout_match.group(1)
                results['exec_timeout'] = f"{minutes} minutos"
                if int(minutes) > 15 or int(minutes) == 0:
                    results['issues'].append(f"Timeout muy largo: {minutes} min (recomendado: 5-15)")
            else:
                results['issues'].append("Exec-timeout no configurado (sin timeout)")
        
        conn.disconnect()
        
    except Exception as e:
        results['issues'].append(f"Error conectando: {str(e)}")
    
    return results

def generate_report(devices, output_file='audit_report.csv'):
    """Generar reporte CSV de auditoría"""
    
    fieldnames = ['device', 'timestamp', 'aaa_enabled', 'ssh_version', 
                  'telnet_allowed', 'enable_secret_configured', 
                  'password_encryption', 'exec_timeout', 'issues']
    
    with open(output_file, 'w', newline='') as f:
        writer = csv.DictWriter(f, fieldnames=fieldnames)
        writer.writeheader()
        writer.writerows(devices)
    
    print(f"Reporte generado: {output_file}")

# Ejecución
if __name__ == "__main__":
    # Lista de dispositivos a auditar
    device_list = [
        '192.168.1.1',
        '192.168.1.2',
        '192.168.1.3',
    ]
    
    username = 'auditor'
    password = 'Audit0r!P@ss'
    
    results = []
    for ip in device_list:
        print(f"Auditando {ip}...")
        result = audit_device(ip, username, password)
        results.append(result)
        
        # Imprimir issues en pantalla
        if result['issues']:
            print(f"  ⚠️  {len(result['issues'])} problemas encontrados:")
            for issue in result['issues']:
                print(f"     - {issue}")
        else:
            print(f"  ✓ Sin problemas")
    
    # Generar reporte CSV
    generate_report(results)
```

```
✓ Deshabilitar servicios innecesarios
✓ Configurar banners legales
✓ Deshabilitar CDP/LLDP en interfaces externas

✓ Deshabilitar HTTP, usar HTTPS
✓ Proteger contra ataques de red comunes
```

```cisco
no ip gratuitous-arps
```

### Protección del Plano de Control (CoPP)

Control Plane Policing protege la CPU del router limitando tráfico destinado **al propio router** (no tráfico que pasa por él).

```cisco
! Clasificar tráfico al plano de control
ip access-list extended ACL-MANAGEMENT
 permit tcp 10.10.10.0 0.0.0.255 any eq 22     ! SSH desde red de gestión
 permit udp 10.10.10.0 0.0.0.255 any eq snmp   ! SNMP desde red de gestión
 deny   ip any any log                          ! Log intentos no autorizados

ip access-list extended ACL-ROUTING-PROTOCOLS
 permit ospf any any
 permit pim any any
 permit igmp any any

ip access-list extended ACL-ICMP
 permit icmp any any echo        ! Ping
 permit icmp any any echo-reply
 permit icmp any any ttl-exceeded
 permit icmp any any unreachable

! Definir clases de tráfico
class-map match-any CM-MANAGEMENT
 match access-group name ACL-MANAGEMENT

class-map match-any CM-ROUTING
 match access-group name ACL-ROUTING-PROTOCOLS

class-map match-any CM-ICMP
 match access-group name ACL-ICMP

! Política de CoPP
policy-map PM-COPP
 class CM-MANAGEMENT
  police 1000000 31250 31250 conform-action transmit exceed-action drop
  ! 1 Mbps para gestión
  
 class CM-ROUTING
  police 10000000 31250 31250 conform-action transmit exceed-action drop
  ! 10 Mbps para protocolos de routing
  
 class CM-ICMP
  police 500000 31250 31250 conform-action transmit exceed-action drop
  ! 500 Kbps para ICMP (prevenir ping floods)
  
 class class-default
  police 100000 31250 31250 conform-action transmit exceed-action drop
  ! 100 Kbps para todo lo demás

! Aplicar política al plano de control
control-plane
 service-policy input PM-COPP
```

**Resultado:**
- Ataque de 10 Gbps de pings → Router solo procesa 500 Kbps, resto se descarta
- CPU protegida, servicios legítimos continúan funcionando

### Protección contra Ataques Comunes

```cisco
ip tcp intercept mode watch
ip tcp intercept watch-timeout 30
ip tcp intercept max-incomplete high 500
ip tcp intercept max-incomplete low 400

access-list ACL-SERVERS permit tcp any 10.20.30.0 0.0.0.255

! Logging con rate-limit
logging buffered 51200 warnings
logging rate-limit console 10 except errors
! Prevenir DoS por syslog flood
```

## 1.5.3 Seguridad Perimetral (Firewalls y ACLs)

El perímetro de red es la frontera entre red interna (confiable) y externa (Internet no confiable).

### Access Control Lists (ACLs) - Filtrado Básico

```cisco
! ACL Estándar (solo IP origen)
! Formato: access-list <1-99> {permit|deny} <source> <wildcard>

access-list 10 permit 192.168.10.0 0.0.0.255
access-list 10 deny any log

interface GigabitEthernet0/0
 ip access-group 10 in

! ACL Extendida (origen, destino, protocolo, puerto)
! Más granular, preferida para seguridad

ip access-list extended ACL-INBOUND-INTERNET
 ! Permitir tráfico establecido (respuestas a conexiones salientes)
 permit tcp any any established
 
 ! Permitir servicios públicos
```

### Zone-Based Firewall (ZBFW)

Firewall stateful en Cisco IOS, más avanzado que ACLs.

```cisco
! PASO 1: Definir zonas de seguridad
zone security INSIDE
zone security OUTSIDE
zone security DMZ

! PASO 2: Definir class-maps (qué tráfico)
class-map type inspect match-any CM-INSIDE-TO-OUTSIDE
 match protocol tcp
 match protocol udp
 match protocol icmp

class-map type inspect match-all CM-OUTSIDE-TO-DMZ-WEB
 match protocol http
 match protocol https

! PASO 3: Definir policy-maps (qué hacer con tráfico)
policy-map type inspect PM-INSIDE-TO-OUTSIDE
 class type inspect CM-INSIDE-TO-OUTSIDE
  inspect                   ! Stateful inspection
  
policy-map type inspect PM-OUTSIDE-TO-DMZ
 class type inspect CM-OUTSIDE-TO-DMZ-WEB
  inspect
 class class-default
  drop log                  ! Bloquear y loggear todo lo demás

! PASO 4: Definir zone-pairs (dirección de tráfico)
zone-pair security ZP-INSIDE-TO-OUTSIDE source INSIDE destination OUTSIDE
 service-policy type inspect PM-INSIDE-TO-OUTSIDE

zone-pair security ZP-OUTSIDE-TO-DMZ source OUTSIDE destination DMZ
 service-policy type inspect PM-OUTSIDE-TO-DMZ

! PASO 5: Asignar interfaces a zonas
interface GigabitEthernet0/0
 description WAN - Internet
 zone-member security OUTSIDE

interface GigabitEthernet0/1
 description LAN Interna
 zone-member security INSIDE

interface GigabitEthernet0/2
 description DMZ - Servidores Web
 zone-member security DMZ
```

**Comportamiento:**
- INSIDE → OUTSIDE: Todo tráfico permitido (inspect = stateful)
- OUTSIDE → INSIDE: Bloqueado (no hay zone-pair definido)
- OUTSIDE → DMZ: Solo HTTP/HTTPS permitido
- Respuestas automáticamente permitidas (stateful inspection)

## 1.5.4 VPNs y Cifrado

VPN (Virtual Private Network) crea túnel cifrado sobre red pública (Internet).

### Tipos de VPN

```
SITE-TO-SITE (Router-to-Router):
- Conecta dos redes remotamente
- Siempre activo
- Transparente para usuarios
- Uso: Conectar sucursales a oficina central

REMOTE ACCESS (User-to-Network):
- Conecta usuario individual
- Activación bajo demanda
- Cliente VPN requerido
- Uso: Teletrabajo, acceso remoto

PROTOCOLOS:
- IPsec: Estándar industrial, complejo configurar
- SSL/TLS VPN: Basado en web, más simple
- WireGuard: Moderno, rápido, simple
- OpenVPN: Open source, versátil
```

### IPsec Site-to-Site VPN (Cisco)

```
TOPOLOGÍA:
Oficina Central ← Internet → Sucursal Remota
192.168.1.0/24                 192.168.2.0/24
Router-HQ                      Router-Branch
200.1.1.1 (WAN)               200.2.2.1 (WAN)
```

**Configuración Router-HQ:**

```cisco
! PASO 1: Definir tráfico a cifrar (interesting traffic)
ip access-list extended ACL-VPN-TRAFFIC
 permit ip 192.168.1.0 0.0.0.255 192.168.2.0 0.0.0.255

! PASO 2: Configurar ISAKMP Phase 1 (establecer túnel seguro)
crypto isakmp policy 10
 encryption aes 256
 authentication pre-share
 group 5
 hash sha256
 lifetime 86400

! PASO 3: Configurar pre-shared key
crypto isakmp key VPN!Pr3Sh@r3dK3y address 200.2.2.1

! PASO 4: Configurar IPsec Phase 2 (cifrado de datos)
crypto ipsec transform-set TS-VPN esp-aes 256 esp-sha256-hmac
 mode tunnel

! PASO 5: Configurar crypto map
crypto map CM-VPN 10 ipsec-isakmp
 set peer 200.2.2.1
 set transform-set TS-VPN
 match address ACL-VPN-TRAFFIC

! PASO 6: Aplicar crypto map a interfaz WAN
interface GigabitEthernet0/0
 description WAN - Internet
 ip address 200.1.1.1 255.255.255.0
 crypto map CM-VPN

! PASO 7: Configurar ruta hacia red remota (a través de túnel)
ip route 192.168.2.0 255.255.255.0 200.2.2.1
```

### Monitoreo de Certificados SSL/TLS

```python
#!/usr/bin/env python3
"""
Monitorear expiración de certificados SSL
Alerta si certificado expira en < 30 días
"""

import ssl
import socket
from datetime import datetime, timedelta

def check_ssl_expiry(hostname, port=443):
    """Verificar fecha de expiración de certificado SSL"""
    
    context = ssl.create_default_context()
    
    try:
        with socket.create_connection((hostname, port), timeout=10) as sock:
            with context.wrap_socket(sock, server_hostname=hostname) as ssock:
                cert = ssock.getpeercert()
                
                # Extraer fecha de expiración
                expiry_date_str = cert['notAfter']
                expiry_date = datetime.strptime(expiry_date_str, '%b %d %H:%M:%S %Y %Z')
                
                # Calcular días restantes
                days_remaining = (expiry_date - datetime.now()).days
                
                return {
                    'hostname': hostname,
                    'issuer': dict(x[0] for x in cert['issuer']),
                    'subject': dict(x[0] for x in cert['subject']),
                    'expiry_date': expiry_date,
                    'days_remaining': days_remaining,
                    'status': 'OK' if days_remaining > 30 else 'WARNING' if days_remaining > 7 else 'CRITICAL'
                }
    
    except Exception as e:
        return {
            'hostname': hostname,
            'error': str(e),
            'status': 'ERROR'
        }

# Monitorear múltiples sitios
sites = [
    'www.empresa.com',
    'vpn.empresa.com',
    'mail.empresa.com',
]

print("SSL Certificate Expiry Check")
print("=" * 70)

for site in sites:
    result = check_ssl_expiry(site)
    
    if 'error' in result:
        print(f"❌ {result['hostname']}: ERROR - {result['error']}")
    else:
        status_icon = {
            'OK': '✓',
            'WARNING': '⚠️',
            'CRITICAL': '🔴'
        }[result['status']]
        
        print(f"{status_icon} {result['hostname']}")
        print(f"   Issuer: {result['issuer']['organizationName']}")
        print(f"   Expires: {result['expiry_date'].strftime('%Y-%m-%d')}")
        print(f"   Days remaining: {result['days_remaining']}")
        print(f"   Status: {result['status']}")
        print()
```

```
   - Contraseñas fuertes y AAA previenen más que IPS caros
   
2. Segmentación es crítica
   - Atacante accedió a toda la red desde un switch de sucursal
   
3. Monitoreo proactivo vs reactivo
   - Sin logs, imposible saber qué pasó
   
4. Backups offline son obligatorios
   - Backups en red = Vulnerables al mismo ataque
   
5. Plan de respuesta debe existir ANTES del incidente
   - Caos organizativo sumó 8 horas de downtime innecesario
   
6. Seguridad = Inversión, no gasto
   - $160k prevención << $5M remediación
   
7. Cultura de seguridad
   - Tecnología es inútil si usuarios ignoran políticas
```

### Caso 2: Migración a Zero Trust Architecture

**Empresa:** Tecnología, 2,000 empleados, 50% teletrabajo

**Problema del Modelo Tradicional:**

```
MODELO "CASTLE AND MOAT":
- Perímetro fuerte (firewall)
- Interior "confiable" (sin verificación)

PROBLEMAS:
1. Usuarios remotos = VPN = Acceso total a red interna
2. Dispositivos BYOD sin control
3. Movimiento lateral sin restricciones
4. No diferencia usuario vs comportamiento
```

**Solución: Zero Trust Network Access (ZTNA)**

```
PRINCIPIOS:
1. "Never trust, always verify"
   - Autenticar TODO: Usuario + Dispositivo + Ubicación + Contexto
   
2. Least Privilege Access
   - Acceso mínimo necesario por aplicación, no por red
   
3. Micro-segmentación
   - Segmentos de 1 aplicación (no VLANs grandes)
   
4. Verificación continua
   - Re-autenticar periódicamente
   - Analizar comportamiento en tiempo real
```

**Implementación:**

```
ARQUITECTURA:

[Usuario] → [Verificación de Identidad] → [Verificación de Dispositivo]
                    ↓
          [Análisis de Contexto]
                    ↓
     [Policy Engine: ¿Permitir?]
                    ↓
          [Acceso a App Específica]
          
COMPONENTES:
- Cisco Duo (MFA + Device Trust)
- Cloudflare Access (ZTNA Gateway)
- CrowdStrike (EDR - Verificación de endpoint)
- Splunk (SIEM - Análisis de comportamiento)
```

**Políticas Implementadas:**

```yaml
# Ejemplo: Acceso a ERP interno

Policy: Access-ERP-Production
  User: 
    - Must be in group: finance, accounting
    - MFA: Required (push notification)
  
  Device:
    - OS: Windows 10/11 or macOS 12+
    - Encryption: Full disk encryption required
    - EDR: CrowdStrike agent running, no threats detected
    - Patch level: < 30 days old
  
  Context:
    - Location: Office network OR approved country
    - Time: Business hours (08:00-20:00 local)
    - Risk score: < 50 (calculado por IA)
  
  Access:
    - Protocol: HTTPS only
    - Duration: 8 hours, re-auth required
    - Network: No direct network access (app-level only)
  
  Action on violation:
    - Deny access
    - Alert security team
    - Require admin approval for override

# Comportamiento anómalo
Anomaly-Detection:
  - Login from new country → Require additional verification
  - Data download >1GB → Require manager approval
  - Login 02:00-06:00→ Alert + Session recording
  - Failed auth >3 times → Lock account 30 min
```

**Resultados:**

```
SEGURIDAD:
- Superficie de ataque: Reducida 75%
- Tiempo de detección de amenaza: 4 horas → 12 minutos
- Movimiento lateral bloqueado: 98% efectividad
- Phishing exitoso: 0 (MFA bloqueó todos los intentos)

EXPERIENCIA USUARIO:
- Quejas iniciales: Altas (cambio cultural)
- 3 meses después: Satisfacción 85%
- Menos VPN issues (no dependen de VPN tradicional)

OPERACIONES:
- Onboarding nuevo empleado: 3 días → 2 horas
- Offboarding: Revocación inmediata (antes: 24-48h)
- Audit trail: Completo (quién accedió a qué, cuándo, desde dónde)

COSTOS:
- CAPEX inicial: $250k (licencias, implementación)
- OPEX anual: $120k (suscripciones)
- Ahorro VPN hardware: $40k/año (eliminado)
- Ahorro en incidentes: $500k/año (proyectado)
- ROI Año 1: 45%
- ROI Año 3: 315%
```

### Mejores Prácticas de Seguridad en Redes

```
1. DEFENSE IN DEPTH (Múltiples capas)
   - Una sola tecnología nunca es suficiente
   - Combinar: Firewall + IPS + EDR + SIEM + Capacitación
   
2. PATCH MANAGEMENT RIGUROSO
   - 80% de brechas explotan vulnerabilidades conocidas
   - Parchear sistemas críticos en < 72h de CVE publicado
   - Test en lab, luego producción
   
3. SEGMENTACIÓN DE RED
   - VLANs por función (usuarios, servidores, IoT, invitados)
   - ACLs entre segmentos
   - Micro-segmentación para aplicaciones críticas
   
4. PRINCIPIO DE MÍNIMO PRIVILEGIO
   - Usuarios: Solo acceso necesario
   - Servicios: Solo puertos necesarios abiertos
   - Duración: Acceso temporal cuando sea posible
   
5. MONITOREO 24/7
   - SIEM con correlación de eventos
   - Alertas automáticas para anomalías
   - SOC (Security Operations Center) o outsource
   
6. BACKUPS INMUTABLES Y OFFSITE
   - 3-2-1 rule: 3 copias, 2 medios, 1 offsite
   - 1 copia air-gapped (sin conexión a red)
   - Pruebas de restauración regulares
   
7. AUTENTICACIÓN FUERTE
   - MFA para TODO (VPN, admin access, aplicaciones críticas)
   - Passwords complejos (12+ caracteres, no palabras de diccionario)
   - Rotación de credenciales
   
8. CIFRADO
   - Datos en tránsito: TLS 1.2+ (no SSL, no TLS 1.0/1.1)
   - Datos en reposo: Full disk encryption
   - VPNs: IPsec o WireGuard (no PPTP, no L2TP sin IPsec)
   
9. GESTIÓN DE CAMBIOS
   - Documentar TODO cambio
   - Peer review de cambios críticos
   - Rollback plan antes de implementar
   - Change windows definidas
   
10. CAPACITACIÓN CONTINUA
    - Entrenamiento anual obligatorio
    - Simulacros de phishing
    - Comunicación de amenazas actuales
    - Cultura de "ver algo, decir algo"
    
11. INCIDENT RESPONSE PLAN
    - Playbooks por tipo de incidente
    - Equipo de respuesta con roles claros
    - Contactos actualizados (legal, PR, forensics)
    - Simulacros regulares
    
12. COMPLIANCE Y AUDITORÍA
    - Conocer regulaciones aplicables (PCI-DSS, GDPR, HIPAA)
    - Auditorías internas trimestrales
    - Auditorías externas anuales
    - Documentar TODO
```

### Errores Comunes (Evitar)

```
❌ ERROR: "Tenemos firewall, estamos seguros"
   ✓ CORRECTO: Firewall = 1 capa, necesitas defensa en profundidad

❌ ERROR: Deshabilitar seguridad por "performance" o "usabilidad"
   ✓ CORRECTO: Optimizar configuración, no deshabilitar

❌ ERROR: Contraseñas compartidas entre equipo
   ✓ CORRECTO: Cuenta individual por persona + AAA

❌ ERROR: No actualizar firmware "si funciona, no lo toques"
   ✓ CORRECTO: Patches de seguridad = Críticos, no opcionales

❌ ERROR: Confiar ciegamente en red interna
   ✓ CORRECTO: Zero Trust, verificar siempre

❌ ERROR: Backups en misma red que producción
   ✓ CORRECTO: Backups offline, air-gapped

❌ ERROR: Solo monitorear perímetro, ignorar tráfico interno
   ✓ CORRECTO: Monitorear Este-Oeste (interno) y Norte-Sur (perimetral)

❌ ERROR: No tener plan de respuesta a incidentes
   ✓ CORRECTO: Plan documentado, probado, equipo entrenado

❌ ERROR: Seguridad = Problema de TI solamente
   ✓ CORRECTO: Seguridad = Responsabilidad de toda la organización

❌ ERROR: No loggear cambios de configuración
   ✓ CORRECTO: Audit trail completo, quién cambió qué y cuándo
```

## Conclusión: Seguridad como Proceso Continuo

La seguridad de red **nunca termina**. Las amenazas evolucionan constantemente, y lo que es seguro hoy puede ser vulnerable mañana.

### Ciclo de Vida de Seguridad

```
1. IDENTIFY (Identificar)
   - ¿Qué tenemos?
   - ¿Qué es crítico?
   - ¿Cuáles son los riesgos?

2. PROTECT (Proteger)
   - Implementar controles
   - Hardening de sistemas
   - Capacitación de usuarios

3. DETECT (Detectar)
   - Monitoreo 24/7
   - Alertas automáticas
   - Threat intelligence

4. RESPOND (Responder)
   - Contener incidente
   - Erradicar amenaza
   - Recuperar servicios

5. RECOVER (Recuperar)
   - Restaurar desde backups
   - Validar integridad
   - Retomar operaciones

6. LEARN (Aprender)
   - Post-mortem
   - Actualizar controles
   - Mejorar procesos

→ REPEAT (Ciclo continuo)
```

### Métricas Clave de Seguridad

```
PREVENTIVAS:
- % de dispositivos con contraseñas fuertes
- % de patches aplicados en SLA
- Tiempo promedio de remediación de vulnerabilidades

DETECCIÓN:
- Tiempo promedio de detección (MTTD)
- Número de falsos positivos/negativos
- % de tráfico inspeccionado

RESPUESTA:
- Tiempo promedio de respuesta (MTTR)
- % de incidentes contenidos en <1h
- Escalamientos a nivel ejecutivo

IMPACTO:
- Número de incidentes por trimestre
- Costo promedio por incidente
- Downtime causado por seguridad
```
