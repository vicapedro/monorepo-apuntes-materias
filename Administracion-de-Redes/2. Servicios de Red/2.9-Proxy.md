# 2.9 Servidores Proxy

> **💡 NOTA IMPORTANTE**: Los proxies se confunden frecuentemente con **VPNs**, pero tienen propósitos diferentes. Un proxy **intercepta tráfico a nivel aplicación** (HTTP/HTTPS), mientras que una VPN **cifra todo el tráfico de red** a nivel IP. Ambos pueden usarse para bypass de restricciones geográficas, pero con diferencias importantes en seguridad, rendimiento y casos de uso.

## Descripción

### ¿Qué es un servidor proxy?

Un **proxy** (del inglés "apoderado" o "intermediario") es un servidor que actúa como **intermediario** entre un cliente y otro servidor. Intercepta las peticiones del cliente, las procesa (opcionalmente modifica), y las reenvía al servidor destino.

**Tipos principales de proxies:**

1. **Forward Proxy** (Proxy tradicional): Cliente → Proxy → Internet
2. **Reverse Proxy**: Internet → Proxy → Servidores backend
3. **Transparent Proxy**: Cliente no sabe que existe (interceptación automática)

### Forward Proxy (Proxy de Salida)

```
┌─────────────────────────────────────────────────────────────────┐

│        │               │               │                        │

│              ┌─────────────────────┐                            │
```

**Casos de uso de Forward Proxy:**
- ✅ **Control de acceso**: Bloquear sitios web (redes sociales, streaming)
- ✅ **Filtrado de contenido**: Prevenir acceso a contenido inapropiado
- ✅ **Autenticación**: Requerir login para acceder a Internet
- ✅ **Cache**: Acelerar acceso a sitios frecuentes
- ✅ **Logging**: Auditoría de navegación (compliance)
- ✅ **Bypass de restricciones**: Acceder a contenido bloqueado (uso polémico)
- ✅ **Anonimato**: Ocultar IP real del cliente

**Casos de uso de Reverse Proxy:**
- ✅ **Load balancing**: Distribuir carga entre múltiples servidores
- ✅ **SSL/TLS termination**: Descifrar HTTPS en proxy, HTTP interno
- ✅ **Caching**: Servir contenido estático sin tocar backend
- ✅ **Compresión**: Gzip/Brotli automático
- ✅ **Seguridad**: WAF, rate limiting, hide backend IPs
- ✅ **Microservicios**: API Gateway para múltiples servicios
- ✅ **A/B Testing**: Rutear tráfico a diferentes versiones

### Transparent Proxy (Proxy Transparente)

El cliente **no sabe** que existe un proxy. El tráfico es interceptado automáticamente en el firewall/router.

```
Cliente                 Firewall/Router             Proxy           Internet
   │                           │                      │                │
   │  GET http://example.com   │                      │                │
   ├──────────────────────────>│                      │                │
   │                           │ iptables REDIRECT    │                │
   │                           ├─────────────────────>│                │
   │                           │                      │                │
   │                           │                      │ GET (forwarded)│
   │                           │                      ├───────────────>│
   │                           │                      │                │
   │                           │                      │ Response       │
   │                           │                      │<───────────────┤
   │                           │                      │                │
   │                           │ Response (forwarded) │                │
   │                           │<─────────────────────┤                │
   │  Response                 │                      │                │
   │<──────────────────────────┤                      │                │
```

**Configuración típica con iptables:**

```bash
# Interceptar puerto 80 y redirigir a Squid (puerto 3128)
iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 \
  -j REDIRECT --to-port 3128
```

### Proxy vs VPN - Diferencias Fundamentales

| Aspecto | Proxy | VPN |
|---------|-------|-----|
| **Nivel de operación** | Aplicación (HTTP/HTTPS) | Red (IP) |
| **Cifrado** | ❌ No (excepto HTTPS) | ✅ Todo el tráfico cifrado |
| **Protocolos soportados** | HTTP, HTTPS, FTP, SOCKS | ✅ Todos (TCP/UDP/ICMP) |
| **Configuración** | Por aplicación | Sistema completo |
| **Rendimiento** | Más rápido (menos overhead) | Más lento (cifrado) |
| **Anonimato** | IP oculta (logs en proxy) | IP oculta + cifrado |
| **Bypass geo-restricciones** | ✅ Sí (HTTP/HTTPS) | ✅ Sí (todo) |
| **Uso típico** | Cache, filtrado corporativo | Privacidad, acceso remoto |
| **Costo** | Gratis o bajo | Gratis (limitado) o suscripción |
| **Trust model** | Proxy ve todo en claro | VPN ve todo (cifrado hasta ella) |

**Ejemplo visual - Proxy vs VPN:**

```
┌─────────────────────────────────────────────────────────────────┐
│                        PROXY (HTTP Only)                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  Cliente ──HTTP claro──> Proxy ──HTTP claro──> Servidor         │
│           (navegador)    (ve todo)             (ve IP proxy)     │
│                                                                   │
│  ❌ DNS: ISP puede ver                                           │
│  ❌ HTTPS: Cliente→Proxy cifrado, pero proxy puede MITM         │
│  ❌ Otros protocolos: No pasan por proxy                         │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                       VPN (Todo el tráfico)                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  Cliente ══════════════════════════> Servidor VPN ─────> Internet│
│         (túnel cifrado completo)      (ve todo)   (ve IP VPN)   │
│                                                                   │
│  ✅ DNS: Pasa por VPN (ISP no ve)                                │
│  ✅ Todos los protocolos: HTTP, HTTPS, SSH, Gaming, P2P         │
│  ✅ IP real completamente oculta                                 │
│  ⚠️  VPN provider ve TODO (elige provider confiable)            │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

**Cuándo usar Proxy:**
- ✅ Solo necesitas acceder a sitios web bloqueados
- ✅ Quieres cache corporativo para acelerar navegación
- ✅ Filtrado de contenido en red empresarial/escolar
- ✅ Scraping web (rotar IPs fácilmente)
- ✅ Bajo presupuesto (proxies gratis abundan)

**Cuándo usar VPN:**
- ✅ Privacidad completa (ISP no ve nada)
- ✅ Trabajo remoto seguro (acceso a red corporativa)
- ✅ WiFi público (protección contra sniffing)
- ✅ Gaming con latencia específica de región
- ✅ Torrents / P2P (proxy no sirve)
- ✅ Bypass de censura gubernamental (más robusto)

### SOCKS Proxy

SOCKS es un protocolo de proxy que opera a **nivel de sesión** (más bajo que HTTP).

**SOCKS4 vs SOCKS5:**

| Característica | SOCKS4 | SOCKS5 |
|----------------|--------|--------|
| **Autenticación** | ❌ No | ✅ Username/password |
| **IPv6** | ❌ No | ✅ Sí |
| **UDP** | ❌ No (solo TCP) | ✅ Sí |
| **DNS remoto** | ❌ No | ✅ Sí |
| **Uso típico** | Legacy | Moderno |

**Casos de uso de SOCKS5:**
- Torrents (necesita UDP)
- Gaming
- SSH tunneling
- Aplicaciones que no soporten HTTP proxy

**Ejemplo de SSH como SOCKS proxy:**

```bash
# Crear túnel SOCKS5 vía SSH
ssh -D 8080 usuario@servidor-remoto.com

# Configurar navegador:
# SOCKS Host: localhost
# Puerto: 8080
# Tipo: SOCKS v5

# Todo el tráfico del navegador pasa por SSH (cifrado)
```

#### Configuración básica de Squid

```bash
# Backup de configuración original
sudo cp /etc/squid/squid.conf /etc/squid/squid.conf.backup

# Editar configuración
sudo nano /etc/squid/squid.conf
```

**Configuración mínima funcional:**

```conf
# /etc/squid/squid.conf

# Puerto de escucha
http_port 3128

# ACL para red local (cambiar según tu red)
acl localnet src 192.168.1.0/24
acl localnet src 10.0.0.0/8

# ACL para puertos seguros (HTTPS)
acl SSL_ports port 443
acl Safe_ports port 80          # http
acl Safe_ports port 443         # https
acl Safe_ports port 21          # ftp
acl Safe_ports port 1025-65535  # puertos altos

# Método CONNECT (para HTTPS)
acl CONNECT method CONNECT

# Reglas de acceso
# Denegar puertos no seguros
http_access deny !Safe_ports

# Denegar CONNECT a puertos que no sean SSL
http_access deny CONNECT !SSL_ports

# Permitir localhost (para gestión)
http_access allow localhost

# Permitir red local
http_access allow localnet

# Denegar todo lo demás
http_access deny all

# Cache (1GB)
cache_dir ufs /var/spool/squid 1024 16 256

# Logs
access_log /var/log/squid/access.log squid

# Hostname visible
visible_hostname proxy.ejemplo.com

# Ocultar información de versión (seguridad)
httpd_suppress_version_string on
```

**Aplicar configuración:**

```bash
# Verificar sintaxis
sudo squid -k parse

# Inicializar cache (primera vez)
sudo squid -z

# Reiniciar Squid
sudo systemctl restart squid

# Ver logs en tiempo real
sudo tail -f /var/log/squid/access.log
```

#### Configurar autenticación en Squid

**Autenticación básica (username/password):**

```bash
# Instalar herramienta de passwords

# Crear archivo de passwords

# Configurar Squid para autenticación
sudo nano /etc/squid/squid.conf
```

```conf
# Autenticación básica
auth_param basic program /usr/lib/squid/basic_ncsa_auth /etc/squid/passwords
auth_param basic realm Proxy - Ingrese usuario y password
auth_param basic credentialsttl 2 hours

# ACL para usuarios autenticados
acl authenticated proxy_auth REQUIRED

# Regla de acceso (después de otras reglas)
http_access allow localnet authenticated
http_access deny all
```

#### Proxy transparente con iptables

**ADVERTENCIA**: Transparent proxy intercepta tráfico sin conocimiento del usuario. **Implicaciones legales** en algunos países. Solo usar en redes corporativas/escolares propias.

```bash
# Habilitar IP forwarding
sudo sysctl -w net.ipv4.ip_forward=1
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf

# Configurar Squid para modo transparente
sudo nano /etc/squid/squid.conf
```

```conf
# Puerto transparente
http_port 3128
http_port 3129 intercept

# ACLs (mismo que antes)
acl localnet src 192.168.1.0/24
http_access allow localnet
http_access deny all
```

```bash
# Configurar iptables para redireccionar tráfico
sudo iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 \
  -j REDIRECT --to-port 3129

# Persistir reglas (Ubuntu)
sudo apt install iptables-persistent -y
sudo netfilter-persistent save

# Reiniciar Squid
sudo systemctl restart squid
```

**Ahora los clientes en 192.168.1.0/24 usan proxy automáticamente sin configurarlo.**

### 2. Nginx como Reverse Proxy

**Configuración básica de reverse proxy:**

```bash
sudo nano /etc/nginx/sites-available/reverse-proxy
```

```nginx
# Reverse proxy básico
upstream backend_servers {
    # Round-robin por defecto
    server 192.168.1.10:8080;
    server 192.168.1.11:8080;
    server 192.168.1.12:8080;
}

server {
    listen 80;
    server_name app.ejemplo.com;

    # Logs
    access_log /var/log/nginx/reverse-proxy-access.log;
    error_log /var/log/nginx/reverse-proxy-error.log;

    location / {
        # Proxy hacia backend
        proxy_pass http://backend_servers;

        # Headers para preservar información del cliente
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Timeouts
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
}
```

```bash
# Habilitar configuración
sudo ln -s /etc/nginx/sites-available/reverse-proxy /etc/nginx/sites-enabled/

# Verificar sintaxis
sudo nginx -t

# Recargar Nginx
sudo systemctl reload nginx
```

#### Load balancing avanzado con Nginx

```nginx
# Diferentes algoritmos de balanceo
upstream backend_weighted {
    # Weighted round-robin
    server 192.168.1.10:8080 weight=3;  # Recibe 3x más tráfico
    server 192.168.1.11:8080 weight=1;
}

upstream backend_leastconn {
    # Least connections (mejor para cargas desiguales)
    least_conn;
    server 192.168.1.10:8080;
    server 192.168.1.11:8080;
}

upstream backend_iphash {
    # IP hash (sticky sessions basado en IP cliente)
    ip_hash;
    server 192.168.1.10:8080;
    server 192.168.1.11:8080;
}

upstream backend_healthcheck {
    # Con health checks
    server 192.168.1.10:8080 max_fails=3 fail_timeout=30s;
    server 192.168.1.11:8080 max_fails=3 fail_timeout=30s;
    server 192.168.1.12:8080 backup;  # Solo si otros fallan
}
```

#### SSL termination en reverse proxy

```nginx
server {
    listen 443 ssl http2;
    server_name app.ejemplo.com;

    # Certificado SSL
    ssl_certificate /etc/ssl/certs/app.ejemplo.com.pem;
    ssl_certificate_key /etc/ssl/private/app.ejemplo.com.key;

    # Configuración SSL segura
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    # HSTS
    add_header Strict-Transport-Security "max-age=31536000" always;

    location / {
        # Backend en HTTP (descifrado en proxy)
        proxy_pass http://backend_servers;
        
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}

# Redirigir HTTP → HTTPS
server {
    listen 80;
    server_name app.ejemplo.com;
    return 301 https://$server_name$request_uri;
}
```

#### Caching en reverse proxy

```nginx
# Definir zona de cache
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=my_cache:10m 
                 max_size=1g inactive=60m use_temp_path=off;

server {
    listen 80;
    server_name static.ejemplo.com;

    location / {
        proxy_pass http://backend_servers;

        # Habilitar cache
        proxy_cache my_cache;
        proxy_cache_valid 200 60m;  # Cachear 200 OK por 60 minutos
        proxy_cache_valid 404 1m;   # Cachear 404 por 1 minuto
        
        # Headers de cache
        add_header X-Cache-Status $upstream_cache_status;

        # Cache bypass para usuarios autenticados
        proxy_cache_bypass $http_authorization;
        proxy_no_cache $http_authorization;
    }

    # No cachear APIs dinámicas
    location /api/ {
        proxy_pass http://backend_servers;
        proxy_no_cache 1;
        proxy_cache_bypass 1;
    }
}
```

### 3. HAProxy (Load Balancer Avanzado)

**Instalación:**

```bash
# Ubuntu
sudo apt install haproxy -y

# Rocky Linux
sudo dnf install haproxy -y

# Verificar versión
haproxy -v
```

**Configuración de HAProxy:**

```bash
sudo nano /etc/haproxy/haproxy.cfg
```

```conf
global
    log /dev/log    local0
    log /dev/log    local1 notice
    chroot /var/lib/haproxy
    stats socket /run/haproxy/admin.sock mode 660 level admin
    stats timeout 30s
    user haproxy
    group haproxy
    daemon

defaults
    log     global
    mode    http
    option  httplog
    option  dontlognull
    timeout connect 5000
    timeout client  50000
    timeout server  50000

# Frontend (recibe conexiones)
frontend http_front
    bind *:80
    stats uri /haproxy?stats
    default_backend http_back

# Backend (servidores)
backend http_back
    balance roundrobin
    option httpchk GET /health  # Health check
    
    server server1 192.168.1.10:8080 check
    server server2 192.168.1.11:8080 check
    server server3 192.168.1.12:8080 check backup

# Frontend HTTPS con SSL termination
frontend https_front
    bind *:443 ssl crt /etc/haproxy/certs/app.pem
    
    # Redirigir HTTP → HTTPS
    redirect scheme https if !{ ssl_fc }
    
    default_backend http_back
```

### 4. Varnish (HTTP Cache Accelerator)

**Instalación:**

```bash
# Ubuntu
sudo apt install varnish -y

# Rocky Linux
sudo dnf install varnish -y
```

**Configuración básica:**

```bash
sudo nano /etc/varnish/default.vcl
```

```vcl
vcl 4.0;

# Backend
backend default {
    .host = "127.0.0.1";
    .port = "8080";
}

# Recepción de request
sub vcl_recv {
    # No cachear POST/PUT/DELETE
    if (req.method != "GET" && req.method != "HEAD") {
        return (pass);
    }

    # No cachear usuarios autenticados
    if (req.http.Authorization || req.http.Cookie) {
        return (pass);
    }

    return (hash);
}

# Antes de entregar al cliente
sub vcl_deliver {
    # Agregar header con status de cache
    if (obj.hits > 0) {
        set resp.http.X-Cache = "HIT";
    } else {
        set resp.http.X-Cache = "MISS";
    }
}
```

## Aspectos de Seguridad

### 1. Proxy como single point of failure

```
Sin proxy:              Con proxy (SPOF):
    ┌───┐                   ┌───┐
    │ C │──> Internet       │ C │──┐
    └───┘                   └───┘  │
    ┌───┐                   ┌───┐  │    ┌─────┐
    │ C │──> Internet  →    │ C │──┼──> │ Proxy│──> Internet
    └───┘                   └───┘  │    └─────┘
    ┌───┐                   ┌───┐  │       ↑
    │ C │──> Internet       │ C │──┘   Si falla = 
    └───┘                   └───┘      nadie tiene Internet
```

**Mitigación: Proxy redundante**

```
              ┌─────────┐
          ┌──>│ Proxy 1 │──┐
          │   └─────────┘  │
Clientes ─┤   Keepalived   ├──> Internet
          │   └─────────┘  │
          └──>│ Proxy 2 │──┘
              └─────────┘
```

### 2. Logs de proxy y privacidad

**Squid registra TODO:**
- URLs visitadas (incluyendo HTTPS domains vía SNI)
- IPs de clientes

**Compliance:**
- ⚠️ GDPR: Logs son datos personales → requiere justificación legal

### 3. SSL Bumping (Man-in-the-Middle corporativo)

Squid puede interceptar y descifrar HTTPS para inspección de contenido.

**⚠️ ADVERTENCIA ÉTICA Y LEGAL:**
- Requiere **consentimiento explícito** (política corporativa firmada)
- Instalar **certificado raíz del proxy** en todos los clientes
- **Ilegal sin consentimiento** en muchas jurisdicciones
- **Rompe privacy** completamente

**Configuración (solo educacional):**

```bash
# Generar CA privada de Squid
cd /etc/squid
openssl req -new -newkey rsa:2048 -sha256 -days 3650 -nodes -x509 \
  -keyout squid-ca.key -out squid-ca.pem

# Configurar SSL Bumping
sudo nano /etc/squid/squid.conf
```

```conf
# SSL Bump
http_port 3128 ssl-bump cert=/etc/squid/squid-ca.pem \
  generate-host-certificates=on dynamic_cert_mem_cache_size=4MB

sslcrtd_program /usr/lib/squid/security_file_certgen -s /var/lib/ssl_db -M 4MB

acl step1 at_step SslBump1
ssl_bump peek step1
ssl_bump bump all

# NO bump a sitios sensibles (banking)
acl nobump_sites dstdomain .banking.com .paypal.com
ssl_bump splice nobump_sites
```

**Clientes deben instalar `/etc/squid/squid-ca.pem` como CA de confianza.**

### 3. Service Mesh (Istio)

Para **microservicios** en Kubernetes:

```yaml
# Istio VirtualService (routing avanzado)
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: reviews-route
spec:
  hosts:
  - reviews
  http:
  # 90% tráfico a v1
  - match:
    - headers:
        end-user:
          exact: jason
    route:
    - destination:
        host: reviews

  - route:
    - destination:
        host: reviews
        subset: v1
      weight: 90
    - destination:
        host: reviews
        subset: v2
      weight: 10
```

**Service Mesh vs Reverse Proxy:**

| Característica | Reverse Proxy | Service Mesh |
|----------------|---------------|--------------|
| **Scope** | Entrada externa | Todo tráfico interno |
| **Deployment** | Centralizado | Sidecar por pod |
| **Protocolo** | HTTP/HTTPS | HTTP/gRPC/TCP |
| **Observabilidad** | Básica | Avanzada (tracing) |
| **mTLS** | Manual | Automático |
| **Traffic Management** | Basic routing | A/B, canary, circuit breaker |
| **Uso típico** | Internet → App | Microservice → Microservice |

## Resumen Ejecutivo

**Proxies y VPNs son tecnologías complementarias con propósitos diferentes:**

### Proxy
- ✅ **Uso**: Cache, filtrado, load balancing
- ✅ **Nivel**: Aplicación (HTTP/HTTPS)
- ✅ **Configuración**: Por aplicación
- ✅ **Transparencia**: Puede ser transparent
- ⚠️ **Seguridad**: No cifra tráfico (excepto HTTPS)
- ⚠️ **Privacidad**: Logs extensivos

### VPN
- ✅ **Uso**: Privacidad, acceso remoto, bypass censura
- ✅ **Nivel**: Red (IP)
- ✅ **Configuración**: Sistema completo
- ✅ **Seguridad**: Cifra TODO el tráfico
- ⚠️ **Performance**: Overhead de cifrado
- ⚠️ **Trust**: VPN provider ve todo

**Puntos críticos:**

1. **Forward proxy** para control corporativo (filtrado, cache, auth)
2. **Reverse proxy** para escalabilidad (load balancing, SSL termination)
3. **Transparent proxy** para enforcement (usuarios no pueden bypass)
4. **API Gateway** para microservicios (Kong, Traefik)
5. **CDN** como proxy global (Cloudflare, Akamai)

**Recomendaciones por escenario:**

| Escenario | Solución |
|-----------|----------|
| **Red corporativa (control)** | Squid Forward Proxy + AD auth |
| **Sitio web (escalabilidad)** | Nginx Reverse Proxy + cache |
| **Microservicios** | Kong API Gateway o Istio |
| **Privacidad personal** | VPN pago (NO proxy) |
| **Bypass geo-restricción** | VPN residencial (proxies detectados) |
| **Cache corporativo** | Squid + Varnish |

**Diferencia clave Proxy vs VPN:**
- **Proxy**: "Intermediario para HTTP" (rápido, sin cifrado completo)
- **VPN**: "Túnel cifrado para TODO" (lento, máxima privacidad)

**Para aprendizaje**: Montar Squid + Nginx reverse proxy enseña arquitecturas web modernas. **Para producción corporativa**: Forward proxy con Squid + reverse proxy con Nginx/HAProxy + CDN (Cloudflare) es combinación ganadora.

**Ética**: Proxies/VPNs para bypass de restricciones pueden violar términos de servicio. Uso educacional ≠ uso malicioso. Respetar copyright y leyes locales.
