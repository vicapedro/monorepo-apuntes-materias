# 2.8 Correo Electrónico - SMTP, POP, IMAP y SASL

> **⚠️ ADVERTENCIA CRÍTICA**: Configurar un servidor de correo es **altamente complejo** y requiere expertise considerable. **Open relay** (relay abierto) convierte su servidor en herramienta de spam y resulta en **blacklist inmediata**. **SPF, DKIM, DMARC** son obligatorios para deliverability. Para producción, considere **servicios administrados** (Microsoft 365, Google Workspace, AWS SES) en lugar de servidor propio.

## Descripción

### Arquitectura de correo electrónico

El correo electrónico utiliza múltiples protocolos interconectados:

```
┌─────────────────────────────────────────────────────────────────┐
│                    Cliente de Correo                            │
│          (Thunderbird, Outlook, Mail.app, Gmail web)           │
└─────────┬───────────────────────────────────────┬───────────────┘
          │                                       │
          │ SMTP (Envío)                         │ POP3/IMAP (Recepción)
          │ Puerto 587 (Submission)              │ Puerto 993/995 (TLS)
          │                                       │
          ▼                                       ▼
┌─────────────────────┐               ┌─────────────────────────┐
│   Servidor SMTP     │   SMTP 25     │   Servidor POP/IMAP     │
│   (Postfix, etc.)   │◄─────────────►│   (Dovecot, etc.)       │
│   - Envío           │               │   - Almacenamiento      │
│   - Relay           │               │   - Acceso a buzones    │
└──────────┬──────────┘               └─────────────────────────┘
           │                                       │
           │ SMTP Puerto 25                       │ Mailbox
           │ (Server-to-Server)                   │ (Maildir/mbox)
           │                                       │
           ▼                                       │
┌─────────────────────┐                           │
│ Servidor SMTP       │                           │
│ Destino             │                           │
│ (ejemplo.com)       │───────────────────────────┘
└─────────────────────┘
```

### SMTP (Simple Mail Transfer Protocol)

**Puerto 25**: Server-to-server (MTA a MTA)  
**Puerto 587**: Submission (cliente a servidor) - **Recomendado con STARTTLS**  
**Puerto 465**: SMTPS (deprecated, pero aún usado)

**Flujo de envío SMTP:**

```
Cliente                                     Servidor SMTP (Postfix)
   │                                                │
   │  1. EHLO cliente.ejemplo.com                  │
   ├──────────────────────────────────────────────>│
   │                                                │
   │  2. 250-servidor.ejemplo.com                  │
   │     250-PIPELINING                            │
   │     250-SIZE 10240000                         │
   │     250-VRFY                                  │
   │     250-STARTTLS                              │
   │     250 AUTH PLAIN LOGIN                      │
   │<───────────────────────────────────────────────┤
   │                                                │
   │  3. STARTTLS (iniciar cifrado)                │
   ├──────────────────────────────────────────────>│
   │                                                │
   │  4. 220 Ready to start TLS                    │
   │<───────────────────────────────────────────────┤
   │                                                │
   │  5. TLS Handshake (intercambio de certs)      │
   │<──────────────────────────────────────────────>│
   │                                                │
   │  6. AUTH LOGIN (autenticación)                │
   ├──────────────────────────────────────────────>│
   │                                                │
   │  7. 334 VXNlcm5hbWU6 (base64: "Username:")    │
   │<───────────────────────────────────────────────┤
   │                                                │
   │  8. dXNlckBlamVtcGxvLmNvbQ== (user@ejemplo.com)│
   ├──────────────────────────────────────────────>│
   │                                                │
   │  9. 334 UGFzc3dvcmQ6 (base64: "Password:")    │
   │<───────────────────────────────────────────────┤
   │                                                │
   │ 10. cGFzc3dvcmQxMjM= (password123 en base64)  │
   ├──────────────────────────────────────────────>│
   │                                                │
   │ 11. 235 Authentication successful             │
   │<───────────────────────────────────────────────┤
   │                                                │
   │ 12. MAIL FROM:<usuario@ejemplo.com>           │
   ├──────────────────────────────────────────────>│
   │                                                │
   │ 13. 250 OK                                    │
   │<───────────────────────────────────────────────┤
   │                                                │
   │ 14. RCPT TO:<destino@otrodominio.com>         │
   ├──────────────────────────────────────────────>│
   │                                                │
   │ 15. 250 Accepted                              │
   │<───────────────────────────────────────────────┤
   │                                                │
   │ 16. DATA                                      │
   ├──────────────────────────────────────────────>│
   │                                                │
   │ 17. 354 End data with <CR><LF>.<CR><LF>       │
   │<───────────────────────────────────────────────┤
   │                                                │
   │ 18. From: usuario@ejemplo.com                 │
   │     To: destino@otrodominio.com               │
   │     Subject: Asunto del mensaje               │
   │     [headers adicionales]                     │
   │                                                │
   │     Cuerpo del mensaje...                     │
   │     .                                          │
   ├──────────────────────────────────────────────>│
   │                                                │
   │ 19. 250 Message accepted for delivery         │
   │     Queue ID: ABC123DEF456                    │
   │<───────────────────────────────────────────────┤
   │                                                │
   │ 20. QUIT                                      │
   ├──────────────────────────────────────────────>│
   │                                                │
   │ 21. 221 Bye                                   │
   │<───────────────────────────────────────────────┤
```

**Códigos de respuesta SMTP:**

| Código | Significado | Descripción |
|--------|-------------|-------------|
| 220 | Ready | Servidor listo |
| 221 | Closing | Conexión cerrándose |
| 235 | Auth successful | Autenticación exitosa |
| 250 | OK | Comando exitoso |
| 354 | Start mail input | Iniciar ingreso de mensaje |
| 421 | Service not available | Servidor sobrecargado |
| 450 | Mailbox unavailable | Buzón temporalmente no disponible |
| 451 | Local error | Error local en procesamiento |
| 452 | Insufficient storage | Sin espacio en disco |
| 500 | Syntax error | Comando no reconocido |
| 501 | Syntax error in parameters | Parámetros inválidos |
| 503 | Bad sequence | Secuencia de comandos incorrecta |
| 550 | Mailbox unavailable | Usuario no existe |
| 551 | User not local | Usuario no es local (relay) |
| 552 | Storage allocation exceeded | Cuota excedida |
| 553 | Mailbox name not allowed | Dirección inválida |
| 554 | Transaction failed | Fallo general |

### POP3 (Post Office Protocol version 3)

**Puerto 110**: POP3 sin cifrar (⚠️ NO usar)  
**Puerto 995**: POP3S (POP3 sobre TLS) - **Recomendado**

**Características:**
- **Download-and-delete**: Descarga mensajes y los borra del servidor (configurable)
- **Stateless**: Sin sincronización entre dispositivos
- **Simple**: Protocolo minimalista

**Flujo POP3:**

```
Cliente                          Servidor POP3 (Dovecot)
   │                                    │
   │  1. USER usuario                  │
   ├──────────────────────────────────>│
   │                                    │
   │  2. +OK                            │
   │<───────────────────────────────────┤
   │                                    │
   │  3. PASS password                 │
   ├──────────────────────────────────>│
   │                                    │
   │  4. +OK Logged in                 │
   │<───────────────────────────────────┤
   │                                    │
   │  5. STAT (estadísticas)           │
   ├──────────────────────────────────>│
   │                                    │
   │  6. +OK 5 1024 (5 mensajes, 1KB)  │
   │<───────────────────────────────────┤
   │                                    │
   │  7. LIST (listar mensajes)        │
   ├──────────────────────────────────>│
   │                                    │
   │  8. +OK                            │
   │     1 120                          │
   │     2 250                          │
   │     3 180                          │
   │     ...                            │
   │<───────────────────────────────────┤
   │                                    │
   │  9. RETR 1 (recuperar mensaje 1)  │
   ├──────────────────────────────────>│
   │                                    │
   │ 10. +OK                            │
   │     [contenido del mensaje]       │
   │<───────────────────────────────────┤
   │                                    │
   │ 11. DELE 1 (marcar para borrar)   │
   ├──────────────────────────────────>│
   │                                    │
   │ 12. +OK                            │
   │<───────────────────────────────────┤
   │                                    │
   │ 13. QUIT                           │
   ├──────────────────────────────────>│
   │                                    │
   │ 14. +OK Logging out                │
   │<───────────────────────────────────┤
```

**Problema de POP3**: Si revisa correo en PC, luego en móvil, **no verá los mensajes descargados en PC**. Sin sincronización entre dispositivos.

### IMAP (Internet Message Access Protocol)

**Puerto 143**: IMAP sin cifrar (⚠️ NO usar)  
**Port 993**: IMAPS (IMAP sobre TLS) - **Recomendado**

**Características:**
- **Server-side storage**: Mensajes permanecen en servidor
- **Stateful**: Sincronización completa entre dispositivos
- **Carpetas**: Soporte para carpetas en servidor
- **Flags**: Leído, no leído, importante, etc.
- **Búsqueda server-side**: Búsquedas sin descargar todo

**Flujo IMAP:**

```
Cliente                                Servidor IMAP (Dovecot)
   │                                          │
   │  1. A001 LOGIN usuario password         │
   ├────────────────────────────────────────>│
   │                                          │
   │  2. A001 OK Logged in                   │
   │<─────────────────────────────────────────┤
   │                                          │
   │  3. A002 LIST "" "*" (listar carpetas)  │
   ├────────────────────────────────────────>│
   │                                          │
   │  4. * LIST (\HasNoChildren) "." INBOX   │
   │     * LIST (\HasNoChildren) "." Sent    │
   │     * LIST (\HasNoChildren) "." Drafts  │
   │     A002 OK List completed              │
   │<─────────────────────────────────────────┤
   │                                          │
   │  5. A003 SELECT INBOX                   │
   ├────────────────────────────────────────>│
   │                                          │
   │  6. * FLAGS (\Answered \Flagged ...)    │
   │     * 42 EXISTS (42 mensajes)           │
   │     * 5 RECENT (5 nuevos)               │
   │     A003 OK [READ-WRITE] Selected       │
   │<─────────────────────────────────────────┤
   │                                          │
   │  7. A004 FETCH 1:5 (FLAGS BODY[HEADER]) │
   ├────────────────────────────────────────>│
   │                                          │
   │  8. * 1 FETCH (FLAGS (\Seen) ...)       │
   │     * 2 FETCH (FLAGS () ...)            │
   │     [headers de mensajes 1-5]           │
   │     A004 OK Fetch completed             │
   │<─────────────────────────────────────────┤
   │                                          │
   │  9. A005 FETCH 2 BODY[TEXT]             │
   ├────────────────────────────────────────>│
   │                                          │
   │ 10. * 2 FETCH (BODY[TEXT] {...})        │
   │     [cuerpo del mensaje]                │
   │     A005 OK Fetch completed             │
   │<─────────────────────────────────────────┤
   │                                          │
   │ 11. A006 STORE 2 +FLAGS (\Seen)         │
   ├────────────────────────────────────────>│
   │                                          │
   │ 12. * 2 FETCH (FLAGS (\Seen))           │
   │     A006 OK Store completed             │
   │<─────────────────────────────────────────┤
   │                                          │
   │ 13. A007 LOGOUT                          │
   ├────────────────────────────────────────>│
   │                                          │
   │ 14. * BYE Logging out                   │
   │     A007 OK Logout completed            │
   │<─────────────────────────────────────────┤
```

**IMAP vs POP3:**

| Aspecto | POP3 | IMAP |
|---------|------|------|
| **Ubicación mensajes** | Cliente (descargados) | Servidor (sincronizados) |
| **Sincronización** | ❌ | ✅ |
| **Múltiples dispositivos** | ❌ | ✅ |
| **Carpetas** | ❌ | ✅ |
| **Búsqueda server-side** | ❌ | ✅ |
| **Uso de ancho de banda** | Alto (descarga todo) | Bajo (solo headers) |
| **Complejidad** | Simple | Compleja |
| **Uso típico** | Obsoleto | Estándar moderno |

### SASL (Simple Authentication and Security Layer)

SASL es un **framework de autenticación** que desacopla protocolos de aplicación (SMTP, IMAP) de mecanismos de autenticación.

**Mecanismos SASL comunes:**

| Mecanismo | Descripción | Seguridad |
|-----------|-------------|-----------|
| **PLAIN** | Username/password en base64 | ⚠️ Solo con TLS |
| **LOGIN** | Similar a PLAIN (legacy) | ⚠️ Solo con TLS |
| **CRAM-MD5** | Challenge-response con hash MD5 | ⚠️ MD5 débil |
| **DIGEST-MD5** | Autenticación mutua con MD5 | ⚠️ MD5 débil |
| **SCRAM-SHA-1** | Challenge-response con SHA-1 | ⚠️ SHA-1 comprometido |
| **SCRAM-SHA-256** | Challenge-response con SHA-256 | ✅ Recomendado |
| **GSSAPI** | Kerberos | ✅ Corporativo |
| **EXTERNAL** | Certificados X.509 | ✅ Máxima seguridad |
| **OAUTHBEARER** | OAuth 2.0 tokens | ✅ Moderno (Google, Microsoft) |

**Ejemplo de AUTH PLAIN:**

```bash
# Autenticación PLAIN en SMTP
# Username: usuario@ejemplo.com
# Password: password123

# Formato: \0username\0password (separado por null bytes)
# Base64: AHVzdWFyaW9AZWplbXBsby5jb20AcGFzc3dvcmQxMjM=

telnet mail.ejemplo.com 587
EHLO cliente.ejemplo.com
STARTTLS
[TLS handshake]
AUTH PLAIN AHVzdWFyaW9AZWplbXBsby5jb20AcGFzc3dvcmQxMjM=
# 235 Authentication successful
```

## Instalación y Configuración

### 1. Postfix (SMTP Server)

**Instalación en Ubuntu 22.04/24.04:**

```bash
# Actualizar repositorios
sudo apt update

# Instalar Postfix
sudo apt install postfix -y

# Durante instalación:
# - General type: Internet Site
# - System mail name: mail.ejemplo.com (FQDN del servidor)

# Verificar instalación
postconf -d | grep mail_version

# Verificar puertos
sudo ss -tulnp | grep master
# Debe mostrar puerto 25
```

**Instalación en Rocky Linux 9:**

```bash
# Instalar Postfix
sudo dnf install postfix -y

# Habilitar e iniciar
sudo systemctl enable postfix --now

# Firewall
sudo firewall-cmd --permanent --add-service=smtp
sudo firewall-cmd --permanent --add-service=smtp-submission
sudo firewall-cmd --reload

# Verificar
sudo systemctl status postfix
```

#### Configuración básica de Postfix

```bash
# Backup de configuración original
sudo cp /etc/postfix/main.cf /etc/postfix/main.cf.backup

# Editar configuración
sudo nano /etc/postfix/main.cf
```

```conf
# /etc/postfix/main.cf - Configuración básica

# Hostname del servidor
myhostname = mail.ejemplo.com
mydomain = ejemplo.com

# Origen de correos
myorigin = $mydomain

# Destinos locales (este servidor acepta correo para estos dominios)
mydestination = $myhostname, localhost.$mydomain, localhost, $mydomain

# Redes autorizadas para relay (CRÍTICO: solo localhost por defecto)
mynetworks = 127.0.0.0/8 [::ffff:127.0.0.0]/104 [::1]/128

# NO permitir relay abierto (open relay)
# Solo autenticados pueden enviar
smtpd_relay_restrictions = permit_mynetworks,
                            permit_sasl_authenticated,
                            reject_unauth_destination

# Interfaz de escucha
inet_interfaces = all
inet_protocols = ipv4

# Tamaño máximo de mensaje (10MB)
message_size_limit = 10485760

# Formato de buzón
home_mailbox = Maildir/

# Banner (no revelar versión por seguridad)
smtpd_banner = $myhostname ESMTP
```

**Aplicar configuración:**

```bash
# Verificar sintaxis
sudo postfix check

# Recargar configuración
sudo postfix reload

# Reiniciar servicio
sudo systemctl restart postfix
```

#### Configurar TLS para SMTP (STARTTLS)

```bash
# Generar certificado self-signed (desarrollo)
sudo openssl req -new -x509 -days 365 -nodes \
  -out /etc/ssl/certs/postfix.pem \
  -keyout /etc/ssl/private/postfix.key \
  -subj "/C=MX/ST=Jalisco/L=Guadalajara/O=Ejemplo/CN=mail.ejemplo.com"

# Permisos
sudo chmod 644 /etc/ssl/certs/postfix.pem
sudo chmod 600 /etc/ssl/private/postfix.key

# Configurar TLS en Postfix
sudo nano /etc/postfix/main.cf
```

```conf
# TLS para SMTP (servidor)
smtpd_tls_cert_file = /etc/ssl/certs/postfix.pem
smtpd_tls_key_file = /etc/ssl/private/postfix.key
smtpd_tls_security_level = may
smtpd_tls_auth_only = yes
smtpd_tls_received_header = yes
smtpd_tls_session_cache_database = btree:${data_directory}/smtpd_scache

# TLS para SMTP (cliente - cuando Postfix envía)
smtp_tls_security_level = may
smtp_tls_session_cache_database = btree:${data_directory}/smtp_scache
smtp_tls_loglevel = 1

# Protocolos y ciphers seguros
smtpd_tls_protocols = !SSLv2, !SSLv3, !TLSv1, !TLSv1.1
smtpd_tls_mandatory_protocols = !SSLv2, !SSLv3, !TLSv1, !TLSv1.1
smtp_tls_protocols = !SSLv2, !SSLv3, !TLSv1, !TLSv1.1
smtp_tls_mandatory_protocols = !SSLv2, !SSLv3, !TLSv1, !TLSv1.1

smtpd_tls_ciphers = medium
smtpd_tls_mandatory_ciphers = medium
```

```bash
# Reiniciar Postfix
sudo systemctl restart postfix
```

#### Configurar puerto 587 (Submission con autenticación)

```bash
# Editar master.cf
sudo nano /etc/postfix/master.cf
```

```conf
# /etc/postfix/master.cf

# Puerto 587 para submission (clientes)
submission inet n       -       y       -       -       smtpd
  -o syslog_name=postfix/submission
  -o smtpd_tls_security_level=encrypt
  -o smtpd_sasl_auth_enable=yes
  -o smtpd_sasl_type=dovecot
  -o smtpd_sasl_path=private/auth
  -o smtpd_sasl_security_options=noanonymous
  -o smtpd_client_restrictions=permit_sasl_authenticated,reject
  -o smtpd_sender_restrictions=reject_sender_login_mismatch
  -o smtpd_recipient_restrictions=reject_non_fqdn_recipient,reject_unknown_recipient_domain,permit_sasl_authenticated,reject
```

```bash
# Reiniciar Postfix
sudo systemctl restart postfix

# Verificar puerto 587
sudo ss -tulnp | grep :587
```

### 2. Dovecot (POP3/IMAP Server)

**Instalación:**

```bash
# Ubuntu
sudo apt install dovecot-core dovecot-imapd dovecot-pop3d -y

# Rocky Linux
sudo dnf install dovecot -y

# Iniciar servicio
sudo systemctl enable dovecot --now
sudo systemctl status dovecot
```

**Configuración básica de Dovecot:**

```bash
# Backup de configuración
sudo cp /etc/dovecot/dovecot.conf /etc/dovecot/dovecot.conf.backup

# Editar configuración principal
sudo nano /etc/dovecot/dovecot.conf
```

```conf
# /etc/dovecot/dovecot.conf

# Protocolos habilitados
protocols = imap pop3

# Escuchar en todas las interfaces
listen = *
```

**Configurar ubicación de mailboxes:**

```bash
sudo nano /etc/dovecot/conf.d/10-mail.conf
```

```conf
# /etc/dovecot/conf.d/10-mail.conf

# Formato Maildir (cada mensaje es un archivo)
mail_location = maildir:~/Maildir

# Usuario y grupo
mail_privileged_group = mail

# Formato de separador de carpetas
namespace inbox {
  inbox = yes
  separator = .
}
```

**Configurar autenticación:**

```bash
sudo nano /etc/dovecot/conf.d/10-auth.conf
```

```conf
# /etc/dovecot/conf.d/10-auth.conf

# Deshabilitar login sin TLS
disable_plaintext_auth = yes

# Mecanismos de autenticación
auth_mechanisms = plain login

# Usuarios del sistema
!include auth-system.conf.ext
```

**Configurar TLS para Dovecot:**

```bash
sudo nano /etc/dovecot/conf.d/10-ssl.conf
```

```conf
# /etc/dovecot/conf.d/10-ssl.conf

# Requerir SSL/TLS
ssl = required

# Certificados (mismo que Postfix)
ssl_cert = </etc/ssl/certs/postfix.pem
ssl_key = </etc/ssl/private/postfix.key

# Protocolos seguros
ssl_min_protocol = TLSv1.2
ssl_cipher_list = ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384
ssl_prefer_server_ciphers = yes
```

**Configurar integración con Postfix (SASL):**

```bash
sudo nano /etc/dovecot/conf.d/10-master.conf
```

```conf
# /etc/dovecot/conf.d/10-master.conf

service auth {
  # Postfix SMTP auth
  unix_listener /var/spool/postfix/private/auth {
    mode = 0660
    user = postfix
    group = postfix
  }
```

### 4. SPF, DKIM, DMARC (Anti-Spam)

#### SPF (Sender Policy Framework)

SPF define qué servidores pueden enviar correo en nombre de tu dominio.

**Registro DNS TXT:**

```
ejemplo.com.  IN  TXT  "v=spf1 mx a ip4:203.0.113.10 include:_spf.google.com ~all"

# Explicación:
# v=spf1        - Versión SPF
# mx            - Servidores MX pueden enviar
# a             - Registro A del dominio puede enviar
# ip4:...       - IP específica autorizada
# include:...   - Incluir SPF de otro dominio (ej: Google Workspace)
# ~all          - SoftFail (marcar como sospechoso si no coincide)
# -all          - HardFail (rechazar si no coincide) - más estricto
```

**Calificadores:**
- `+` Pass (autorizado)
- `-` Fail (rechazar)
- `~` SoftFail (marcar sospechoso)
- `?` Neutral (no opinar)

#### DKIM (DomainKeys Identified Mail)

DKIM firma digitalmente los mensajes para verificar integridad y autenticidad.

**Instalación:**

#### DMARC (Domain-based Message Authentication, Reporting & Conformance)

DMARC une SPF y DKIM con políticas de handling.

**Registro DNS TXT:**

```
_dmarc.ejemplo.com.  IN  TXT  "v=DMARC1; p=quarantine; rua=mailto:dmarc@ejemplo.com; ruf=mailto:forensics@ejemplo.com; fo=1; adkim=s; aspf=s; pct=100"

# Parámetros:
# v=DMARC1              - Versión
# p=quarantine          - Política: none, quarantine, reject
# rua=mailto:...        - Reportes agregados
# ruf=mailto:...        - Reportes forenses
# fo=1                  - Generar reporte si falla SPF o DKIM
# adkim=s               - Alineación DKIM estricta (s) o relajada (r)
# aspf=s                - Alineación SPF estricta (s) o relajada (r)
# pct=100               - Porcentaje de mensajes a los que aplicar política
```

**Políticas DMARC:**
- `p=none` - Solo monitoreo (recibir reportes)
- `p=quarantine` - Marcar como spam si falla
- `p=reject` - Rechazar si falla (más estricto)

## Aspectos de Seguridad

### 1. Problema crítico: Open Relay

**Open relay** = servidor que acepta correo de cualquiera y lo reenvía a cualquier destino.

**Consecuencias:**
- ❌ **Blacklist instantánea** (Spamhaus, Barracuda, etc.)
- ❌ IP reputation arruinada (tarda meses en recuperarse)
- ❌ Abuso de tu servidor para enviar millones de spams
- ❌ Consumo de recursos (CPU, ancho de banda)

**Verificar que NO seas open relay:**

```bash
# Método 1: telnet desde otra IP
telnet tu-servidor.com 25
EHLO attacker.com
MAIL FROM:<spammer@evil.com>
RCPT TO:<victim@gmail.com>
# Debe responder: 554 Relay access denied

# Método 2: Herramientas online
# https://mxtoolbox.com/diagnostic.aspx
```

**Prevención en Postfix:**

```conf
# /etc/postfix/main.cf

# Solo relay para redes autorizadas y usuarios autenticados
smtpd_relay_restrictions = permit_mynetworks,
                            permit_sasl_authenticated,
                            reject_unauth_destination

# Redes autorizadas (solo localhost por defecto)
mynetworks = 127.0.0.0/8 [::1]/128

# NUNCA hacer:
# mynetworks = 0.0.0.0/0  # ¡Open relay!
```

### 2. Autenticación obligatoria en puerto 587

```conf
# /etc/postfix/master.cf

submission inet n       -       y       -       -       smtpd
  -o smtpd_sasl_auth_enable=yes
  -o smtpd_client_restrictions=permit_sasl_authenticated,reject
```

Sin esto, cualquiera puede usar tu servidor para enviar spam.

### 3. Rate limiting

```conf
# /etc/postfix/main.cf

# Límite de mensajes por conexión
smtpd_client_message_rate_limit = 100

# Límite de destinatarios por mensaje
smtpd_recipient_limit = 50

# Límite de errores antes de desconectar
smtpd_error_sleep_time = 1s
smtpd_soft_error_limit = 10
smtpd_hard_error_limit = 20
```

## Resumen Ejecutivo

**Montar un servidor de correo es complejo y arriesgado para producción.** Reputación de IP, deliverability, y anti-spam requieren expertise considerable.

**Puntos críticos:**

1. **Open Relay = Blacklist instantánea** → Verificar siempre que solo autenticados pueden relay
2. **SPF, DKIM, DMARC son obligatorios** → Sin ellos, tus emails van a spam
3. **Reputación de IP tarda meses** → IP nueva necesita "warming" (envío gradual)
4. **TLS obligatorio** → STARTTLS en puerto 587, SSL/TLS en 993/995
5. **Monitoreo constante** → Blacklists, cola de correos, tasa de rechazo

**Recomendaciones por escenario:**

| Escenario | Solución recomendada |
|-----------|----------------------|
| **Empresa <100 usuarios** | Microsoft 365 o Google Workspace |
| **Emails transaccionales** | AWS SES, SendGrid, Mailgun |
| **Control total requerido** | Postfix + Dovecot (con expertise) |
| **Alto volumen (>10K users)** | Self-hosted con equipo dedicado |
| **Marketing emails** | Mailchimp, SendinBlue (NO self-hosted) |

**Para aprendizaje**: Instalar Postfix/Dovecot en laboratorio es excelente. **Para producción**: Considerar seriamente servicios administrados (Microsoft 365, Google Workspace) o transaccionales (AWS SES) que eliminan complejidad de deliverability y compliance.

**Conclusión**: Servidor de correo propio solo tiene sentido si tienes equipo técnico dedicado, presupuesto para monitoreo 24/7, y requisitos muy específicos de control. En otros casos, servicios cloud son más confiables y económicos a largo plazo.
