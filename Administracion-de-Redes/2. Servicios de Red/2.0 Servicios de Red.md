# Unidad 2: Servicios de Red

## Introducción

Los **servicios de red** constituyen el núcleo funcional de cualquier infraestructura tecnológica moderna. Sin ellos, una red de comunicaciones es simplemente un conjunto de cables y dispositivos sin propósito real. Estos servicios transforman la conectividad física en capacidades operativas concretas que permiten a los usuarios y aplicaciones comunicarse, compartir recursos, acceder a información y colaborar de manera efectiva.

En una red corporativa, los servicios de red son **absolutamente críticos** para las operaciones diarias. Desde la asignación automática de direcciones IP (DHCP) que permite a dispositivos conectarse sin configuración manual, hasta los servicios de correo electrónico (SMTP/POP/IMAP) que facilitan la comunicación empresarial, pasando por el sistema de nombres de dominio (DNS) que traduce nombres legibles a direcciones IP, cada servicio cumple una función específica e indispensable.

### Competencia Específica de la Unidad

**Instala, configura y administra diferentes servicios de red para satisfacer las necesidades específicas de las organizaciones.**

Esta unidad desarrolla las habilidades prácticas necesarias para:
- Implementar servicios de red en diferentes plataformas (Linux, BSD, Windows Server)
- Configurar políticas de control de acceso y seguridad
- Optimizar el rendimiento de los servicios según las necesidades organizacionales
- Integrar servicios de red en arquitecturas empresariales complejas
- Troubleshooting y resolución de problemas de servicios

## Evolución Tecnológica: Servicios Tradicionales vs Modernos

Los servicios de red han evolucionado significativamente en las últimas décadas. Algunos servicios que en su momento fueron revolucionarios ahora se consideran **obsoletos o inseguros**, mientras que otros han permanecido como pilares fundamentales con actualizaciones constantes.

### Servicios que Permanecen Relevantes

```
✓ DHCP (Dynamic Host Configuration Protocol)
  - Asignación automática de direcciones IP
  - Esencial en cualquier red moderna
  - Evolución: DHCPv6 para IPv6

✓ DNS (Domain Name System)
  - Traducción de nombres a direcciones IP
  - Columna vertebral de Internet
  - Evolución: DNSSEC (seguridad), DNS over HTTPS (privacidad)

✓ SSH (Secure Shell)
  - Acceso remoto seguro cifrado
  - Reemplazo de Telnet
  - Estándar para administración remota

✓ HTTP/HTTPS
  - Protocolo web fundamental
  - HTTPS = HTTP + TLS (cifrado)
  - HTTP/2 y HTTP/3 (QUIC) mejoran performance

✓ SMTP, POP3, IMAP
  - Protocolos de correo electrónico
  - Aún usados masivamente
  - Evolución: OAuth2, autenticación moderna

✓ LDAP (Lightweight Directory Access Protocol)
  - Directorios centralizados de usuarios/recursos
  - Base de Active Directory
  - Integración con servicios modernos (SSO)

✓ Proxy (Forward/Reverse)
  - Control de tráfico web
  - Cache y optimización
  - Evolución: WAF, CDN, API Gateway
```

### Servicios Tradicionales/Obsoletos (Incluidos por Valor Pedagógico)

```
⚠ FTP (File Transfer Protocol)
  Problema: Credenciales y datos en texto plano (sin cifrar)
  Alternativas modernas:
  - SFTP (SSH File Transfer Protocol) ✓
  - FTPS (FTP over TLS) ✓
  - SCP (Secure Copy) ✓
  - Soluciones cloud (Dropbox, OneDrive, Google Drive, S3)
  
  ¿Por qué estudiarlo?
  - Aún presente en sistemas legacy
  - Comprensión de protocolos de transferencia
  - Base para entender alternativas seguras

⚠ TFTP (Trivial File Transfer Protocol)
  Problema: Sin autenticación, sin cifrado, muy básico
  Uso actual: Solo en entornos controlados (PXE boot, actualizaciones firmware)
  Alternativas:
  - HTTP/HTTPS para distribución de archivos
  - SCP/SFTP para transferencias seguras
  
  ¿Por qué estudiarlo?
  - Usado en boot de dispositivos de red (switches, routers)
  - Simple para entender transferencia de archivos UDP
  - Contexto histórico de protocolos livianos

⚠ NFS (Network File System)
  Problema: Versiones antiguas (NFSv2/v3) sin cifrado ni autenticación robusta
  Estado: NFSv4 con Kerberos es seguro
  Alternativas modernas:
  - SMB/CIFS (Windows)
  - WebDAV
  - Soluciones cloud
  - iSCSI para storage empresarial
  
  ¿Por qué estudiarlo?
  - Aún usado en entornos Unix/Linux
  - Concepto de sistemas de archivos distribuidos
  - Base para entender SMB y alternativas

⚠ Telnet
  Problema: TODO en texto plano (usuario, contraseña, comandos)
  Reemplazo: SSH (100% de los casos)
  
  ¿Por qué NO está en el temario?
  - Absolutamente inseguro
  - No tiene casos de uso legítimos modernos
  - Se menciona solo para explicar por qué SSH existe
```

## Arquitectura de Servicios de Red Corporativos

En una organización real, los servicios de red se implementan siguiendo una arquitectura estructurada que considera alta disponibilidad, seguridad y escalabilidad.

### Modelo de Capas de Servicios

```
┌─────────────────────────────────────────────────────────────┐
│              CAPA DE USUARIOS Y APLICACIONES                │
│  (Navegadores, clientes de correo, apps empresariales)     │
└────────────────────┬────────────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────────────┐
│               CAPA DE SERVICIOS DE APLICACIÓN               │
│  • HTTP/HTTPS (Web)                                         │
│  • SMTP/IMAP (Correo)                                       │
│  • Proxy (Control de acceso web)                            │
│  • LDAP/AD (Directorio de usuarios)                         │
└────────────────────┬────────────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────────────┐
│            CAPA DE SERVICIOS DE INFRAESTRUCTURA             │
│  • DNS (Resolución de nombres)                              │
│  • DHCP (Asignación de IPs)                                 │
│  • NTP (Sincronización de tiempo)                           │
│  • SSH (Administración remota)                              │
└────────────────────┬────────────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────────────┐
│                   CAPA DE RED Y TRANSPORTE                  │
│  (TCP/IP, Routing, Switching, Firewalls)                    │
└─────────────────────────────────────────────────────────────┘
```

### Principios de Diseño para Servicios Empresariales

```
1. ALTA DISPONIBILIDAD
   - Redundancia de servidores (mínimo 2)
   - Load balancing entre instancias
   - Failover automático
   - Ejemplo: 2 servidores DNS, 2 DHCP, cluster de mail servers

2. SEGURIDAD POR CAPAS
   - Autenticación (¿quién eres?)
   - Autorización (¿qué puedes hacer?)
   - Cifrado (datos protegidos en tránsito)
   - Auditoría (registro de acciones)
   - Ejemplo: LDAP + TLS + ACLs + syslog

3. ESCALABILIDAD
   - Diseño que permita crecimiento
   - Separación de servicios en servidores dedicados
   - Balanceo de carga horizontal
   - Ejemplo: DNS distribuido, proxy en cluster

4. MONITOREO Y OBSERVABILIDAD
   - Logs centralizados (syslog, SIEM)
   - Métricas de performance (CPU, RAM, disco, red)
   - Alertas proactivas
   - Ejemplo: Zabbix monitoreando todos los servicios

5. DOCUMENTACIÓN Y ESTANDARIZACIÓN
   - Configuraciones documentadas
   - Procedimientos de instalación/actualización
   - Políticas de respaldo
   - Diagramas de arquitectura actualizados
```

## Servicios Incluidos en la Unidad 2

A continuación, se presenta la lista completa de servicios que se cubrirán en esta unidad, organizados por categoría funcional:

### 2.1 Servicios de Infraestructura Básica

#### 2.1.1 DHCP (Dynamic Host Configuration Protocol)
**Función:** Asignación automática de configuración IP a dispositivos de red

**Importancia:** Sin DHCP, cada dispositivo requeriría configuración manual de IP, máscara, gateway y DNS. Inviable en redes modernas.

**Contenido:**
- Descripción del protocolo y funcionamiento (DORA: Discover, Offer, Request, Acknowledge)
- Objetivo: Automatizar configuración de red, reducir errores humanos
- Instalación y configuración: ISC DHCP Server (Linux), Windows Server DHCP
- Configuración de scopes, pools, reservas, opciones (router, DNS, NTP)
- Demostración: Asignación dinámica, reservas MAC, múltiples subredes
- Aspectos de seguridad: DHCP snooping, rogue DHCP detection
- DHCP Relay en redes segmentadas

**Archivo:** `2.1-DHCP.md`

---

#### 2.1.2 DNS (Domain Name System)
**Función:** Traducción de nombres de dominio a direcciones IP

**Importancia:** El DNS es la "agenda telefónica" de Internet. Sin él, tendríamos que memorizar direcciones IP para todo.

**Contenido:**
- Descripción: Jerarquía de DNS (root servers, TLD, authoritative)
- Objetivo: Facilitar acceso a recursos mediante nombres memorables
- Instalación y configuración: BIND (Berkeley Internet Name Domain), Windows DNS
- Tipos de registros: A, AAAA, CNAME, MX, TXT, PTR, NS, SOA
- Zonas: Forward lookup, reverse lookup, zona primaria, secundaria
- Demostración: Resolución de nombres, caché DNS, queries recursivas vs iterativas
- Aspectos de seguridad: DNSSEC (validación criptográfica), DNS over HTTPS (DoH), DNS over TLS (DoT)
- Protección contra DNS spoofing, cache poisoning
- Split DNS (interno vs externo)

**Archivo:** `2.2-DNS.md`

---

### 2.2 Servicios de Acceso y Administración

#### 2.2.1 SSH (Secure Shell)
**Función:** Acceso remoto seguro y cifrado a sistemas

**Importancia:** Reemplazo completo de Telnet. Estándar de facto para administración remota de servidores y dispositivos de red.

**Contenido:**
- Descripción: Protocolo de capa de aplicación con cifrado fuerte
- Objetivo: Administración remota segura, transferencia de archivos (SCP/SFTP), túneles cifrados
- Instalación y configuración: OpenSSH (Linux/BSD), PuTTY (cliente Windows)
- Autenticación por contraseña vs claves públicas (recommended)
- Port forwarding (local, remote, dynamic)
- Demostración: Conexión SSH, SCP, SFTP, túneles
- Aspectos de seguridad: Hardening (disable root login, change port, fail2ban)
- Autenticación multifactor (MFA)
- SSH certificates vs keys

**Archivo:** `2.3-SSH.md`

---

#### 2.2.2 FTP y TFTP (File Transfer Protocols)
**Función:** Transferencia de archivos entre sistemas

**Importancia Histórica:** FTP fue estándar durante décadas. TFTP aún usado para boot de dispositivos.

**Estado:** Obsoletos para transferencias seguras, incluidos por valor pedagógico.

**Contenido:**
- Descripción: Protocolos de transferencia (FTP activo/pasivo, TFTP UDP)
- Objetivo: Comprender transferencia de archivos, entender limitaciones de protocolos legacy
- Instalación y configuración: vsftpd, ProFTPD (FTP), tftpd-hpa (TFTP)
- Demostración: Transferencias, modos activo/pasivo FTP
- Aspectos de seguridad: 
  - **Problemas:** Credenciales en texto plano, tráfico sin cifrar
  - **Alternativas modernas:**
    - **SFTP (SSH File Transfer Protocol):** Transferencia sobre SSH, completamente cifrado
    - **FTPS (FTP over TLS):** FTP con capa TLS
    - **SCP (Secure Copy):** Transferencia simple sobre SSH
    - **WebDAV:** Transferencia sobre HTTP/HTTPS
    - **Rsync over SSH:** Sincronización eficiente
    - **Soluciones cloud:** AWS S3, Azure Blob Storage, Google Cloud Storage
- Casos de uso legítimos actuales: TFTP para PXE boot, actualizaciones de firmware en entorno controlado

**Archivo:** `2.4-FTP-TFTP.md`

---

### 2.3 Servicios Web

#### 2.3.1 HTTP y HTTPS
**Función:** Protocolo de transferencia de hipertexto (web)

**Importancia:** Base de la web moderna. HTTPS es obligatorio para cualquier sitio serio.

**Contenido:**
- Descripción: HTTP (texto plano) vs HTTPS (HTTP + TLS)
- Objetivo: Servir aplicaciones web, APIs, contenido estático/dinámico
- Instalación y configuración: Apache HTTP Server, Nginx, IIS
- Virtual hosts, configuración SSL/TLS, certificados Let's Encrypt
- Reverse proxy, load balancing
- Demostración: Servidor web básico, HTTPS con certificado, virtual hosts
- Aspectos de seguridad:
  - TLS 1.2/1.3 (deshabilitar SSL, TLS 1.0/1.1)
  - Cipher suites fuertes
  - HSTS (HTTP Strict Transport Security)
  - Content Security Policy (CSP)
  - Protección contra ataques comunes (XSS, CSRF, Clickjacking)

**Archivo:** `2.5-HTTP-HTTPS.md`

---

#### 2.3.2 Proxy (Forward y Reverse)
**Función:** Intermediario para peticiones de clientes o servidores

**Importancia:** Control de acceso web, cache, optimización de ancho de banda, seguridad.

**Contenido:**
- Descripción: Forward proxy (cliente → proxy → Internet), Reverse proxy (Internet → proxy → servidor)
- Objetivo: Filtrado de contenido, cache, anonimato, balanceo de carga
- Instalación y configuración: Squid (forward), Nginx (reverse), HAProxy
- ACLs, cache, autenticación
- Demostración: Proxy transparente, filtrado de URLs, cache web
- Aspectos de seguridad:
  - SSL interception (inspection)
  - Blacklists/whitelists
  - Integración con antivirus
  - Logs de auditoría
- Evolución moderna: WAF (Web Application Firewall), CDN, API Gateway

**Archivo:** `2.9-Proxy.md`

---

### 2.4 Servicios de Almacenamiento y Archivos

#### 2.4.1 NFS (Network File System)
**Función:** Sistema de archivos distribuido (Unix/Linux)

**Importancia Histórica:** Estándar en ambientes Unix durante décadas.

**Estado Actual:** NFSv4 con Kerberos es seguro, pero desplazado por alternativas.

**Contenido:**
- Descripción: Montar sistemas de archivos remotos como locales
- Objetivo: Compartir archivos entre servidores Unix/Linux
- Instalación y configuración: nfs-kernel-server (Linux), exports, mount
- Demostración: Exportar directorios, montar en clientes, permisos
- Aspectos de seguridad:
  - **Problemas:** NFSv2/v3 sin cifrado, autenticación débil basada en UID
  - **Solución:** NFSv4 con Kerberos
  - **Alternativas modernas:**
    - **SMB/CIFS (Samba):** Protocolo Windows, mejor integración multiplataforma
    - **SSHFS:** Sistema de archivos sobre SSH
    - **WebDAV:** Acceso a archivos vía HTTP/HTTPS
    - **GlusterFS/Ceph:** Sistemas de archivos distribuidos modernos
    - **Object storage:** AWS S3, MinIO, Azure Blob

**Archivo:** `2.6-NFS.md`

---

### 2.5 Servicios de Directorio y Autenticación

#### 2.5.1 LDAP (Lightweight Directory Access Protocol)
**Función:** Servicio de directorio centralizado para usuarios, grupos y recursos

**Importancia:** Base de Microsoft Active Directory. Autenticación centralizada en Linux.

**Contenido:**
- Descripción: Base de datos jerárquica optimizada para lectura
- Objetivo: Centralizar autenticación, directorio de usuarios/grupos, Single Sign-On (SSO)
- Instalación y configuración: OpenLDAP, 389 Directory Server
- Estructura DIT (Directory Information Tree), DN, schemas
- Demostración: Agregar usuarios/grupos, autenticación Linux contra LDAP
- Aspectos de seguridad:
  - LDAPS (LDAP over TLS) - puerto 636
  - STARTTLS
  - ACLs de acceso
  - Integración con Kerberos (LDAP + Kerberos = mejor seguridad)
- Integración con Active Directory
- Aplicaciones: FreeIPA (Red Hat), JumpCloud (cloud)

**Archivo:** `2.7-LDAP.md`

---

### 2.6 Servicios de Correo Electrónico

#### 2.6.1 SMTP, POP3, IMAP y SASL
**Función:** Envío, recepción y autenticación de correo electrónico

**Importancia:** Correo electrónico sigue siendo comunicación empresarial crítica.

**Contenido:**
- Descripción: 
  - SMTP (Simple Mail Transfer Protocol): Envío de correo
  - POP3 (Post Office Protocol v3): Descarga de correo (elimina del servidor)
  - IMAP (Internet Message Access Protocol): Acceso a correo (permanece en servidor)
  - SASL (Simple Authentication and Security Layer): Framework de autenticación
- Objetivo: Sistema de correo corporativo completo
- Instalación y configuración: Postfix (SMTP), Dovecot (POP3/IMAP)
- MX records, relay, virtual domains
- Demostración: Envío/recepción de correos, autenticación SASL
- Aspectos de seguridad:
  - TLS para SMTP (STARTTLS), POP3S (puerto 995), IMAPS (puerto 993)
  - SPF (Sender Policy Framework): Validar remitentes autorizados
  - DKIM (DomainKeys Identified Mail): Firmas digitales en correos
  - DMARC (Domain-based Message Authentication): Política de validación
  - Filtros anti-spam: SpamAssassin, rspamd
  - Autenticación SASL obligatoria para relay
- Soluciones modernas: Office 365, Google Workspace (Gmail), Exchange Online

**Archivo:** `2.8-SMTP-POP-IMAP-SASL.md`

## Filosofía de la Unidad: Aprender Haciendo

Esta unidad se basa en **aprendizaje práctico intensivo**. No basta con leer sobre servicios de red; hay que:

1. **Instalar** los servicios en VMs reales
2. **Configurar** según diferentes escenarios
3. **Romper** las configuraciones intencionalmente
4. **Troubleshootar** y aprender de los errores
5. **Documentar** todo el proceso
6. **Presentar** soluciones al equipo/clase

> "No aprendes a nadar leyendo libros sobre natación. Necesitas meterte a la piscina."

Lo mismo aplica para administración de servicios de red. **Hands-on experience** es indispensable.

---

## Conclusión

Los servicios de red son el corazón palpitante de cualquier infraestructura tecnológica. Dominar su instalación, configuración, administración y troubleshooting es una habilidad fundamental para cualquier profesional de sistemas y redes.

A lo largo de esta unidad, desarrollarás competencias prácticas que te permitirán:

✓ Implementar infraestructuras de servicios de nivel empresarial  
✓ Comprender la evolución tecnológica (legacy vs moderno)  
✓ Aplicar mejores prácticas de seguridad  
✓ Diseñar arquitecturas resilientes y escalables  
✓ Troubleshootar problemas complejos  
✓ Documentar soluciones de forma profesional  

**Prepárate para ensuciarte las manos con configuraciones reales, logs extensos, y la satisfacción de hacer que servicios complejos funcionen correctamente.**
