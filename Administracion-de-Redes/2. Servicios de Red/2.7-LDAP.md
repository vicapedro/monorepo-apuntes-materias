# 2.7 LDAP (Lightweight Directory Access Protocol) - Protocolo de Directorio Ligero

> **⚠️ ADVERTENCIA DE SEGURIDAD**: LDAP sin cifrar (puerto 389) transmite credenciales en texto plano. **LDAPS (puerto 636) o StartTLS son obligatorios** en producción. Considere **alternativas modernas** como FreeIPA, Azure AD, Okta para implementaciones nuevas con SSO y MFA integrados.

## Descripción

### LDAP (Lightweight Directory Access Protocol)

LDAP es un protocolo estándar de la industria para acceder y mantener servicios de información de directorio distribuido sobre redes IP. Desarrollado en los 90s como versión "ligera" de X.500 DAP, se ha convertido en el estándar de facto para directorios corporativos.

**Características fundamentales:**
- **Protocolo de consulta y modificación**: No es una base de datos, sino el protocolo para acceder a ella
- **Estructura jerárquica**: Árbol de directorios (Directory Information Tree - DIT)
- **Optimizado para lectura**: Muchas lecturas, pocas escrituras (perfil típico de directorios)
- **Agnóstico a la implementación**: OpenLDAP, Active Directory, 389 DS, etc.
- **Estándar abierto**: RFC definido por IETF

### Conceptos clave de LDAP

#### 1. Directory Information Tree (DIT)

Estructura jerárquica similar a sistema de archivos:

```
                          dc=ejemplo,dc=com (Raíz)
                                  │
                ┌─────────────────┼─────────────────┐
                │                 │                 │
        ou=usuarios       ou=grupos        ou=servidores
                │                 │                 │
        ┌───────┴───────┐         │                │
        │               │         │                │
  uid=jperez     uid=mgarcia  cn=admins      cn=web01
  (Usuario)      (Usuario)    (Grupo)       (Host)
```

#### 2. Distinguished Name (DN)

Identificador único de cada entrada en el árbol:

```
DN completo (ruta desde raíz):
uid=jperez,ou=usuarios,dc=ejemplo,dc=com

Componentes:
- uid=jperez         → Relative DN (RDN)
- ou=usuarios        → Organizational Unit
- dc=ejemplo,dc=com  → Domain Component (raíz)
```

#### 3. Atributos y ObjectClass

Cada entrada tiene atributos definidos por objectClass:

```
dn: uid=jperez,ou=usuarios,dc=ejemplo,dc=com
objectClass: inetOrgPerson
objectClass: posixAccount
objectClass: shadowAccount
cn: Juan Pérez
sn: Pérez
givenName: Juan
uid: jperez
uidNumber: 10001
gidNumber: 10000
homeDirectory: /home/jperez
loginShell: /bin/bash
mail: jperez@ejemplo.com
userPassword: {SSHA}3kj2h4k23h4k23h4k23h4k23h4 (hash)
```

**ObjectClass comunes:**
- `person`: Atributos básicos de persona (cn, sn, telephoneNumber)
- `inetOrgPerson`: Extensión con email, título, etc.
- `posixAccount`: Atributos Unix/Linux (uidNumber, gidNumber, homeDirectory)
- `shadowAccount`: Información de passwords Unix
- `organizationalUnit`: Contenedor para organización
- `groupOfNames`: Grupo con miembros (member: dn)

#### 4. LDIF (LDAP Data Interchange Format)

Formato de texto plano para representar datos LDAP:

```ldif
# Crear Organizational Unit
dn: ou=usuarios,dc=ejemplo,dc=com
objectClass: organizationalUnit
ou: usuarios

# Crear usuario
dn: uid=jperez,ou=usuarios,dc=ejemplo,dc=com
objectClass: inetOrgPerson
objectClass: posixAccount
objectClass: shadowAccount
cn: Juan Pérez
sn: Pérez
givenName: Juan
uid: jperez
uidNumber: 10001
gidNumber: 10000
homeDirectory: /home/jperez
loginShell: /bin/bash
mail: jperez@ejemplo.com
userPassword: {SSHA}hash

# Crear grupo
dn: cn=desarrolladores,ou=grupos,dc=ejemplo,dc=com
objectClass: groupOfNames
cn: desarrolladores
member: uid=jperez,ou=usuarios,dc=ejemplo,dc=com
member: uid=mgarcia,ou=usuarios,dc=ejemplo,dc=com
```

### LDAP vs Active Directory

#### Active Directory: LDAP + Extras de Microsoft

Active Directory **NO es LDAP**, sino una implementación de servicios de directorio que **UTILIZA LDAP** como uno de sus protocolos de acceso.

**Relación:**
```
┌──────────────────────────────────────────────────────────────┐
│                    Active Directory                          │
├──────────────────────────────────────────────────────────────┤
│  Kerberos  │  LDAP  │  DNS  │  SMB  │  NTLM  │  Replication │
├────────────┴────────┴───────┴───────┴────────┴──────────────┤
│              Directory Database (NTDS.DIT)                   │
└──────────────────────────────────────────────────────────────┘

OpenLDAP = Solo el protocolo LDAP + directorio
Active Directory = Suite completa de servicios de directorio
```

**Diferencias principales:**

| Aspecto | OpenLDAP | Active Directory |
|---------|----------|------------------|
| **Protocolo principal** | LDAP | LDAP + Kerberos + DNS |
| **Autenticación** | LDAP bind | Kerberos (preferido) + NTLM |
| **Esquema** | Flexible (configurable) | Extendido (Microsoft) |
| **Replicación** | syncrepl | Multi-Master Replication |
| **Group Policy** | No | ✅ GPO |
| **DNS integrado** | No | ✅ DNS dinámico |
| **Plataforma** | Linux/Unix | Windows Server |
| **Licencia** | Open Source (gratuito) | Comercial (incluido en Windows Server) |
| **Naming Context** | dc=ejemplo,dc=com | DC=ejemplo,DC=com (case-insensitive) |
| **Atributos únicos AD** | N/A | sAMAccountName, userAccountControl, objectGUID, objectSID |

**Active Directory puede consultarse vía LDAP:**

```bash
# Consultar AD desde Linux usando LDAP
ldapsearch -H ldap://dc.ejemplo.com \
  -D "CN=consulta,CN=Users,DC=ejemplo,DC=com" \
  -W -b "DC=ejemplo,DC=com" \
  "(sAMAccountName=jperez)"

# AD responde con atributos específicos de Microsoft:
# - sAMAccountName (login Windows)
# - objectGUID (GUID único)
# - objectSID (Security Identifier)
# - userPrincipalName (UPN: jperez@ejemplo.com)
# - memberOf (grupos del usuario)
```

### Arquitectura LDAP

```
┌────────────────────────────────────────────────────────────┐
│                   Cliente LDAP                             │
│  (Aplicación, PAM, SSSD, Apache mod_ldap, etc.)          │
└─────────────────────┬──────────────────────────────────────┘
                      │
                      │ 1. Bind (autenticación)
                      │ 2. Search (consulta)
                      │ 3. Add/Modify/Delete (modificación)
                      │ 4. Unbind (desconexión)
                      │
┌─────────────────────▼──────────────────────────────────────┐
│               Servidor LDAP (slapd)                        │
├────────────────────────────────────────────────────────────┤
│  LDAP Protocol Handler                                     │
├────────────────────────────────────────────────────────────┤
│  Access Control (ACL)                                      │
├────────────────────────────────────────────────────────────┤
│  Schema Engine (objectClass, atributos)                   │
├────────────────────────────────────────────────────────────┤
│  Backend Database (mdb, hdb, etc.)                        │
└────────────────────────────────────────────────────────────┘
```

### Operaciones LDAP

| Operación | Descripción | Ejemplo |
|-----------|-------------|---------|
| **Bind** | Autenticar con el servidor | Conectar como admin para consultar |
| **Unbind** | Cerrar conexión | Finalizar sesión |
| **Search** | Consultar entradas | Buscar usuario por uid |
| **Compare** | Comparar valor de atributo | Verificar si user es miembro de grupo |
| **Add** | Crear entrada nueva | Agregar nuevo usuario |
| **Delete** | Eliminar entrada | Borrar usuario |
| **Modify** | Cambiar atributos | Actualizar email |
| **Modify DN** | Renombrar entrada | Mover usuario a otra OU |

### Filtros de búsqueda LDAP

Sintaxis similar a SQL WHERE, pero con notación de prefijo:

```bash
# Igualdad
(uid=jperez)

# AND (múltiples condiciones)
(&(objectClass=posixAccount)(uid=jperez))

# OR (cualquier condición)
(|(uid=jperez)(uid=mgarcia))

# NOT
(!(uid=jperez))

# Wildcard
(cn=Juan*)

# Presente (atributo existe)
(mail=*)

# Comparación
(uidNumber>=10000)

# Ejemplo complejo: Usuarios activos con email en dominio ejemplo.com
(&(objectClass=inetOrgPerson)(mail=*@ejemplo.com)(!(shadowExpire=*)))
```

### 2. Configurar TLS/SSL (LDAPS)

**⚠️ CRÍTICO**: LDAP sin TLS transmite passwords en texto plano.

**Generar certificados (self-signed para desarrollo):**

```bash
# Generar CA privada
sudo openssl genrsa -out /etc/ldap/ca-key.pem 4096

# Generar certificado CA
sudo openssl req -new -x509 -days 3650 -key /etc/ldap/ca-key.pem -out /etc/ldap/ca-cert.pem \
  -subj "/C=MX/ST=Jalisco/L=Guadalajara/O=Ejemplo/CN=LDAP CA"

# Generar clave del servidor
sudo openssl genrsa -out /etc/ldap/ldap-server-key.pem 2048

# Generar CSR
sudo openssl req -new -key /etc/ldap/ldap-server-key.pem -out /etc/ldap/ldap-server.csr \
  -subj "/C=MX/ST=Jalisco/L=Guadalajara/O=Ejemplo/CN=ldap.ejemplo.com"

# Firmar con CA
sudo openssl x509 -req -days 365 -in /etc/ldap/ldap-server.csr \
  -CA /etc/ldap/ca-cert.pem -CAkey /etc/ldap/ca-key.pem -CAcreateserial \
  -out /etc/ldap/ldap-server-cert.pem

# Permisos
sudo chown openldap:openldap /etc/ldap/*.pem
sudo chmod 600 /etc/ldap/*-key.pem
```

**Configurar slapd para usar TLS:**

```bash
# tls.ldif
cat > tls.ldif << 'EOF'
dn: cn=config
changetype: modify
add: olcTLSCACertificateFile
olcTLSCACertificateFile: /etc/ldap/ca-cert.pem
-
add: olcTLSCertificateFile
olcTLSCertificateFile: /etc/ldap/ldap-server-cert.pem
-
add: olcTLSCertificateKeyFile
olcTLSCertificateKeyFile: /etc/ldap/ldap-server-key.pem
EOF

# Aplicar configuración TLS
sudo ldapmodify -Y EXTERNAL -H ldapi:/// -f tls.ldif

# Reiniciar slapd
sudo systemctl restart slapd

# Verificar puerto LDAPS (636)
sudo ss -tulnp | grep 636
```

**Configurar /etc/default/slapd para escuchar en LDAPS:**

```bash
# Ubuntu: /etc/default/slapd
sudo nano /etc/default/slapd

# Cambiar línea SLAPD_SERVICES:
SLAPD_SERVICES="ldap:/// ldapi:/// ldaps:///"

# Reiniciar
sudo systemctl restart slapd

# Verificar puertos
sudo ss -tulnp | grep slapd
# Debe mostrar: 389 (ldap), 636 (ldaps)
```

### 3. Cliente LDAP (Autenticación Linux contra OpenLDAP)

#### Método moderno: SSSD (System Security Services Daemon)

```bash
# Instalar SSSD
sudo apt install sssd sssd-ldap ldap-utils -y

# Configurar SSSD
sudo nano /etc/sssd/sssd.conf
```

```ini
[sssd]
config_file_version = 2
services = nss, pam
domains = ejemplo.com

[domain/ejemplo.com]
id_provider = ldap
auth_provider = ldap
chpass_provider = ldap

ldap_uri = ldaps://ldap.ejemplo.com
ldap_search_base = dc=ejemplo,dc=com
ldap_default_bind_dn = cn=admin,dc=ejemplo,dc=com
ldap_default_authtok = password_admin

# TLS
ldap_tls_reqcert = demand
ldap_tls_cacert = /etc/ldap/ca-cert.pem

# Cache
cache_credentials = true

[nss]
filter_users = root,daemon,bin,sys
filter_groups = root,daemon,bin,sys

[pam]
offline_credentials_expiration = 7
```

```bash
# Permisos correctos (crítico)
sudo chmod 600 /etc/sssd/sssd.conf

# Copiar CA cert
sudo cp /etc/ldap/ca-cert.pem /etc/ssl/certs/

# Iniciar SSSD
sudo systemctl enable sssd --now
sudo systemctl restart sssd

# Verificar
sudo systemctl status sssd
```

**Configurar PAM para usar SSSD:**

```bash
# Ubuntu 22.04/24.04 (PAM moderno con pam-auth-update)
sudo pam-auth-update --enable sss

# Verificar usuario LDAP
id jperez
# uid=10001(jperez) gid=10000(desarrolladores) groups=10000(desarrolladores)

# Login SSH como usuario LDAP
ssh jperez@localhost
```

#### Método legacy: nslcd (no recomendado, pero funcional)

```bash
# Instalar nslcd
sudo apt install libnss-ldapd libpam-ldapd nscd -y

# Durante configuración:
# - LDAP URI: ldaps://ldap.ejemplo.com
# - Base DN: dc=ejemplo,dc=com
# - Services: group, passwd, shadow

# Editar /etc/nslcd.conf si es necesario
sudo nano /etc/nslcd.conf
```

```conf
uri ldaps://ldap.ejemplo.com
base dc=ejemplo,dc=com
binddn cn=admin,dc=ejemplo,dc=com
bindpw password_admin

tls_reqcert demand
tls_cacertfile /etc/ldap/ca-cert.pem
```

### 4. Integración con Active Directory

#### Opción 1: SSSD con AD (recomendado)

```bash
# Instalar paquetes necesarios
sudo apt install sssd sssd-tools realmd adcli samba-common-bin -y

# Descubrir dominio AD
sudo realm discover EJEMPLO.COM

# Unirse al dominio
sudo realm join --user=Administrator EJEMPLO.COM

# Verificar
sudo realm list

# SSSD se configura automáticamente en /etc/sssd/sssd.conf
# Verificar usuario AD
id administrator@ejemplo.com
```

**Configuración manual de SSSD para AD:**

```ini
# /etc/sssd/sssd.conf
[sssd]
config_file_version = 2
services = nss, pam
domains = ejemplo.com

[domain/ejemplo.com]
id_provider = ad
auth_provider = ad
access_provider = ad

# AD server
ad_domain = ejemplo.com
ad_server = dc.ejemplo.com

# Kerberos
krb5_realm = EJEMPLO.COM

# DNS autodiscovery
dyndns_update = true

# Usuario por defecto
default_shell = /bin/bash
fallback_homedir = /home/%u@%d

# Cache
cache_credentials = true

[nss]
filter_users = root,daemon,bin,sys

[pam]
offline_credentials_expiration = 7
```

```bash
# Permisos
sudo chmod 600 /etc/sssd/sssd.conf

# Reiniciar SSSD
sudo systemctl restart sssd

# Verificar login con usuario AD
su - jperez@ejemplo.com
```

#### Opción 2: Winbind (alternativa)

```bash
# Instalar Samba y Winbind
sudo apt install samba winbind -y

# Configurar Samba
sudo nano /etc/samba/smb.conf
```

```ini
[global]
   workgroup = EJEMPLO
   realm = EJEMPLO.COM
   security = ads
   
   # Winbind
   winbind use default domain = yes
   winbind offline logon = yes
   winbind enum users = yes
   winbind enum groups = yes
   
   # ID mapping
   idmap config * : backend = tdb
   idmap config * : range = 10000-999999
   idmap config EJEMPLO : backend = rid
   idmap config EJEMPLO : range = 10000-999999
```

```bash
# Unirse al dominio
sudo net ads join -U Administrator

# Iniciar Winbind
sudo systemctl enable winbind --now

# Verificar
wbinfo -u  # Listar usuarios AD
wbinfo -g  # Listar grupos AD
```

## Demostración y Pruebas

### 1. Consultas básicas con ldapsearch

```bash
# Buscar toda la estructura (requiere bind como admin)
ldapsearch -x -H ldaps://ldap.ejemplo.com \
  -D "cn=admin,dc=ejemplo,dc=com" -W \
  -b "dc=ejemplo,dc=com"

# Buscar usuario específico
ldapsearch -x -H ldaps://ldap.ejemplo.com \
  -D "cn=admin,dc=ejemplo,dc=com" -W \
  -b "dc=ejemplo,dc=com" \
  "(uid=jperez)"

# Buscar solo atributos específicos
ldapsearch -x -H ldaps://ldap.ejemplo.com \
  -D "cn=admin,dc=ejemplo,dc=com" -W \
  -b "dc=ejemplo,dc=com" \
  "(uid=jperez)" mail cn uidNumber

# Buscar todos los usuarios (posixAccount)
ldapsearch -x -H ldaps://ldap.ejemplo.com \
  -D "cn=admin,dc=ejemplo,dc=com" -W \
  -b "ou=usuarios,dc=ejemplo,dc=com" \
  "(objectClass=posixAccount)"

# Buscar grupos
ldapsearch -x -H ldaps://ldap.ejemplo.com \
  -D "cn=admin,dc=ejemplo,dc=com" -W \
  -b "ou=grupos,dc=ejemplo,dc=com" \
  "(objectClass=posixGroup)"

# Búsqueda anónima (si está permitida)
ldapsearch -x -H ldaps://ldap.ejemplo.com \
  -b "dc=ejemplo,dc=com" \
  "(uid=jperez)"
```

## Aspectos de Seguridad

### 1. Problema crítico: LDAP sin cifrar (puerto 389)

**Vulnerabilidad: Passwords en texto plano**

```
Cliente                         Atacante (Sniffing)          Servidor LDAP
   │                                    │                          │
   │  BIND Request                      │                          │
   │  DN: uid=jperez,...                │                          │
   │  Password: secreto123              │                          │
   ├───────────────────────────────────>│─────────────────────────>│
   │                                    │                          │
   │                                    │ (captura password)       │
   │                                    │ secreto123               │
```

**Solución: LDAPS (puerto 636) o StartTLS**

```bash
# ❌ INSEGURO (puerto 389, sin TLS)
ldapsearch -x -H ldap://ldap.ejemplo.com -D "..." -w "password"

# ✅ SEGURO (puerto 636, LDAPS)
ldapsearch -x -H ldaps://ldap.ejemplo.com -D "..." -w "password"

# ✅ SEGURO (puerto 389 con StartTLS)
ldapsearch -x -H ldap://ldap.ejemplo.com -Z -D "..." -w "password"
# -Z = StartTLS obligatorio
```

### 2. Configuración de ACLs (Access Control Lists)

**Problema**: Por defecto, cualquier usuario autenticado puede leer todo el directorio (incluyendo hashes de passwords).

**Solución: ACLs restrictivas**

```ldif
# acl.ldif - Configurar ACLs seguras

dn: olcDatabase={1}mdb,cn=config
changetype: modify
replace: olcAccess
# Admin tiene acceso completo
olcAccess: {0}to * by dn="cn=admin,dc=ejemplo,dc=com" write by * break
# Usuarios pueden leer sus propias entradas
olcAccess: {1}to dn.base="dc=ejemplo,dc=com" by * read
# Passwords: usuario puede leer propio, nadie más
olcAccess: {2}to attrs=userPassword
  by self write
  by anonymous auth
  by * none
# Shadow attributes: solo self puede leer
olcAccess: {3}to attrs=shadowLastChange,shadowExpire
  by self write
  by * none
# Resto: autenticados pueden leer, anónimos no
olcAccess: {4}to *
  by self write
  by users read
  by anonymous none
```

```bash
# Aplicar ACLs
sudo ldapmodify -Y EXTERNAL -H ldapi:/// -f acl.ldif
```

### 5. Migración de usuarios locales a LDAP

**Script de migración:**

```bash
#!/bin/bash
# migrate_users_to_ldap.sh

LDAP_SERVER="ldaps://ldap.ejemplo.com"
ADMIN_DN="cn=admin,dc=ejemplo,dc=com"
BASE_DN="dc=ejemplo,dc=com"

# Extraer usuarios locales (UID >= 1000)
getent passwd | awk -F: '$3 >= 1000 && $3 < 65534 {print}' | while IFS=: read -r username password uid gid gecos home shell; do
    
    # Extraer nombre completo
    fullname=$(echo "$gecos" | cut -d',' -f1)
    firstname=$(echo "$fullname" | awk '{print $1}')
    lastname=$(echo "$fullname" | awk '{for(i=2;i<=NF;i++) printf "%s ", $i; print ""}' | sed 's/ *$//')
    
    if [ -z "$lastname" ]; then
        lastname="$firstname"
    fi
    
    # Obtener grupos
    groups=$(id -Gn "$username" | tr ' ' '\n' | tail -n +2)
    
    # Crear LDIF
    cat > /tmp/${username}.ldif << EOF
dn: uid=${username},ou=usuarios,${BASE_DN}
objectClass: inetOrgPerson
objectClass: posixAccount
objectClass: shadowAccount
cn: ${fullname}
sn: ${lastname}
givenName: ${firstname}
uid: ${username}
uidNumber: ${uid}
gidNumber: ${gid}
homeDirectory: ${home}
loginShell: ${shell}
userPassword: {CRYPT}$(grep "^${username}:" /etc/shadow | cut -d: -f2)
EOF

    echo "Migrando usuario: $username"
    ldapadd -x -H ${LDAP_SERVER} -D ${ADMIN_DN} -W -f /tmp/${username}.ldif
    
    rm /tmp/${username}.ldif
done

echo "✅ Migración completada"
echo "⚠️  Verificar que usuarios puedan autenticarse antes de eliminar cuentas locales"
```

## Resumen Ejecutivo

**LDAP es el protocolo estándar para directorios corporativos**, pero por sí solo es insuficiente para entornos modernos.

**Puntos clave:**
1. **LDAP ≠ Active Directory**: LDAP es el protocolo, AD es la implementación completa
2. **LDAP sin TLS es inseguro**: Puerto 389 transmite passwords en texto plano
3. **OpenLDAP requiere expertise**: Configuración manual, ACLs complejas, sin Kerberos out-of-the-box
4. **Active Directory es dominante** en Windows, puede integrarse con Linux vía SSSD
5. **FreeIPA** es la mejor alternativa open source completa (LDAP + Kerberos + DNS + CA)
6. **Cloud IAM** (Azure AD, Okta, Auth0) es el futuro: SSO, MFA, y provisioning automático

**Recomendaciones según escenario:**

| Escenario | Solución recomendada |
|-----------|----------------------|
| **Empresa Windows** | Active Directory (ya lo tienen) |
| **Empresa Linux** | FreeIPA (todo integrado) |
| **Híbrido Windows/Linux** | AD + SSSD en Linux |
| **Startup/Cloud-first** | Azure AD, Okta, Auth0 |
| **Legacy migration** | OpenLDAP → FreeIPA o Azure AD |
| **Budget limitado** | FreeIPA (gratis, completo) |

**Conclusión**: Para proyectos nuevos, considere **FreeIPA** (on-premise) o **Azure AD/Okta** (cloud) en lugar de OpenLDAP puro. Si debe integrar con AD existente, use **SSSD con Kerberos** para autenticación robusta.
